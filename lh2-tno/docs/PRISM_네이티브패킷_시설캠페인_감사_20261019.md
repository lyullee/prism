# 네이티브 LH2 패킷 시설 campaign 감사

`results/20261019/generic_native_packet_rebound_campaign.json`은 24개 선언 사건의 campaign 요청을 저장된 strict `lh2dt` packet으로 다시 만든 입력이다. 이 입력에서 고속 기체인 G1은 handoff가 없는 원래 packet으로 먼저 실행해 실패를 확인했고, 이후 같은 event/component/port/source digest를 가진 명시적 압축성 plane handoff를 별도 rebind했다. 최종 실행 결과는 `results/20261019/generic_native_packet_rebound_g1_handoff_result.json`에 있고, 요약 장부는 [`examples/native_lh2dt_packet_campaign_execution_ledger_g1_handoff.json`](../examples/native_lh2dt_packet_campaign_execution_ledger_g1_handoff.json)이다. 원래 실패 장부도 [`examples/native_lh2dt_packet_campaign_execution_ledger.json`](../examples/native_lh2dt_packet_campaign_execution_ledger.json)에 보존한다.

## 확인 결과

| 항목 | 결과 |
|---|---:|
| 선언 이벤트 | 24 |
| campaign case | 24 |
| packet identity 소비 | 24/24 |
| source/result digest 보존 | 24/24 |
| 피해체인 실행 case | 24 |
| 운전자 제한 case | 20 |
| 실패 case | 0 |
| risk atom | 96 |
| 시설 전체 IR/F-N | 보류 |

G1은 원래 packet으로는 `resolved low-Mach gas exit scope exceeded; compressible/underexpanded plane adapter required`를 반환했다. 그 실패는 그대로 보존한 뒤, 별도의 `resolved_release_with_handoff.json`을 **같은 event ID·component ID·port ID·provider source digest**가 맞을 때만 재결합했다. handoff provider result digest는 바뀌었고, `prism-notional-plane-adapter:0.1.0`의 독립 검증되지 않은 근접장이라는 provenance를 잃지 않았다. 따라서 24개 case가 모두 chain까지 도달했지만 20개는 여전히 `EXECUTED_OPERATOR_LIMITED`이며, G1의 handoff도 qualified provider packet이나 물리검증 결과가 아니다.

이 실행은 패킷의 source/result digest와 provider 종료 시계를 실제 campaign 요청에 넣었다는 증거다. 20개 `EXECUTED_OPERATOR_LIMITED`는 계산값은 있지만 합성·운전자 제한 때문에 완전한 시설 위험으로 승격할 수 없는 상태다. `provider_packet_promoted=false`, `frequency_from_provider_packet=false`, `facility_qra_claim=false`, `physical_validation_claim=false`를 유지한다.

같은 최종 campaign 결과를 `build_facility_assessment.py`에 한 번만 넣어 시설 ledger도 다시 만들었다. 24개 사건·96개 risk atom이 하나의 시설 ledger로 모이고, 문헌 빈도 5개 시나리오가 저장된 atom에 재가중되지만, 20개 운전자 제한과 1개 domain-incomplete 표시 때문에 `facility_total_risk_available=false`를 유지한다. 이 실행의 조건부 진단 IR/F-N은 별도 요약 [`examples/native_lh2dt_packet_campaign_facility_assessment_summary.json`](../examples/native_lh2dt_packet_campaign_facility_assessment_summary.json)에 기록했다. 이 값은 시설 전체 위험의 자격 있는 결론이 아니라 현재 입력과 제한을 그대로 반영한 진단용 합산이다.

## 2026-10-19 별도 vertical handoff를 공통 시설 장부에 결합

- namespace: `generic-lh2-full-scope-example/vertical-handoff`
- 설비: `vertical-handoff-vent`
- component: `vertical-handoff-terminal-pipe-01`

## 2026-10-19 two-sided rupture의 공통 시설 결합과 scope matrix 병합

기존 `two_sided_rupture/provider_set_adapter_smoke/branch_campaign_result.json`은 두 종단(`G1`, `G2`)을 계산했지만 별도 `two-sided-rupture-campaign` 시설 ID를 사용했다. `campaign_namespace.py`와 `rebind_campaign_namespace.py`는 이를 `generic-lh2-full-scope-example/two-sided-rupture` 아래로 이동하고, `two-sided-rupture-pipe-01` component로 명시했다. 네 수용점은 `worker-01`로 매핑하며 충돌은 endpoint maximum으로 합친다.

결합 결과는 2개 event, 6개 case row, 16개 risk atom이다. 4개 case row는 `EXECUTED_OPERATOR_LIMITED`, 6개 uncomputed row는 원본의 미완료 endpoint/운전자 제한 기록을 그대로 보존한다. 네 near-worker harm atom이 비영이어서, generic·vertical 결과와 함께 시설 조건부 진단 IR/F-N이 처음으로 `worker-01: [1.0×10^-7, 1.0×10^-7]`, F-N의 1명 수준 누적빈도가 `1.0×10^-7 / year`로 나타난다. 이는 합성 geometry·인구·점화·endpoint 집합을 사용한 조건부 진단값이며, qualified facility total이 아니다.

세 개의 사고범위 matrix도 `scope_matrix_merge.py`로 하나의 시설 matrix로 병합했다. 그 결과 `vertical_handoff`와 `two_sided_rupture`가 `NO_EVENT_GENERATED`로 사라지지 않고 모두 `PARTIAL`로 보인다. 이 병합은 family별 누락을 드러내는 회계 단계이며, 서로 다른 family의 빈도를 더하지 않는다. 최신 장부와 평가 요약은 [`native_lh2dt_packet_campaign_vertical_handoff_two_sided_facility_assessment_summary.json`](../examples/native_lh2dt_packet_campaign_vertical_handoff_two_sided_facility_assessment_summary.json), 범위 장부는 `results/20261019/generic_vertical_two_sided_merged_scope_matrix.json`이다.

최신 결합 평가에는 31개 event, 40개 case, 120개 risk atom, 9개 관찰 component가 있다. 12개 주요 사고 family 중 4개만 `EXECUTED`, 나머지는 `PARTIAL`이고, 22개 operator-limited·5개 명시적 uncomputed case가 남는다. 따라서 IJHE 감사는 27개 검사·3개 blocker를 유지한다. provider packet 적격성, 물리검증, 전체 시설 IR/F-N은 승격하지 않는다.

## 2026-10-19 inventory depletion을 공통 시설 장부에 결합

재고 소진 캠페인은 원래 `equipment-inventory-campaign`이라는 독립 진단 시설이었다. 이를 generic transfer-line과 같은 물리 범위로 더하지 않고, `generic-lh2-full-scope-example/inventory-depletion` namespace와 `inventory-depletion-pipe-01` component로 별도 rebind했다. event ID, asset/component ID, provider packet ID, 수용점 매핑은 provenance에 함께 남는다.

재결합 결과는 5개 event, 10개 실행 case, 0개 미계산 case, 40개 risk atom이다. 각 case는 `inventory_depletion` 종료근거와 양수 재고 threshold 도달 시간을 보존한다. harm atom은 현재 합성 진단 입력에서 0이므로 기존 two-sided rupture의 near-worker 진단 위험을 중복해서 키우지 않는다. 선언 빈도는 연간 `6.38×10^-6`을 그대로 사용하며 현장 빈도 추정이나 센서 학습을 하지 않는다.

일부 독립 진단 결과에는 `coverage.by_component`가 없었다. `campaign_namespace.py`는 이제 event/case/uncomputed-case 회계에서 명시적 component coverage 한 행을 만들고, 이를 통해 시설 원장이 해당 설비를 `EXECUTED`로 구분한다. 이 보완은 회계 메타데이터를 만드는 작업이며 물리검증·provider 승격·시설 QRA 승격을 수행하지 않는다. 관련 테스트를 포함한 portable suite는 460개가 통과했다.

네 개의 disjoint matrix를 병합한 범위표는 `results/20261019/generic_vertical_two_sided_merged_scope_matrix.json`이다. 통합 시설 평가는 [`examples/native_lh2dt_packet_campaign_vertical_handoff_two_sided_inventory_facility_assessment_summary.json`](../examples/native_lh2dt_packet_campaign_vertical_handoff_two_sided_inventory_facility_assessment_summary.json)에서 확인한다. 전체 결과는 36개 event, 50개 case, 160개 risk atom, 10개 component이고 조건부 IR/F-N은 계산되지만 12개 사고 family의 부분 범위, synthetic/operator-limited release, 독립 물리검증 부족 때문에 qualified facility total은 계속 보류된다.

## 2026-10-19 차단 성공·실패 campaign의 공통 시설 결합

최신 다중 campaign 평가와 범위표는 [`isolation 포함 시설 평가 요약`](../examples/native_lh2dt_packet_campaign_vertical_handoff_two_sided_inventory_isolation_facility_assessment_summary.json)과 `results/20261019/generic_vertical_two_sided_merged_scope_matrix.json`이다. 통합 장부는 41개 event, 70개 case, 240개 risk atom, 11개 component이며 IJHE 감사는 27개 검사·3개 blocker를 유지한다.

## provider packet 승격 상태

이번 구현은 packet identity를 소비한 case 수와 qualified provider evidence가 exact-match한 case 수를 별도로 기록한다. `RiskCampaign.provider_packet_evidence`의 `prism.provider_packet_evidence.v1`는 event/component/port와 source/result digest를 대조하며, 누락 또는 불일치가 있으면 `provider_packet_promoted=false`로 남긴다. `physical_validation_evidence`가 독립 검증 ID와 digest를 함께 제공하지 않으면 `physical_validation_claim`과 `complete_facility_qra_claim`도 열리지 않는다. 이 게이트는 빈도를 공급하지 않고, 기존 FrequencyPlan의 문헌 빈도를 그대로 보존한다. 현재 41-event 통합 결과는 qualified provider packet 0건이며 전체 시설 IR/F-N은 계속 보류한다.
## 2026-10-19 시설 evidence request 자동화

시설 평가가 부분 범위로 끝났을 때 다음 provider 입력을 사람이 다시 해석하지 않도록 `facility_evidence_request.py`를 추가했다. 이 모듈은 최신 assessment와 merged scope matrix의 현재 상태를 읽어 12개 사고군과 11개 component별 요구 증거를 생성한다. 각 항목에는 `prism.external_accident_history.v1` packet, exact component/port/event/opening/geometry, provider 종료시간·차단·재고 이력, 질량·에너지 폐합, 독립 물리검증이 포함된다.

생성기는 [`scripts/build_facility_evidence_request.py`](../scripts/build_facility_evidence_request.py)이며 결과 예시는 [`facility_evidence_request_summary.json`](../examples/facility_evidence_request_summary.json)이다. 출력 상태는 `OPEN_EVIDENCE_REQUEST`로 고정하고 provider나 센서에서 빈도를 추정하지 않는다. `EXECUTED`이고 미계산 case가 없는 사고군만 형식상 승격 후보로 표시하며, 실제 qualified provider와 독립 검증 없이는 시설 IR/F-N을 열지 않는다.
