# PRISM 검증근거 통합장부 — 2026-10-22

## 왜 만들었나

PRISM에는 서로 성격이 다른 근거가 여러 개 있다. 예를 들어 풀(spreading) 구성요소 실험 재실행, 액화수소 설비의 정상 운전 관측자료, 외부 설비 모델의 사고 export 함수 검사, 조건부 시설 진단 결과가 있다. 이 자료들을 한 줄로 합치면 “시설 전체가 검증됐다”는 잘못된 결론이 생길 수 있다.

통합장부는 자료를 한 화면에 모으되, 각 자료가 실제로 뒷받침하는 범위를 분리한다. 구성요소 근거는 구성요소 근거로만, 정상 운전 관측자료는 관측자료로만, 조건부 계산은 조건부 계산으로만 표시한다.

## 현재 판정

생성 파일:

```text
results/20261022/validation_evidence_matrix_repaired_valve_transfer_line_replacement.json
```

현재 장부의 판정은 `RESTRICTED_EVIDENCE_MATRIX`이며, 시설 QRA 판정은 `FACILITY_QRA_WITHHELD`이다. 다음 값은 계속 거짓이다.

```text
physical_validation_claim=false
full_chain_validation_claim=false
accident_release_validation_claim=false
facility_qra_claim=false
frequency_inference_performed=false
```

## 근거별 의미

| 근거 | 현재 상태 | 말할 수 있는 것 | 말할 수 없는 것 |
|---|---|---|---|
| DynamicLH2PoolX | 제한된 구성요소 근거 | 지면 도달 유입 뒤 풀·확산 항의 hold-out 및 질량 장부 | 설비 누출, 대기 확산, 점화, 화재·폭발, IR/F-N |
| 설비 관측자료 | 제한된 정상 운전 관측 근거 | fit/holdout 분리와 독립 검증 release gate 기록 | 사고 방출, 차단·재고 소진, 빈도, SLABx 검증 |
| 외부 모델 계약 감사 | 진단 인터페이스 근거 | `export_accident_history` 메서드와 adapter 계약 존재 | qualified provider packet, 물리검증, 시설 QRA |
| 시설 평가 | 조건부 진단 | 선언한 가정 아래 source→consequence→IR/F-N 연결 실행 | 독립 검증된 시설 전체 위험도 |
| IJHE 완료 감사 | 증거 범위 감사 | 미충족 조건과 blocker 추적 | blocker가 남은 상태의 논문용 완료 주장 |
| 외부 LH2 스윕 | 폐합·처리시간 screening | 탱크 수지 잔차, TNO 실행시간, 실패 사례 보존 | 독립 물리검증, provider packet, 시설 IR/F-N |

## 생성 방법

```powershell
python scripts/build_validation_evidence_matrix.py `
  --pool-record results/20261017/validation_evidence/dynamiclh2poolx_stage_c_prism_record_current_source.json `
  --equipment-audit results/20261009/validation_evidence/equipment_validation_audit_live.json `
  --facility-assessment results/20261022/native_campaign_with_repaired_valve_transfer_line_replacement_vertical_all_bins_two_sided_inventory_isolation_facility_assessment.json `
  --native-contract results/20261018/lh2dt_native_contract_audit_current.json `
  --ijhe-audit results/20261022/ijhe_completion_audit_repaired_valve_transfer_line_replacement.json `
  --external-sweep examples/center_lh2_external_sweep_audit.json `
  --output results/20261022/validation_evidence_matrix_repaired_valve_transfer_line_replacement.json
```

입력 JSON은 SHA-256으로 장부에 기록한다. 입력이 시설 QRA나 물리검증을 이미 참이라고 주장하면 장부 상태를 `EVIDENCE_MATRIX_REVIEW_REQUIRED`로 낮추고, 최종 claim은 강제로 거짓으로 유지한다. 따라서 이 장부는 증거를 더해도 자동으로 시설 QRA를 승격하지 않는다.

## 현재 SLABx-LH2 근거 재현 기록

외부 `SLABx_LH2` 작업공간의 현재 `results.json`과 재현 감사 `audit.json`을 2026-11-06에 다시 읽어 `results/20261106/slabx_lh2_validation_audit_recomputed.json`으로 재생성했다. 모델 식별, 재현성, 6개 분산 비교, 풀 반경·negative control, 질량·반복실행 장부의 **5개 검사가 모두 통과**했다. 이어서 `results/20261106/validation_evidence_matrix_current_slabx.json`에 이 감사 결과를 연결했다.

이 재현은 이전 파일의 source hash drift를 줄이는 조치이며, 주장을 시설 전체 물리검증으로 확장하지 않는다. 현재 근거가 뒷받침하는 범위는 SLABx-LH2의 옥외 분산·LFL 및 극저온 풀 구성요소다. 설비 사고방출, 차단·재고소진, 점화·화재·폭발, IR/F-N, 시설 QRA는 여전히 검증 대상에서 제외되어 있고 최종 claim은 계속 `false`다.

추가로 외부 SLABx-LH2 source-term validation gate ledger를 읽기 전용으로
감사했다. [`slabx_lh2_source_validation_gate_audit.json`](../results/20261106/slabx_lh2_source_validation_gate_audit.json)은
6개 gate와 6개 casewise 수치 closure row를 해시로 고정한다. 모든 casewise
질량·에너지 잔차는 선언 tolerance 안에 있지만, 독립 정량 physical-validation
gate는 0개다. 공개 문헌 envelope, 별도 source reproduction, 비전이성 비교와
관측 gate는 각각의 제한을 보존하며 서로의 fit target이나 시설 위험도 증거로
합치지 않는다. 이 결과는 source-term component evidence로만 허용되고,
설비 방출 자격·빈도·IR/F-N·시설 QRA는 계속 보류된다.

## IJHE 사용 범위

논문에서는 “구성요소 검증, 정상 운전 관측자료 감사, native 사고 export 계약 검사, 조건부 시설 진단, 외부 탱크·PSV·TNO 스윕의 폐합·처리시간을 각각 별도 근거로 관리했으며, 독립적인 전체 사고 방출·대기 확산·시설 위험 검증이 없으므로 시설 QRA 주장은 보류했다”고 기술할 수 있다. 이는 현재 데이터가 실제로 뒷받침하는 범위와 일치한다.
