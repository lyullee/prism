# PRISM 방출·차단·재고 장부 개발 기록

## 목적

사고 결과를 숫자 하나로만 저장하면 “얼마나 오래 방출됐는지”, “차단이 성공했는지”, “재고를 얼마나 사용했는지”, “계산되지 않은 분기가 무엇인지”를 다시 확인하기 어렵다. 이번 변경은 campaign의 모든 `event × release branch × annual condition`을 한 행으로 남기는 `prism.release_termination_inventory_ledger.v1` 장부를 추가했다.

## 구현

- `src/lh2_tno/release_ledger.py`가 case row를 장부 행으로 변환한다.
- `campaign.py`가 각 provider packet의 source/result digest, 종료근거, provider duration, available mass와 cumulative mass를 campaign 결과에 보존한다.
- 결과의 `release_termination_inventory_ledger`에는 24개 사건 분기 행이 저장된다.
- `reviewed_isolation_success`가 명시된 경우에만 `provider_declared_isolation_success`로 표시한다.
- `inventory_depletion` 또는 `inventory_over_600s`가 명시된 경우에만 재고 종료 종류를 표시한다.
- `UNCOMPUTED`, `FAILED`, `EXECUTED_OPERATOR_LIMITED`, `EXECUTED_DOMAIN_INCOMPLETE`를 서로 구분한다.
- 누락된 provider mass나 종료 시각을 0 또는 임의의 값으로 채우지 않는다.

## 최신 혼합 campaign 결과

실행 명령:

```powershell
python scripts/run_lh2_mixed_provider_campaign.py `
  --manifest examples/generic_lh2_full_scope_manifest.json `
  --campaign results/20261014/generic_mixed_provider_campaign.json `
  --backend-config results/20261009/equipment_campaign/backend_config.json `
  --output results/20261018/generic_mixed_provider_campaign_release_ledger.json
```

결과는 다음과 같다.

| 항목 | 값 |
|---|---:|
| 장부 행 | 24 |
| provider packet digest가 소비된 행 | 19 |
| operator-limited 또는 domain-incomplete | 5 |
| 실패 | 14 |
| 명시적 미계산 | 5 |
| 완전한 `EXECUTED` 장부 행 | 0 |
| 최대 end-to-end 질량 잔차 | 0 kg |

5개 실행 행은 `synthetic_diagnostic_horizon`을 사용한다. 따라서 질량 적분이 닫혀도 실제 설비 차단 성공, 실제 재고 소진, 현장 고장확률 또는 시설 전체 IR/F-N으로 승격하지 않는다. 14개 실패와 5개 미계산은 결과에 남아 있으며 다른 사고로 대체되지 않는다.

최신 시설 assessment와 IJHE 감사는 다음에 저장했다.

- `results/20261018/generic_mixed_provider_release_ledger_assessment.json`
- `results/20261018/ijhe_completion_audit_release_ledger.json`

IJHE 감사는 19개 점검 중 15개를 통과하고 4개를 차단한다. 차단 사유는 실제 설비 accident export/qualified packet 부재, 부분 사고범위, 시설 전체 IR/F-N 보류다. 방출 장부 점검 자체는 PASS이며, 이는 장부 형식과 실행된 진단 경로가 확인됐다는 뜻이다.

## 2026-10-18 보완 pool 재실행

기본 pool 입력에서 발생한 실패·미계산을 최신 상태로 사용하지 않도록, 검토된 `generic_mixed_provider_campaign_pool.json`을 현재 코드로 다시 실행했다. 최신 기록은 `results/20261018/generic_mixed_provider_campaign_refined_pool_current.json`이다.

| 항목 | 최신 결과 |
|---|---:|
| 전체 case | 24 |
| `EXECUTED` | 5 |
| `EXECUTED_OPERATOR_LIMITED` | 19 |
| `FAILED` | 0 |
| `UNCOMPUTED` case row | 0 |
| provider packet 소비 | 24/24 |
| release ledger 완전 행 | 5 |
| campaign 소요시간 | 349.76 s |
| case p95 / p99 | 30.09 s / 68.97 s |

19건은 합성 진단 horizon, 상수 상태, 또는 짧은 방출의 순간화 handoff 제한 때문에 `EXECUTED_OPERATOR_LIMITED`로 남는다. `storage-shell/AREA_100%`의 확산 domain 불완전 표시는 case 원장과 release ledger에서 `DOMAIN_INCOMPLETE`로 별도 보존한다. 이를 완전한 물리 검증으로 승격하지 않는다. 실패·미계산 분기는 제거되어 연결성이 개선됐지만, qualified provider·독립 물리검증·시설 전체 IR/F-N gate는 여전히 열리지 않는다.

## 범위와 다음 조건

이 장부는 provider가 계산한 물리값을 다시 계산하지 않는다. provider packet이 없거나 종료·재고 장부가 없으면 해당 행은 미계산으로 남긴다. 실제 시설 위험도 승격에는 각 설비의 native `export_accident_history(request)`, provider 종료·차단 기록, 실제 형상·재고, 독립 물리검증, 선언한 사고 family 전체 계산이 추가로 필요하다.
