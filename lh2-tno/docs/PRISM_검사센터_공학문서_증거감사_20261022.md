# PRISM 검사센터 공학문서 증거 감사

## 목적

검사센터 자료 폴더에 있는 P&ID, 배치·준공도면, 운전절차서, 비상대응절차서와 시험절차서를 일반 액화수소 시설 모델에 사용할 수 있는 입력 후보인지 점검했다. 이 감사는 특정 검사센터를 PRISM의 기본 설비로 고정하지 않는다. 파일의 종류와 무결성을 기록하고, 다음 설비 모델링 단계에서 사람이 확인할 문서 후보를 정리하는 준비 단계다.

실행기는 `scripts/audit_engineering_document_evidence.py`이고, 공통 구현은 `src/lh2_tno/engineering_document_evidence.py`에 있다. 공개 요약은 `examples/inspection_center_engineering_document_audit.json`에서 확인한다.

## 확인 결과

2026-10-22 현재 지정된 공학문서 폴더에서 PDF 18개를 읽었다. 모든 파일에 SHA-256 해시와 페이지 수를 기록했다.

| 문서 분류 | 개수 | PRISM에서 의미하는 후보 |
|---|---:|---|
| P&ID 토폴로지 후보 | 4 | 설비·배관·포트·라인 라벨 후보 |
| 공학 도면 후보 | 2 | 형상·배치 후보 |
| 운전절차 후보 | 2 | 정상 순서·운전자 조치 후보 |
| 비상절차 후보 | 2 | 비상조치·격리조치 후보 |
| 시험·검사절차 후보 | 1 | 계측·측정 맥락 후보 |
| 연구개발 참고 후보 | 1 | 프로젝트 범위 참고 |
| 분류 보류 | 6 | 파일명만으로 의미를 확정하지 않음 |

이 자료는 설비 모델링에 유용한 출발점이다. 특히 P&ID와 도면은 일반적인 `EquipmentManifest`를 채우기 위한 후보 자료가 될 수 있고, 운전·비상 절차서는 상태 전이와 격리 명령의 후보 자료가 될 수 있다.

## 아직 연결하지 않은 것

PDF가 있다는 사실만으로 다음 정보를 확정하지 않았다.

- 실제 설비 ID, 포트 좌표, 유체 물성 기준, 밸브의 정상·고장 상태
- 센서 태그와 공학 단위, 교정·품질 상태
- 사고 전용 개구, 방출 질량 유량, 지속시간, 종료근거, 질량·엔탈피 장부
- 문헌 빈도와 사고 packet의 exact match
- SLABx-LH2로 넘길 provider 소유 출구 면·방향·혼합상태

따라서 감사 결과는 `ENGINEERING_DOCUMENT_SCREENING_ONLY`이며, 사고 방출 packet 0개, 적격 provider packet 0개이다. `state_snapshot_binding_allowed`, `frequency_applied`, `provider_packet_created`, `facility_qra_claim`은 모두 `false`다. 정상 운전 문서나 도면을 사고 방출로 바꾸지 않는 fail-closed 경계다.

## 다음 설비 결합 절차

1. P&ID에서 설비 ID·포트·라인·밸브 태그를 사람이 검토해 일반 `EquipmentManifest` 초안을 만든다.
2. 도면에서 위치·높이·방향·방출구 좌표를 별도 검토하고 단위를 확인한다.
3. 운전·비상절차서에서 정상 운전, 차단 성공, 차단 실패의 상태 전이를 명시한다.
4. 실제 설비 모델이 사고 전용 `export_accident_history()`를 내보내고, 개구·시계·질량·엔탈피 장부를 제공할 때만 `ResolvedGasRelease` 또는 `ResolvedLiquidRelease`로 변환한다.
5. 문헌 빈도는 별도 `FrequencyPlan`의 exact match로만 결합한다. PDF 내용만으로 빈도를 만들지 않는다.

이 순서가 지켜져야 검사센터 자료가 일반 액화수소시설용 모델에 재사용될 수 있고, 센터 고유 태그나 합성값이 일반 시설의 기본값으로 굳어지는 것을 막을 수 있다.
