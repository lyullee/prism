# PRISM 검증 입력 준비도 감사

검사센터의 액화수소 시계열과 외부 설비 검증 장부를 PRISM의 검증 입력 관점에서 한 번 더 묶었다. 이 문서는 정상 운전 자료를 사고자료로 바꾸는 문서가 아니다. 어떤 자료가 있는지, 다음 단계로 넘기려면 무엇이 더 필요한지를 자동으로 기록하는 장부다.

## 실행

```powershell
python scripts/build_validation_intake_audit.py `
  --inspection-timeseries-audit examples/inspection_center_timeseries_audit.json `
  --equipment-validation-audit results/20261009/validation_evidence/equipment_validation_audit.json `
  --output results/20261104/validation_intake_audit_current.json
```

## 현재 결과

현재 결과의 상태는 `SCREENED_NO_PROMOTION`이다. 검사센터 자료 17개 workbook, 78개 sheet, 147,529개 행과 522개 수치 후보 열을 확인했다. 자료는 인수·벤트·공급 시나리오와 원본/학습 자료가 섞인 입력 준비도 자료이며, 이 숫자만으로 압력 단위, 온도 단위, 질량유량 기준 또는 사고 개구부를 결정하지 않는다.

외부 설비 검증 장부에는 독립 검증 시나리오가 기록되어 있지만 방출이 승격된 시나리오는 0개다. 따라서 현재 PRISM은 다음을 모두 닫아 둔다.

- 정상 운전 행을 accidental release packet으로 변환
- 센서값에서 누출 구경·방출시간·차단 성공을 역산
- 센서 자료에서 사고 빈도를 학습하거나 빈도에 반영
- 검사센터 태그를 일반 LH2 시설의 자산·P&ID 포트로 자동 복사
- 물리검증 점수, 전체 방출→SLABx-LH2 검증, 시설 IR/F-N 승격

단위표를 별도로 검토해 넣더라도 이것은 상태 입력의 준비 단계일 뿐이다. 단위표 이후에는 보정·품질·결측·시각 지연을 확인하고, 일반 시설의 자산 및 P&ID 포트 대응표를 만든 뒤, 동일 설비·동일 개구를 가리키는 provider 방출 packet을 독립적으로 제출해야 한다. 그 packet에는 방출 시작, 종료 근거, 차단, 재고 장부 및 질량수지가 있어야 한다.

## 장부의 역할

`results/20261104/validation_intake_audit_current.json`은 입력자료의 존재와 승격 게이트를 함께 보존한다. `scenario_groups`는 인수·벤트·공급 자료의 파일 수, sheet 수, 행 수, 수치 후보 열 수를 보여준다. `promotion_gates`는 자료가 많아도 사고 방출이나 빈도가 자동으로 생기지 않음을 명시한다. 이 장부가 `promotion_allowed=false`인 것은 자료가 쓸모없다는 뜻이 아니라, 자료의 역할이 공정 상태 후보 증거로 제한되어 있다는 뜻이다.

## 다음에 필요한 원본

1. 검토자가 승인한 exact tag-to-unit 및 절대압/게이지압 기준표
2. 센서 보정, 품질 플래그, 결측 처리, 원본시각·도착시각·지연 기록
3. 일반 LH2 시설의 자산번호와 P&ID 포트·밸브·벤트 끝점 대응표
4. 각 설비 모델이 만든 개구·종료·차단·재고·질량수지 포함 방출 packet
5. raw historian/DCS/PLC 자료에 대한 독립 holdout 비교와 승격 결정

이 조건이 충족되면 먼저 상태 snapshot을 검증하고, 그 다음 provider 방출 경계와 SLABx-LH2 결과를 별도로 검증한다. 조건이 충족되기 전에는 검사센터 데이터가 PRISM의 문헌 빈도, 방출 지속시간, 피해영향 또는 시설 QRA를 바꾸지 않는다.

## IJHE 목표 감사와의 연결

이 준비도 장부를 IJHE 목표 감사의 `diagnostic_validation_intake_readiness` 검사에 연결했다.

```powershell
python scripts/build_ijhe_objective_coverage_audit.py `
  # 기존 통합 원장 입력을 모두 전달한 뒤
  --validation-intake-audit results/20261104/validation_intake_audit_current.json `
  --output results/20261104/ijhe_objective_coverage_audit_with_validation_intake.json
```

현재 검사는 `PASS`지만 이것은 입력자료 준비도와 승격 차단 정책이 올바르게 기록됐다는 뜻이다. 최신 IJHE 감사 상태는 `CONDITIONAL_DIAGNOSTIC_COMPLETE_STRICT_GATES_OPEN`이며 핵심 연결 차단은 0개, 엄격 승격 차단은 4개다. 새 검사는 엄격 차단 목록에 들어가지 않으므로 검사센터의 정상 운전자료가 물리검증·빈도·시설 IR/F-N을 열지 않는다.
