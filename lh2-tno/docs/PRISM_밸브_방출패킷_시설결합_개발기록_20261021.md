# PRISM 밸브 방출 패킷 시설 결합 기록 — 2026-10-21

## 이번 개발의 목적

기존 시설 위험도 계산에는 `transfer-valve-01`의 5개 문헌 면적 사건이 생성되어 있었지만, 실제 액체 방출 패킷이 시설 계산에 연결되지 않아 해당 사건이 미계산으로 남아 있었다. 이번 단계에서는 저장된 `lh2dt.Valve` 방출 패킷을 PRISM의 일반 시설 캠페인 입력으로 묶었다.

## 연결된 계산 경로

```text
LH2_VALVE 문헌 면적 빈도
  → transfer-valve-01 사건 5개
  → 저장된 lh2dt.Valve 액체/2상 방출 패킷
  → 방출 지속시간·방출 질량·잔류 질량 확인
  → SLABx-LH2/SLABx 피해 계산
  → 점화·기상 조건별 IR/F-N 위험 원자
  → 7개 캠페인 시설 원장
```

실행 스크립트는 [validate_valve_campaign.py](../scripts/validate_valve_campaign.py)이다. 패킷의 `event_id`와 `component_id`를 확인하고, PRISM 시설 포트 `valve-accident-out`으로 연결한다. 패킷이 가진 방출 경계와 종료 시간을 PRISM이 다시 추정하지 않는다.

## 빈도 해석

밸브 빈도는 `LH2_VALVE` 문헌의 5개 면적 구간을 그대로 사용했다. 패킷의 결과나 센서 신호에서 누출 빈도를 학습하거나 새로 만들지 않았다. 5개 구간의 문헌 중앙값과 로그정규 한계는 기존 빈도 불확실성 시나리오에서 유지되며, 서로 독립이라고 가정해 시설 신뢰구간으로 부르지 않는다.

## 현재 남은 문제

1. 밸브 패킷은 실제 시설 설비의 검증된 상태 출력이 아니라 합성·스크리닝 자료이다.
2. 0.01% 면적의 두 사례가 시간 제한으로 계산되지 않았다.
3. 제공자 패킷의 자격 증거와 독립 물리 검증이 없다.
4. 재고 소진, 차단 신뢰도, 실제 설비 형상·인구·기상은 시설 실증 자료로 닫히지 않았다.
5. 따라서 [IJHE 완료 감사](../results/20261021/ijhe_completion_audit_valve_transfer_line_replacement.json)는 `INCOMPLETE_EVIDENCE`이다.

이번 단계는 밸브 설비를 별도 애드온으로 분리한 것이 아니라, PRISM의 동일한 시설 위험 원장에 선택형 외부 방출 패킷 경계로 결합한 것이다. 다만 제공자 경계가 자격을 얻기 전까지는 조건부 진단 결과로만 사용한다.

## 2026-10-22 제한시간 재시도

초기 실행에서 `AREA_0.01%` 두 사례가 180초 백엔드 제한을 넘었다. `validate_valve_campaign.py`에 `--area-bin`과 `--timeout-s` 옵션을 추가해 해당 구간만 360초 제한으로 재실행했다. 두 사례 모두 `EXECUTED_OPERATOR_LIMITED`로 완료됐고, 질량 잔차는 허용오차 안에 들어왔다.

수정된 밸브 캠페인은 [repaired campaign result](../results/20261022/valve_provider_all_bins_campaign_repaired/campaign_result.json)이며, 전체 밸브 사례는 10개 실행·10개 operator-limited·0개 backend failure가 됐다. 7개 캠페인 시설 원장은 [repaired facility ledger](../results/20261022/native_campaign_with_repaired_valve_transfer_line_replacement_vertical_all_bins_two_sided_inventory_isolation_facility_ledger.json)로 갱신됐고 41개 사건, 80개 사례, 37개 보류 복사본, 312개 위험 원자를 기록한다.

재시도로 계산 누락은 줄었지만 provider의 정상상태·개방 경계 한계와 합성 시설 조건은 그대로다. 따라서 시설 전체 IR/F-N과 IJHE 완료 감사는 여전히 차단 상태다. 새 처리시간은 밸브 캠페인 사례 p95 약 87.5초, p99 약 94.9초이며 1 Hz 신선 물리계산을 의미하지 않는다.

## 조건부 숫자 계산과 시설 승격의 분리

범위표에 `conditional_status`와 `conditional_chain_complete`를 추가했다. `EXECUTED_OPERATOR_LIMITED`는 숫자 결과가 존재하므로 조건부 계산 통계에서는 실행으로 세지만, 엄격한 `status`와 `matrix_complete`에서는 시설 자격 부족으로 계속 `PARTIAL`이다. 현재 통합 범위표는 엄격한 시설 범위가 `PARTIAL`이지만, 이전 형식 범위표의 `executed_case_count`도 조건부 회계에 반영하도록 병합기를 보완해 12개 선언 family의 조건부 미계산 case는 0개가 됐다. 이 표기를 통해 계산된 운전자 제한 사례, 실제 미계산 사례, 시설 승격 차단을 서로 섞지 않는다.

## 2026-10-22 감사 회계 보완

`src/lh2_tno/completion_audit.py`에 `conditional_accident_scope_accounting` 진단 항목을 추가했다. 이 항목은 범위표가 제공하는 `conditional_status`, 실행 case 수, 미계산 case 수, 그리고 조건부 차단 이유를 형식적으로 확인한다. 조건부 항목이 `PASS`라는 뜻은 숫자 결과를 보존할 수 있다는 뜻이며, `EXECUTED_OPERATOR_LIMITED`를 적격 시설 계산으로 승격하지 않는다.
