# 방출부터 최종 피해까지: 전체 계산 연결

2026-10-08 / LH2-TNO v0.2.0

**한 번 실행하면 방출량부터 사람 위치별 최종 피해까지 이어지는 진단 계산 경로를 구현했다.** 앞서 만든 설명서에서 “전체 연결 미완료”라고 설명했던 부분에 대한 후속 구현이다. 이 문서의 완료는 프로그램 연결의 완료를 뜻한다. 모든 액화수소 현상, 현장 정확도, IJHE 게재 요건의 완료를 뜻하지 않는다.

## 아주 쉽게 말하면

이전에는 여러 계산기가 따로 있었다. “수소가 얼마나 새는가”를 계산하는 기계, “어디로 퍼지는가”를 계산하는 기계, “사람에게 얼마나 위험한가”를 계산하는 기계가 서로 결과를 넘기지 못했다.

이제는 앞 계산의 결과를 다음 계산에 실제로 넘긴다.

**탱크에서 샘 → 액체와 기체를 나눔 → 바닥의 액체가 증발함 → 수소가 퍼짐 → 불이 붙는 경우를 나눔 → 열과 폭발 피해를 계산함 → 사람 위치별 피해 확률을 계산함.**

시설마다 센터의 태그나 운전 설정을 복사할 필요가 없다. 탱크, 누출구, 바닥, 바람, 사람 위치를 해당 시설의 값으로 바꾸는 구조다. 검증용 입력은 합성 사례이며 센터 실증자료로 보정한 결과가 아니다.

## 실제로 연결한 계산

| 순서 | 계산 내용 | 실제 호출/처리 |
|---|---|---|
| 1 | 압력·온도·누출구에서 방출량 계산 | 최신 SLABx-LH2 `integrated_lh2_source`, HEM/HNEM 선택 |
| 2 | 기체·잔류 액적·바닥 액체를 구분 | native 액적 분배 및 질량 검사. 해결되지 않은 잔류 액적은 거절 |
| 3 | 액체가 바닥에 도착 | 액적 등급별 비행시간만큼 유입 시계를 지연 |
| 4 | 바닥 액체가 퍼지고 증발 | DynamicLH2PoolX. 방출이 끝나도 남은 액체의 증발을 계산 |
| 5 | 차가운 제트가 공기를 끌어들이고 방향을 바꿈 | `lh2_jet_cloud_transition`, 극저온 공기상 변화 및 수평 벡터 전이 |
| 6 | 멀리 퍼지는 구름 | SLABx `run_dispersion`, 보존 검사된 handoff |
| 7 | 시간별 구름·사람 위치의 농도 | native 평균 단면을 사용한 유한 질량/유한 체적 구름 재구성 |
| 8 | 바로 점화·늦은 점화·폭발·점화 없음 | 상호 배타적인 사건 분기. 전체 확률 합계 1 검사 |
| 9 | 화재가 주는 열 | TNO 화염 형상·복사 전달, 명시한 복사율 범위 |
| 10 | 폭발 피해 구역 | 구름 내 4–75 mol% 수소 질량 → TNO multi-energy 0.3/0.1 barg 구역 |
| 11 | 사람의 피해 | 실제 방사열 시간 적분 → TNO 열피해 probit; flash/fire/blast 피해 |
| 12 | 조건부 위험 | 이미 관측된 누출의 피해, 미발생 사건의 단기 위험, 현재 기상 연간 기여 |

방사열을 임의로 넣어 피해변환만 시험하는 기존 예제와 달리, 새 전체 경로의 방사열은 앞단 화재 계산에서 생성한다. 폭발용 수소 질량도 “면적×고정 높이” 대용값 대신 계산 격자 안의 수소 질량으로 구한다.

## 무엇을 넣고 무엇을 받는가

시설 입력에는 탱크 체적·수소 물성 기준·사람 위치가 들어간다. 시나리오 입력에는 압력·온도·누출구 크기/방향·방출 시간·바람이 들어간다. 바닥에 액체가 도달하면 바닥 열물성과 유입 면적도 필요하다. 한 개의 액적 충돌점만으로 유입 면적을 알 수 없으므로, 설계값·실측값·명시한 민감도 가정 중 어느 것인지 표시한다.

점화 확률, 구름이 타는 시간, 복사율 범위, 폭발 에너지에 관여하는 장애물 비율, 누출 빈도는 출처가 있는 입력값이다. 프로그램이 실험자료에서 이 값들을 자동 학습했다고 표시하지 않는다.

결과 JSON에는 다음 값이 들어간다.

- 원래 방출 계산의 전체 상태와 기체/바닥 액체 질량.
- 액적 도착 시계, 시간별 풀 잔량과 누적 증발량.
- 근거리→SLAB 전이 상태와 보존 잔차.
- 시간별 구름 질량, 격자 밖 수소 질량, 가연성 수소 질량.
- 사람 위치별 농도 이력, 방사열 이력, 열 노출량과 피해 확률.
- 폭발 피해 구역, 점화 분기별 피해, 관측된 누출의 조건부 피해.
- 빈도가 있으면 해당 사건·현재 기상 조건의 연간 기여. 빈도가 없으면 `None`.
- 계산 시간, 입력/시설/모델 코드 식별값, 적용범위와 미검증 항목.

한 사건 안에서 열·flash·폭발 피해가 겹치면 독립적인 사망 사건처럼 곱하지 않는다. `min(1, 피해확률 합)`이라는 합집합 상한을 사용한다. 출력의 low/high는 입력 복사율 두 값에 대한 민감도 결과이며, 통계적 신뢰구간이 아니다.

## 실제 실행 확인

두 기본 사례는 0.2초 방출과 20초 후속 계산을 사용한다. 재실행마다 시간은 달라질 수 있다.

| 확인 항목 | 결과 |
|---|---|
| 단위·입력·보존·시계·캐시 시험 | 68개 통과 |
| 기체 분산부터 최종 피해 | 전체 실행. 최근 약 3초 |
| 바닥 액체→풀→증발→최종 피해 | 전체 실행. 실행별 약 7–10초 |
| 기체 사례 총 방출량 | 약 0.210338 kg |
| 바닥 도달 사례 유입량 | 약 0.205405 kg. source 출력에서 자동 전달 |
| 전체 질량 장부 | 기체 사례 잔차 0 kg; 풀 사례 약 10⁻¹⁶ kg 수준 |
| 방출 종료 후 풀 증발 | 실제 native 풀 결과에서 증가 확인 |
| 점화 확률이 0인 경우 | 연소 피해 0 |
| 방출 압력차가 0인 경우 | 방출·구름·연소 피해 0 |
| 시설과 바람을 함께 90도 회전 | 가연성 질량·사람 피해의 일관성 확인 |
| 빈도가 없는 경우 | 연간 값을 0으로 만들지 않고 `None` |
| native 방출 이력이 도중 종료 | 마지막 방출률을 계속 연장하지 않고 거절 |
| 지면 도달량은 양수인데 footprint 없음 | 풀을 만들어내지 않고 거절 |

질량 잔차가 작다는 것은 수소를 중간에서 잃거나 두 번 더하지 않았다는 뜻이다. 농도·복사열·피해 예측이 실험과 맞는다는 뜻은 아니다.

## 디지털트윈 연결

`ConsequenceService.update_from_telemetry()`는 기존 텔레메트리 정규화 결과의 탱크 압력·온도를 전체 계산에 전달한다. 압력의 절대/게이지 기준, 단위, 센서 위치, 품질, 자료 출처는 먼저 정규화 계층에서 확인한다. 누출구 위치·크기·방향이 알려진 시나리오에 대한 상태 갱신이다. 센서만으로 누출구 크기나 누출 빈도를 역추정한 결과는 아니다. 외부 설비 디지털 트윈이 새 방출 경계를 계산하는 경우에는 `release_resolver`를 명시적으로 사용하며, resolver가 검증된 `ResolvedGasRelease`/`ResolvedGasReleaseSet`/`ResolvedLiquidRelease`가 들어 있는 `ConsequenceRequest`를 반환해야 한다. 일반 source 입력, 누출 크기 추정, initiating frequency를 반환하면 거절한다.

완전히 동일한 입력과 동일한 모델 코드의 결과는 메모리에서 조회한다. 실제 조회 시험은 약 20–40 ms 수준이었다. 센서 압력 등 입력이 달라지면 새 계산을 요구한다. 예전 결과를 새 계산이라고 내보내지 않는다. 코드가 바뀌면 캐시도 사용하지 않는다.

**약 20–40 ms 조회와 매초 새로운 물리 계산은 다르다.** 지금 확인된 신규 계산 시간은 기체 약 3초, 풀 포함 약 7–10초다. 실시간 신규 계산 요건은 아직 입증하지 않았다.

## 지금 결과를 어디까지 믿을 수 있는가

현재 지원 범위는 바람이 있는 옥외·평탄 지면·알려진 누출구의 진단 계산이다. 다음은 명확한 후속 항목이다.

- 액적 증발이 일어나는 위치·시간을 기체 구름에 분포시키는 전달. 지금 기체 분기는 terminal gas 경계로 축약한다.
- 누출구의 수직 운동량 전달. 화재 형상에는 방향을 반영하지만 근거리 전이는 수평 벡터 경로다. 수직 전용 노즐은 거절한다.
- native 평균 단면을 이용한 유한 체적 농도 재구성의 독립 검증. 이 경로는 기존 FFI 7개 시험의 동결된 최종 농도장 경로가 아니다.
- 여러 구름 packet의 공기·압력·온도 재평형, 화재가 풀에 되돌려주는 열, 짧은 방출에서 화염이 자라는 시간.
- 연속 과압/충격량 곡선, DDT/폭굉, 실내·복잡한 장애물·움직이는 deposition 중심. 현재 폭발 피해는 두 TNO 구역이다.
- 센터 독립 실증자료 검증, 다른 시설 데이터 검증, 점화·복사율·빈도 근거 확보.
- 전체 기상 분포를 적분한 연간 IR, 누출 역추정, 신규 계산 가속과 처리시간 분포.

따라서 결과 상태는 `END_TO_END_DIAGNOSTIC_EXECUTED`, 현장 검증 상태는 `WITHHELD`로 남긴다. 외부 연구 코드와 기존 동결 논문 결과는 수정하지 않았다.

## 재실행 방법

`lh2-tno` 폴더에서 프로젝트 Python 환경을 사용한다. 외부 모델 interpreter와 해시는 `results/20261008/full_chain/backend_config.json`에 있다.

```powershell
$env:PYTHONPATH = "src"
python -m lh2_tno.cli results/20261008/full_chain/facility.json --backend results/20261008/full_chain/backend_config.json --consequences results/20261008/full_chain/rainout_pool_request.json --output results/20261008/full_chain/user_run.json
```

Python 직접 호출은 `ResearchPipeline.consequences(ConsequenceRequest)`다. 통합 실행 스크립트는 `scripts/validate_chain.py`, 실제 모델의 경계조건·회전·센서·캐시 확인은 `scripts/validate_chain_edgecases.py`다. 실행 입력, 전체 결과, 짧은 요약은 `results/20261008/full_chain`에 저장된다.
