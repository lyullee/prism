# PRISM 설비 액체·2상 출구 연결 기록

2026-10-09

## 목적

기존 `ResolvedGasRelease` 경계만으로는 설비 모델이 계산한 액체·2상 방출을 표현할 수 있었다. 이 단계에서 provider가 계산한 flash와 지면 분할을 PRISM의 기존 피해 경로에 명시적으로 전달하는 `ResolvedLiquidRelease` 경계를 추가했다. 특정 검사센터의 태그를 복사하지 않고 일반적인 옥외 액화수소 설비의 출구 계약으로 정의했다.

연결 순서는 다음과 같다.

```text
설비 provider
  → 액체 총 유량 / flash 기체 / 지면 액체 / 액적 도착 시계
  → ResolvedLiquidRelease 계약
  → 기체 근거리 전이 + SLABx 확산
  → 지면 액체 도착 + DynamicLH2PoolX 풀/증발
  → 점화·화재·폭발·TNO 인명 피해
```

PRISM은 provider의 압력완화, flash, nozzle 유량, 액적 운동을 다시 풀지 않는다. 질량 분할, 대기압 기체 상태, provider 누적 질량·엔탈피가 맞는지만 검사한다.

## 계약에서 확인하는 것

- `component_id`와 `port_id`가 시설의 outward liquid/two-phase 포트와 일치한다.
- `property_basis`와 native enthalpy 기준이 시설과 일치한다.
- ENU 출구 방향이 단위벡터이고 출구 높이가 평탄 지면보다 높다.
- 각 시간 구간에서 `total = gas + ground + airborne`가 닫힌다.
- 기체 유량이 있으면 대기압, 온도, 밀도, 유효 면적, 속도가 모두 있고 `gas = rho × velocity × area`가 닫힌다.
- 지면 액체 유량이 있으면 액적 등급의 비행시간·충돌 위치가 있어야 한다.
- provider cumulative mass/enthalpy와 시간 적분이 일치한다.
- `airborne_liquid_mass_flow_kg_s > 0`은 별도 검증된 droplet adapter가 없으므로 거절한다. 이를 기체로 조용히 더하지 않는다.
- normal vent에는 임의 사고 빈도를 붙이지 않는다. 사고 빈도를 붙일 때는 구멍 크기와 LH2 서비스가 문헌 사건과 맞아야 한다.

핵심 구현은 `src/lh2_tno/equipment_boundary.py`, `src/lh2_tno/resolved_liquid_worker.py`, `src/lh2_tno/consequences.py`, `src/lh2_tno/chain_worker.py`에 있다. `service.py`는 provider-resolved liquid request를 telemetry가 P/T로 덮어쓰지 않도록 막는다.

## 실제 진단

`scripts/validate_equipment_liquid_release.py`는 pinned SLABx-LH2 `liquid_jet_source`를 호출하고, endpoint 샘플을 제외한 left-held provider interval을 `ResolvedLiquidRelease`로 변환한다. 이후 다음 단계를 한 번에 실행했다.

| 항목 | 결과 |
|---|---:|
| provider phase basis | `two_phase` |
| provider 방출 재고 | 1.3210337112 kg |
| provider gas/ground partition | 닫힘 |
| DynamicLH2PoolX 경로 | 실행 |
| 전체 chain 상태 | `END_TO_END_DIAGNOSTIC_EXECUTED` |
| 최종 질량 잔차 | 약 `7.55×10⁻¹⁵ kg` |
| 전체 실행 시간 | 약 14.24 s |
| 물리 검증 claim | `false` |

단계별 시간은 source 약 0.71 s, pool 약 0.98 s, 근거리·확산 약 11.99 s, 관측연산자 약 0.20 s, 화재·폭발·피해 약 0.12 s였다. 이 한 건은 일반적인 처리시간 분포나 1 Hz 신규 계산을 입증하지 않는다.

## 해석과 남은 범위

이번 결과는 “설비가 계산한 액체·2상 경계를 받아 방출부터 최종 피해까지 계산할 수 있다”는 소프트웨어 연결 증거다. 다음을 의미하지 않는다.

- SLABx-LH2의 flash·분무·ballistic rainout이 현장 실험으로 검증됐다는 뜻이 아니다.
- provider의 open spray-energy closure를 닫았다는 뜻이 아니다.
- 실제 LayeredTank 액체/2상 재고 소진 또는 actuator 차단 신뢰도를 계산했다는 뜻이 아니다.
- airborne liquid을 모델링했다는 뜻이 아니다. 해당 상태는 현재 명시적으로 거절한다.
- 이 사건에 문헌 빈도나 시설 전체 annual IR/F-N을 붙였다는 뜻이 아니다. 이번 진단은 조건부 피해 경로만 실행했다.

다음 개발은 LayeredTank provider가 양수 재고 종료·flash·에너지 장부·차단 사건을 함께 반환하는 계약을 제공한 뒤, 동일한 `ResolvedLiquidRelease` 경계로 연결하는 것이다. 그 전까지는 현재 provider liquid 경로를 `operator_limited`로 유지한다.
