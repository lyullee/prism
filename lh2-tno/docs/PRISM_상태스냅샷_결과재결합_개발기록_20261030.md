# PRISM 상태 스냅샷 결과 재결합 개발 기록

## 목적

시설 캠페인 결과가 상태 스냅샷과 실제로 같은 설비 실행을 가리키는지 다시 확인한다. 이전 결과 파일에 상태 연결 감사가 있어도, 결과의 `cases`와 `risk_atoms`에 스냅샷이 보존되지 않으면 재실행 때 상태 정보가 사라질 수 있었다.

## 적용 규칙

- 원래 캠페인 요청에 canonical `EquipmentStateSnapshot`과 snapshot digest가 있어야 한다.
- 상태 감사가 `STATE_SNAPSHOT_BOUND_AND_ECHOED`이고 component 및 provider-result digest가 정확히 일치해야 한다.
- 결과의 component, snapshot digest, provider-result digest가 요청·감사 장부와 모두 같아야 한다.
- 방출량, 지속시간 또는 피해값으로 상태를 거꾸로 추정하지 않는다.
- 하나라도 빠지거나 모호하면 캠페인 재생성을 중지한다.

구현은 `src/lh2_tno/state_snapshot_result_binding.py`의
`bind_campaign_result_state_snapshots()`에 있다. 전체 시설 union 실행기는 이 검사를 base result에 먼저 적용한 뒤에만 수직 handoff·재고 소진 결과를 병합한다.

## 재현 명령

```powershell
python scripts/run_native_full_scope_union_assessment.py `
  --base-dir results/20261026/native_full_scope_frequency_assessment `
  --base-campaign results/20261030/native_near_receptor_scope_packets_state_bound/campaign_state_bound.json `
  --base-campaign-result results/20261030/native_near_receptor_scope_packets_state_bound/campaign_result.json `
  --vertical-result results/20261020/vertical_vent_all_bins/campaign_result.json `
  --vertical-scope-matrix results/20261020/vertical_handoff_scope_matrix_all_bins.json `
  --inventory-result results/20261009/equipment_inventory_campaign/campaign_result.json `
  --inventory-scope-matrix results/20261019/inventory_depletion_scope_matrix_rebound.json `
  --inventory-source-asset-id terminal_pipe_asset `
  --inventory-source-component-id terminal_pipe `
  --state-snapshot-binding-audit results/20261027/native_generic_scope_packets_state_bound/state_snapshot_binding_audit.json `
  --output-dir results/20261026/native_full_scope_union_assessment
```

실제 공식 실행은 34개 event, 44개 case, 176개 risk atom을 만들었고 176개 risk atom 모두 상태 스냅샷을 보존했다. base 결과에 대해서는 24개 event, 43개 case, 96개 risk atom이 `STATE_SNAPSHOT_RESULT_BOUND_AND_ECHOED`로 재결합된다. 이 결과는 상태 연결을 재현할 수 있다는 뜻이며, provider 자격·독립 물리검증·시설 전체 IR/F-N을 자동으로 승인하지 않는다.

## 결과 파일

- `results/20261026/native_full_scope_union_assessment/base_result_state_snapshot_binding.json`
- `results/20261026/native_full_scope_union_assessment/verification.json`
- `results/20261026/native_full_scope_union_assessment/ijhe_completion_audit.json`

현재 IJHE 감사는 33개 검사 중 28개 PASS, 5개 BLOCKED다. 차단 사유는 방출 종료 경계, 실제 qualified provider packet, 주요 사고 범위, 시설 IR/F-N, 44개 시설 case의 provider packet coverage다. 따라서 union은 재현 가능한 진단 결과로 유지하며 시설 전체 QRA로 표기하지 않는다.
