# PRISM 실시간 설비별 위험순위 장부

## 목적

`FacilityRealtimeConsequenceMonitor`는 여러 설비의 같은 시각 frame을 묶어
방출과 피해를 계산합니다. 이번 보완은 그 snapshot 안에서 현재 계산된 설비별
위험을 운영자가 먼저 확인할 수 있도록 우선순위 장부를 추가한 것입니다.

## 계산 규칙

`aggregate.component_risk_ranking`은 각 설비의
`harm_given_observed_release_low_high`와 별도 `RealtimeFrequencyBinding`을
사용해 만든 현재 기상 연간 IR을 읽습니다. 설비별 모든 수용점 중 가장 큰 IR을
낮은·높은 불확실성 끝점으로 보존하고, 높은 끝점부터 정렬합니다. 수용점을 서로
더하거나 설비 빈도를 재분배하지 않습니다.

빈도 binding이 없거나 frame이 빠졌거나 provider 피해가 잘못된 설비는
`rank=null`, `peak_annual_ir_low_high=[null, null]`로 남습니다. 이 값은 0 위험을
뜻하지 않습니다. `withheld_component_count`와 각 행의 `reason`으로 왜 순위가
보류됐는지 확인합니다. 일부 설비만 계산된 경우에도 계산된 설비의 순위는 남기되,
상태는 `PARTIAL_CURRENT_WEATHER_COMPONENT_RANKING`으로 표시합니다.

각 행에 문헌 빈도 binding의 `p05`·`published`·`p95`가 모두 있으면
`frequency_sensitivity_peak_annual_ir_low_high`와
`frequency_sensitivity_rank`도 함께 기록합니다. 세 빈도 시나리오에서 같은 순위를
유지하면 `frequency_sensitivity_rank_stable=true`입니다. 이 순위는 같은 provider
피해 결과에 빈도만 다시 곱한 것이며 물리계산을 반복하지 않습니다. 일부 설비에
범위가 없으면 해당 행의 시나리오 값은 `null`이고 전체 장부 상태는
`PARTIAL_CURRENT_WEATHER_FREQUENCY_RANKING`으로 남습니다.

예시:

```json
{
  "component_risk_ranking": {
    "status": "PARTIAL_CURRENT_WEATHER_COMPONENT_RANKING",
    "component_count": 2,
    "available_component_count": 1,
    "withheld_component_count": 1,
    "frequency_reallocation_performed": false,
    "facility_ir_fn_promotion": false,
    "stale_or_zero_fallback_used": false,
    "rows": [
      {
        "rank": 1,
        "component_id": "storage-tank-01",
        "peak_annual_ir_low_high": [2.0e-5, 4.0e-5],
        "frequency_sensitivity_rank": {
          "p05": 1,
          "published": 1,
          "p95": 1
        },
        "frequency_sensitivity_rank_stable": true
      },
      {
        "rank": null,
        "component_id": "transfer-pump-01",
        "peak_annual_ir_low_high": [null, null],
        "risk_status": "WITHHELD_MISSING_LITERATURE_FREQUENCY"
      }
    ]
  }
}
```

이 장부는 설비 점검 순서를 정하는 진단 화면용입니다. 시설 전체 annual IR/F-N,
센서 기반 빈도 학습, 누출 크기 역추정, 1 Hz 신규 물리계산을 열지 않습니다.
전체 시설 위험을 계산하려면 모든 선언 설비·사고 family·문헌 빈도·검증 packet이
별도 gate를 통과해야 합니다.

## 검증

`tests/test_consequence_service.py`는 문헌 빈도가 없는 두 설비의 순위를 보류하고,
빈 frame을 0으로 대체하지 않으며, 명시된 문헌 빈도가 있는 설비의 현재 기상 IR
순위만 계산하는지 확인합니다.
