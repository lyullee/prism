# PRISM 설비별 사고 시나리오 커버리지 감사 (2026-11-04)

## 왜 필요한가

액화수소 설비 모델이 있다는 사실만으로는 어떤 사고를 계산할 수 있는지 알 수 없다. 예를 들어 탱크 모델은 정상 운전 상태를 계산할 수 있어도 탱크 벽 구멍, 배관 양단 파열, 전량 재고 소진을 실제 방출 이력으로 내보내지 않을 수 있다.

이 감사는 다음 연결을 설비별로 보여준다.

```text
설비 ID → P&ID component kind → 사고 family → 필요한 provider 연산자
       → 방출 packet(지속시간·차단·재고·질량수지) → SLABx-LH2 → IR/F-N
```

중간 단계가 비어 있으면 뒤 단계로 넘어가지 않는다. 태그 이름이나 모델 클래스 이름만 보고 탱크·배관·밸브 종류를 추측하지 않는다.

## 현재 결과

결과는 [`equipment_scenario_coverage_audit_current.json`](../results/20261104/equipment_scenario_coverage_audit_current.json)이다.

현재 외부 설비 감사에는 12개 설비가 있지만 일반 시설용 P&ID component-kind crosswalk가 아직 없다. 그래서 12개 사고 family는 목록으로 선언했지만 0개 설비가 확정 매핑됐고, 방출 packet·빈도·시설 QRA는 열리지 않는다.

| 항목 | 현재 값 |
|---|---:|
| 설비 수 | 12 |
| 확정 component-kind 매핑 | 0 |
| 확정 설비 identity | 0 |
| 사고 family 목록 | 12 |
| 사고 방출 packet 허용 | 아니오 |
| 빈도 추론 허용 | 아니오 |
| 시설 QRA 허용 | 아니오 |

감사 상태 `CROSSWALK_REQUIRED`는 “사고 목록이 없다”는 뜻이 아니다. 탱크 hole, pipe hole, valve hole, vent discharge, pump hole, vaporizer hole, reliquefier hole, liquid two-phase, inventory depletion, 600 s bounded inventory, two-sided rupture, vertical handoff 같은 선언된 family는 보인다. 다만 어떤 실제 설비와 연결되는지 증거가 없어 계산하지 않는다는 뜻이다.

## 일반 시설에서 사용하는 방법

시설별로 다음 형식의 crosswalk를 준비한다.

```json
{
  "schema_version": "prism.equipment_kind_crosswalk.v1",
  "facility_neutral": true,
  "rows": [
    {
      "asset_id": "TK-01",
      "component_kind": "storage_tank",
      "identity_status": "resolved",
      "identity_basis": "P&ID tag, port schedule, asset register"
    }
  ]
}
```

`identity_status`가 `candidate`이면 사고 family를 계산 대상으로 열지 않는다. `resolved`가 된 뒤에도 provider가 사고 방출 packet을 제출해야 한다. packet에는 개구 또는 방출 방식, 시간 이력, 차단 시각, 재고 소진 또는 제한시간, 출구 열역학 상태, 질량수지가 있어야 한다.

재현 명령은 다음과 같다.

```powershell
python scripts/build_equipment_scenario_coverage_audit.py `
  --equipment-audit results/20261104/external_equipment_model_audit_current.json `
  --kind-crosswalk configs/equipment_kind_crosswalk.json `
  --output results/20261104/equipment_scenario_coverage_audit_current.json
```

crosswalk를 아직 준비하지 않은 진단 실행은 `--kind-crosswalk`를 생략한다. 이 경우 현재처럼 `CROSSWALK_REQUIRED`로 남는다.

## IJHE 감사 연결

이 결과는 `diagnostic_equipment_scenario_coverage` 행으로 IJHE 원장에 연결된다. 최신 원장은 [`ijhe_objective_coverage_audit_with_external_equipment_model.json`](../results/20261104/ijhe_objective_coverage_audit_with_external_equipment_model.json)이다.

* 전체 상태: `CONDITIONAL_DIAGNOSTIC_COMPLETE_STRICT_GATES_OPEN`
* 검사 수: 20개
* 핵심 연결 차단: 0개
* 엄격 승격 차단: 4개
* 설비 시나리오 커버리지 진단: `PASS`

여기서 `PASS`는 crosswalk가 완성됐다는 뜻이 아니다. “crosswalk가 없다는 사실과 그에 따른 계산 차단을 정확히 기록했다”는 뜻이다. 이는 일반 액화수소 시설로 확장할 때 검사센터 전용 tag를 몰래 재사용하는 오류를 막는다.

## 다음 증거

1. 설비 ID와 P&ID port를 일반 시설용 crosswalk로 확정한다.
2. 각 확정 설비·사고 family에 provider release packet을 연결한다.
3. packet의 지속시간·차단·재고 소진·질량수지를 검증한다.
4. SLABx-LH2 결과와 독립 holdout 자료를 비교한다.
5. 그 다음에만 문헌 빈도 시나리오와 시설 IR/F-N 집계를 연결한다.
