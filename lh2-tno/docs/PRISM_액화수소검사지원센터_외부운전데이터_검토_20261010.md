# PRISM 외부 운전 데이터 검토 기록 (2026-10-10)

## 목적

`액화수소검사지원센터 데이터`를 PRISM의 일반 액화수소시설 기능에 연결할 수 있는지 읽기 전용으로 확인했다. 이 폴더의 자료를 일반시설의 빈도나 방출 종료값으로 복사하지 않고, 어떤 자료가 상태 재생에 쓸 수 있고 어떤 자료가 추가 검토를 필요로 하는지 기록한다.

검토 결과의 기계 판독 기록은 [review.json](../results/20261010/external_support_center_data_review/review.json)에 있다. 외부 원본은 저장소에 복사하지 않고 경로와 SHA-256만 기록했다.

## 확인된 자료

### 운전 순서 CSV

인수, 저장 벤트, 공급의 세 CSV에는 밸브 동작, 절차 단계, 누출·화재·폭발의 예상 고장과 조치가 들어 있다. 예를 들어 `XV10`의 개방·폐쇄와 폐쇄 후 하류 압력·유량 확인 항목이 있다. 이 자료는 설비의 신호명과 운전순서 어휘를 정하는 데 유용하지만, 사고 발생 횟수·노출시간·가동시간 분모가 없으므로 개시 빈도를 만들 수 없다.

### 10회차 예측 워크북

인수·저장 벤트·공급의 10회차 워크북은 `action`, `from_step`, `to_step`, `progress_pct`와 압력·온도·차압 열을 포함한다. 인수와 공급 파일의 단계별 행 수는 절차 진행을 나타내고, `progress_pct`는 0에서 100으로 반복된다. 이 파일에는 사고 시계, 실제 밸브 차단 시각, 누출 유량 또는 방출 종료 시각을 나타내는 명시적 시간열이 없다. 따라서 이 파일만으로 DynamicHEMPipe의 `inlet_isolation_time_s`나 `termination_threshold_kg`를 정하지 않는다.

### 원본 학습 데이터

인수·공급 원본에는 날짜-시간 열이 있는 분 단위 신호가 있고, 저장 벤트 복원 워크북에는 초 단위 시간열이 있는 시트가 있다. 그러나 각 자료의 설명 시트는 그래프 캡처 자료와 보정·삽입 값이 섞였음을 설명한다. 따라서 현재는 **상태 재생 및 신호명·시간축 후보**로만 분류한다. 공학 단위, 태그와 설비 포트, 압력 기준, 시계 동기화, 신호 품질을 검토한 뒤에야 `inspection_timeseries`와 상태 스냅샷으로 승격할 수 있다.

## 방출 종료와 빈도에 대한 판정

이번 검토 자료에서 다음 항목은 찾지 못했다.

- provider가 계산한 사고 개구와 방출 질량유량
- 사고 시작 후 실제 인입 차단 명령·확인 시각
- 양수 재고의 검토된 잔량 임계값 또는 대기압에서의 releasable inventory 정의
- 질량잔차와 에너지잔차
- 밸브 폐쇄 후 허용 누출유량과 하류 압력의 수치 기준
- 사고 발생 횟수와 운전·노출시간 분모

따라서 이 자료는 현재 일반 LH2 카탈로그의 15개 고정·합성 horizon을 닫지 않는다. 다만 향후 일반시설 입력 어댑터가 받을 수 있는 `component_id`, `port_id`, `sequence_step`, `commanded_state`, `observed_time`, `pressure`, `flow`, `quality`, `source_digest` 필드의 후보를 제공한다.

## PRISM에 반영한 범위

이번 단계에서 추가한 것은 외부 자료의 **출처·내용·승격 제한을 기록한 검토 아티팩트**다. 센서 숫자를 방출원이나 빈도로 역산하지 않으며, 센터 고유의 XV 태그와 절차를 일반시설 기본값으로 넣지 않는다. 자료가 나중에 검토되어도 다음 조건을 만족하는 행만 설비 provider 입력으로 사용할 수 있다.

1. 태그와 일반시설 `component_id/port_id`의 명시적 매핑
2. 단위·압력 기준·시계·품질의 검토 기록
3. 사고 개구와 방출 경계를 소유하는 provider 응답
4. 차단 시각과 양수 재고 종료 기준의 digest 결합 증거
5. 빈도는 별도의 문헌 `FrequencyEvent`와 reviewed accident port로 연결

이 구분을 지키면 센터 자료를 일반 모듈의 입력 형식과 검증 사례로 사용할 수 있지만, 센터 전용 위험도나 센서 기반 빈도 학습 모듈로 변하지 않는다.

## 현재 개발량과 남은 작업

현재 PRISM은 24개 일반 LH2 provider 사건 중 9개가 종료 증거까지 닫혀 있고 15개가 열린 상태다. 24개 모두에 대해 방출→SLABx-LH2→점화·기상·인구·IR/F-N의 진단 경로는 존재하지만, 열린 15개는 실제 차단·종료 근거가 없어 qualified provider와 시설 QRA로 승격되지 않는다. 최신 Actions의 `eee2f70` 검사는 성공했으며 로컬도 `885 passed, 1 skipped`다. 열린 packet별 수집 항목은 `prism.provider_release_closure_request.v1`로 자동 출력된다.

IJHE 제출 가능한 결과로 마무리하려면 기능을 크게 늘리기보다 다음 증거를 순서대로 채우는 것이 남은 일이다.

1. 실제 또는 검토된 provider 15개 사건에 차단 시각·종료 기준·재고 장부를 공급한다.
2. 그 packet을 현재 generic catalog에 exact-match하고 24개 사건의 case coverage를 다시 계산한다.
3. 사고 가족별 미계산 목록을 정리하고, 모든 사건에 reviewed accident port와 문헌 빈도를 연결한다.
4. 독립 물리 검증 자료와 신규 처리시간을 결과표로 고정한다.
5. 위 조건이 모두 채워졌을 때만 시설 IR/F-N과 최종 IJHE 문장을 qualified 결과로 작성한다.

현 자료만으로는 1번을 자동으로 완료할 수 없다. 실측 사고 방출 기록이 아니라 운전 절차와 상태 시계열이기 때문이다. 따라서 현재 남은 개발은 코드 작성량보다 **15개 provider 종료 증거의 확보와 검토**가 지배한다.
