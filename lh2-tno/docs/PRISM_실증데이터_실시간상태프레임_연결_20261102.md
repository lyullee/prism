# PRISM 실증데이터 실시간 상태 프레임 연결 기록 (2026-11-02)

## 목적

검사센터의 관측 자료를 디지털트윈에서 매 주기 사용할 수 있는 입력 형태로 만들었다.
이 단계의 입력은 압력·온도·질량·차압 같은 **현재 상태**다. 상태만 보고 누출이
일어났다고 판단하거나 사고빈도를 학습하지 않는다.

## 실행 흐름

```text
원본 Excel
  -> observed_state_input_manifest
  -> 상태 증거 장부와 원문 SHA-256 재생성
  -> source별 최신 captured_at_s 1개 선택
  -> prism.observed_state_runtime_frames.v1
  -> 정상상태 모델 또는 provider resolver 입력
  -> provider가 방출량·방출 방향·종료/차단·재고 경계를 명시
  -> PRISM 방출 packet 검증
  -> SLABx-LH2 확산·점화·피해 계산
```

`provider`가 방출 경계와 종료 조건을 반환하기 전에는 마지막 두 단계를 실행하지
않는다. 따라서 상태 frame은 서비스의 `validate_equipment_process_state`가 읽을 수
있는 `values` 구조와 canonical `prism.equipment_state_snapshot.v1`를 함께 가진다.

## 이번 산출물

실행 결과는
[`inspection_center_observed_state_runtime_frames.json`](../results/20261102/inspection_center_observed_state_runtime_frames.json)이다.

| 항목 | 결과 |
|---|---:|
| 상태 원본 | 3개 |
| 최신 runtime frame | 3개 |
| 원본 표본 | 8,955개 |
| 연결 대상 | intake tank, storage vent, supply/vaporizer boundary |
| 선택 규칙 | `captured_at_s`가 가장 큰 유효 표본, 동률은 원본 순서 |
| 상태 재생성 | 원문 SHA-256 3/3 및 canonical digest 일치 |

각 frame에는 `component_id`, 측정 `values`, `state_snapshot_digest`,
`frame_digest`, 센서 위치와 품질이 들어간다. 한 component에 여러 원본이 들어오면
중복을 허용하지 않고 오류로 중단한다. 지원하지 않는 사고·누출·점화·빈도 필드는
상태 evidence 단계에서 거부한다.

runtime handoff 계약은 `service_state_from_runtime_frame`과
`request_from_observed_state_runtime_frame`으로 고정했다. 호출자가 `now_s`를
명시해야 데이터 지연을 계산할 수 있고, resolver가 방출 경계를 반환하지 않으면
`request_from_equipment_resolver`가 요청을 거부한다. resolver는 사고빈도를
할당할 수 없고, 방출 지속시간·차단·재고 경계의 소유자는 설비 provider다.

## 안전한 해석 범위

산출물의 `policy`는 다음을 명시한다.

- `state_only=true`
- 방출 시나리오 생성, 빈도 추정, 센서 빈도 학습: `false`
- provider packet 승격, 독립 물리검증, 시설 QRA: `false`
- 피해 계산 전 provider 방출 결과 필요: `true`

그러므로 이 파일은 “실증 상태가 정상 모델 입력으로 들어갈 준비가 됐다”는
증거다. “검사센터 설비가 특정 사고 packet과 결합됐다”거나 “현장 빈도가
확보됐다”는 증거가 아니다. 현재 시설 component identity가 검토로 해소되지
않은 상태에서는 기존 매핑 정책대로 사고 방출 연결을 열지 않는다.

## 재현 명령

프로젝트의 bundled Python 또는 테스트 환경에서 다음을 실행한다.

```powershell
python scripts/build_observed_state_runtime_frames.py `
  --manifest examples/inspection_center_observed_state_manifest.json `
  --source-root "C:\Users\lyul\Desktop\DocuData\액화수소검사지원센터 데이터" `
  --output results/20261102/inspection_center_observed_state_runtime_frames.json
```

IJHE 목표 감사에 연결할 때는 `build_ijhe_objective_coverage_audit.py`에
`--observed-state-runtime-frames`를 추가한다. 감사에는
`diagnostic_observed_state_runtime_frames` 행이 생기며, frame 수·digest·state-only
정책이 맞을 때만 `PASS`다. 이 행이 `PASS`여도 qualified provider, 독립 물리검증,
엄격한 사고범위, 시설 전체 IR/F-N gate를 닫지는 않는다.
