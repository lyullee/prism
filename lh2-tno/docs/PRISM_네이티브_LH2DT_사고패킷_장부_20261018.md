# PRISM 네이티브 LH2DT 사고 패킷 장부

이 문서는 `lh2dt_models`의 설비 모델이 만든 사고 방출 결과를 PRISM이 어디까지 소비했는지 기록한다. 장부의 목적은 계산된 범위를 쉽게 확인하는 것이다. 이 장부 자체가 현장 검증, 시설 전체 QRA, 또는 새로운 사고빈도를 만들어 주지는 않는다.

## 현재 기록

자동 생성 파일은 [`examples/native_lh2dt_packet_coverage_ledger.json`](../examples/native_lh2dt_packet_coverage_ledger.json)이다. 생성 명령은 다음과 같다.

```powershell
$py = (Get-Item '../output/prism-export-v060-1febujhk/venv/Scripts/python.exe').FullName
& $py scripts/build_native_lh2dt_packet_coverage_ledger.py `
  --provider-worklist results/20261017/provider_worklist_with_scenario_families.json `
  --output examples/native_lh2dt_packet_coverage_ledger.json
```

2026-10-18 현재 장부에는 네이티브 출력 25건이 들어 있다. 이 중 24건은 선언된 24개 작업목록 이벤트와 정확히 맞고, 16건은 PRISM 피해영향 체인까지 이어졌다. 한 건은 문헌 빈도를 바인딩한 `LH2_PIPE AREA_100%` 진단이다.

| 설비 계열 | 저장된 패킷 | 피해 체인 연결 | 비고 |
|---|---:|---:|---|
| 저장탱크 | 5 | 5 | LayeredTank 액체 방출 |
| 이송 배관 | 6 | 3 | DynamicHEMPipe, 한 건은 압력 평형 종료와 문헌 빈도 연결 |
| 밸브 | 5 | 1 | Valve 액체/2상 진단 |
| 펌프 | 2 | 2 | MappedPump 진단 |
| 벤트 | 1 | 1 | VentStack 비상 방출 진단 |
| 기화기 | 3 | 3 | DynamicVaporizer 재고·기체 방출 |
| 재액화기 | 2 | 0 | 양단 방출 패킷만 보존 |
| 네이티브 탱크 smoke | 1 | 1 | 작업목록 밖의 별도 인터페이스 smoke |

각 행에는 이벤트 ID, 설비 ID, 포트, 개구 직경, 방출 시간, 종료 근거, 방출 질량, 질량 잔차, PRISM 체인 연결 여부, 주파수 바인딩 여부가 들어 있다. `synthetic_diagnostic_horizon`은 계산을 일정 시간에서 멈춘 기록이고, `inventory_depletion` 또는 `model_pressure_equalization`은 해당 네이티브 모델이 반환한 종료 근거다. 종료 근거가 있어도 차단밸브 신뢰도나 현장 운전조건을 대신하지 않는다.

## 장부를 읽는 방법

`NATIVE_PACKET_WITH_CONSEQUENCE_CHAIN`은 방출 패킷이 PRISM의 확산·화재·피해 계산 경계까지 들어갔다는 뜻이다. `NATIVE_PACKET_ONLY`는 패킷과 보존량은 확인됐지만 해당 행의 체인 실행 증거가 없다는 뜻이다. `frequency_bound`가 참인 행만 문헌 빈도가 명시적으로 연결된 진단이며, 빈도가 외부 모델에서 학습됐다는 뜻은 아니다.

장부의 정책 필드는 항상 다음을 확인한다.

- `provider_packet_promoted` = `false`
- `frequency_inference_performed` = `false`
- `facility_qra_claim` = `false`
- `physical_validation_claim` = `false`

따라서 이 장부가 PASS여도 시설 전체 IR/F-N을 열지 않는다. 현재 전체 감사의 남은 차단 사유는 실제 현장용 provider 패킷 부재, 일부 사고군의 미계산·운전자 제한 상태, 그리고 그에 따른 시설 전체 IR/F-N 보류다.

## IJHE 감사 연결

`scripts/build_ijhe_completion_audit.py`에 `--native-packet-coverage-ledger`를 주면 감사에 `diagnostic_native_lh2dt_packet_coverage` 검사가 추가된다. 이 검사는 작업목록 이벤트 수와 장부의 정확 일치 수를 비교하고, 패킷 승격·시설 QRA·물리검증 주장이 섞이지 않았는지 확인한다. 결과는 [`results/20261018/ijhe_completion_audit_with_native_packet_coverage.json`](../results/20261018/ijhe_completion_audit_with_native_packet_coverage.json)에서 확인할 수 있다.

이 연결이 닫는 것은 **설비 상태 → 네이티브 사고 방출 → PRISM 피해영향** 경계의 추적성이다. 닫지 않는 것은 현장 빈도 보정, 모든 개구율의 실제 종료 계산, 기상·점화·인구의 시설별 입력 검증, 독립 실험 검증이다.
