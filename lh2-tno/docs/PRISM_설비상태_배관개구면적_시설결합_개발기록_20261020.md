# PRISM 설비 상태→배관 방출→시설 위험 결합 기록 (2026-10-20)

## 이번 단계의 목적

기존 generic LH2 시설 캠페인에서 `liquid-transfer-line-01`의 다섯 개 누출 크기가 미계산으로 남아 있었다. 이번 단계에서는 액화수소 설비 모델이 계산한 대기 방출 경계를 각 개구면적에 하나씩 연결하고, 기존 시설 장부의 transfer-line 사건과 중복되지 않도록 교체 결합했다.

이 단계가 시설 전체 QRA를 완료했다는 뜻은 아니다. 설비 모델의 방출 결과를 PRISM의 방출→확산→점화→피해→IR/F-N 계산에 넣는 연결과 장부 회계를 보완한 것이다.

## 계산 흐름

```text
설비 상태/배관 경계
  → 설비 provider가 개구면적별 유량·압력·온도 계산
  → ResolvedGasRelease 방출 packet
  → SLABx-LH2/SLABx 및 PRISM 피해 계산
  → 두 기상 조건의 수용점 harm
  → 문헌 빈도로 재가중
  → 시설 ledger와 조건부 IR/F-N
```

각 개구면적은 별도 provider 계산으로 실행했다. 결과에는 provider 시간, 종료 근거, 질량·에너지 장부와 계산 case ID가 보존된다. PRISM은 설비 provider의 유량을 다시 계산하거나 센서 신호에서 누출 크기·빈도를 추정하지 않는다.

## 실행 범위와 결과

```powershell
python scripts/validate_equipment_campaign.py `
  --all-area-bins `
  --facility-id generic-lh2-full-scope-example `
  --common-receptor-id worker-01 `
  --component-id liquid-transfer-line-01 `
  --asset-id equipment-transfer-line_asset `
  --output-dir results/20261020/equipment_campaign_all_bins_transfer_line_replacement
```

이 설비 campaign은 `AREA_0.01%`, `AREA_0.1%`, `AREA_1%`, `AREA_10%`, `AREA_100%`의 다섯 사건을 만들고, 각 사건을 두 기상 조건에 연결했다. 따라서 5개 event, 10개 실행 case, 0개 미계산 case가 생성됐다.

시설 결합에서는 원래 generic campaign의 transfer-line 5개 event를 그대로 더하지 않고, 그 자리를 위의 설비 campaign으로 교체했다. 이 교체를 위해 파생 ledger `results/20261020/generic_campaign_without_transfer_line_for_replacement.json`을 만들었으며, 이는 기존 결과를 삭제하는 것이 아니라 장부 중복을 방지하는 재결합 입력이다.

최종 결합 결과는 다음과 같다.

| 항목 | 결과 |
| --- | ---: |
| 시설 event | 41 |
| 전체 case | 75 |
| 실행 risk atom | 280 |
| 미계산 case | 32 |
| 결합 campaign | 6 |
| 기대 설비 수 | 11 |
| `liquid-transfer-line-01` 상태 | `EXECUTED` |
| 시설 전체 IR/F-N | 보류 |

이전 all-bin 시설 장부의 미계산 case 37개에서 32개로 줄었다. 줄어든 5개는 transfer-line 개구면적 사건이며, 다른 탱크·펌프·밸브·양단파열·수직 handoff의 미계산 또는 operator-limited 항목은 그대로 보존했다.

## 빈도 적용

빈도는 provider가 만들지 않는다. 기존 PRISM 문헌 catalogue의 transfer-line 빈도를 유지하고, 다음 파일의 다섯 문헌 시나리오로 재가중한다.

- `examples/native_lh2_transfer_line_replacement_frequency_scenarios.json`
- `generic-lh2-published-central`
- `generic-lh2-literature-low`
- `generic-lh2-literature-high`
- `generic-lh2-independent-low`
- `generic-lh2-independent-high`

이번 계산은 현장 사고빈도나 센서 기반 학습 결과가 아니다. provider 계산이 끝났다는 사실도 빈도 검증이나 시설 QRA 자격을 만들어 주지 않는다.

## 현재 판정과 남은 차단

최신 시설 assessment는 `PARTIAL_FACILITY_SCOPE`이며, 조건부 진단 IR/F-N은 계산되지만 `facility_total_risk_available=false`이다. 자동 IJHE 감사는 `results/20261020/ijhe_completion_audit_transfer_line_replacement.json`에 기록되어 27개 검사를 수행하고 다음 세 가지 차단을 유지한다.

1. 실제 자격을 갖춘 사고 방출 provider packet이 없음
2. 주요 사고 family 중 일부가 `PARTIAL` 또는 미계산
3. 시설 전체 IR/F-N은 불완전·합성 범위 때문에 보류

독립 물리검증도 여전히 DynamicLH2PoolX의 제한된 구성요소 증거만 있으며, 전체 설비 방출부터 최종 피해까지의 검증은 아니다. 처리시간 기록도 여러 campaign의 계산 분포이며 1 Hz 실시간 성능을 입증하지 않는다.
