# PRISM 재고 방출·양단 파열 통합 기록 (2026-10-14)

이번 단계의 목표는 일반 액화수소 시설 작업목록에 선언된 사고 family를 설비 모델의 방출 packet으로 연결하는 것이었다. 대상은 현장 사고빈도 학습이 아니라, 문헌 빈도를 적용하기 전에 필요한 설비 경계와 방출 이력의 계약 연결이다.

## 재고 방출 adapter

파일은 `scripts/export_lh2dt_dynamic_vaporizer_inventory_prism_packet.py`와 `src/lh2_tno/equipment_accident_export.py`의 `InventoryReleaseExportRequest`이다.

* `instantaneous_inventory`는 provider가 `inventory_depletion`을 선언하고 대기압 평형에서 종료한다.
* `inventory_over_600s`는 정확히 600초의 provider history와 `inventory_over_600s` 종료근거를 요구한다.
* PRISM은 정상 `step()` 출력이나 센서 신호에서 누출 구경·지속시간·빈도를 역산하지 않는다.
* adapter 내부의 대기 밸브 면적은 계산에 필요한 진단 면적이며, resolved packet의 failure opening으로 승격하지 않는다.
* 구버전 합성 packet에 면적 필드가 남아 있으면 frequency binding은 그 값을 inventory 사건의 문헌 hole 구경으로 비교하지 않는다. 새 packet은 해당 필드를 `null`로 둔다.

검증 산출물은 다음과 같다.

* G1 저압·큰 진단 면적: `results/20261014/vaporizer_worklist_g1_lowmach/`
* G1 consequence chain: `results/20261014/vaporizer_worklist_g1_lowmach_chain/`
* G2 600초 packet: `results/20261014/vaporizer_worklist_g2/`
* G2 consequence chain: `results/20261014/vaporizer_worklist_g2_chain/`

G2 chain은 `END_TO_END_DIAGNOSTIC_EXECUTED`로 끝났고, provider mass residual은 `3.3881317890172014e-21 kg`이다. G1의 원래 고압·작은 면적 조합은 SLABx 저마하 경계를 넘어서 `resolved low-Mach gas exit scope exceeded`로 중단됐다. 저압·큰 진단 면적 조합으로 다시 계산한 G1은 chain을 통과했지만, 이는 압축성 출구 모델을 대신하는 것이 아니며 현장 조건을 의미하지 않는다.

## 양단 파열 adapter

`scripts/export_lh2dt_reliquefier_two_sided_prism_packet.py`는 한 개의 `DynamicReliquefier` finite-volume 상태에서 두 개의 명시적 `Valve` endpoint를 계산한다. 결과는 `prism.resolved_release_set.v1`로 저장하며, 두 endpoint가 다음을 공유하는지 검사한다.

* 같은 `event_id`와 component
* 같은 초기 재고와 provider duration
* 서로 다른 accident port
* 각 endpoint의 독립 방향·질량·엔탈피 이력

G4와 G5 packet은 `results/20261014/reliquefier_worklist_G4/`, `results/20261014/reliquefier_worklist_G5/`에 있고, catalog는 `results/20261014/structural_two_sided_provider_catalog.json`에 있다. 한 endpoint를 복사해 양단 파열로 만들지 않는다.

구조 loader와 request builder는 통과하지만 현재 consequence worker는 jet 방향을 바람에 맞춘 수평 handoff로만 허용한다. 두 endpoint 중 하나가 현재 바람 방향에 대해 상류가 되므로 `handoff remains upwind; no silent rotation into a downwind source`로 중단됐다. 이 제한을 우회해 방향을 바꾸거나 endpoint를 하나만 계산하지 않았다. 압축성/고마하 출구와 양방향 plume 상호작용을 추가한 뒤에야 G4/G5 피해 계산을 열 수 있다.

## 아직 완료로 표시하지 않는 항목

1. 24개 packet은 모두 합성 진단이고, 실제 적격 provider packet은 0건이다.
2. inventory G1/G2와 two-sided G4/G5는 모델 계약이 연결된 것이지, 모든 조건에서 피해 chain이 계산됐다는 뜻이 아니다.
3. 문헌 빈도는 작업목록에만 있으며 센서 기반 빈도 학습이나 현장 빈도 보정은 하지 않았다.
4. 기상·점화·인구·IR/F-N의 시설 전체 합산은 exact binding, barrier branch, 독립 물리검증, facility geometry가 모두 확인될 때까지 보류한다.
5. 실시간 처리 주장은 하지 않는다. G2 실행 시간과 기존 case timing은 diagnostic timing일 뿐 1 Hz fresh-physics SLA가 아니다.

전체 portable test는 `367 passed`이며, coverage gate와 packet chain은 위 결과 디렉터리에서 재현할 수 있다.
