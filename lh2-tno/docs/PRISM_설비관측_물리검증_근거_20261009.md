# PRISM 설비 관측자료와 물리검증 근거

이 기록은 액화수소 설비 모델의 관측자료를 PRISM 위험평가에 어떻게 사용할 수 있는지, 그리고 아직 사용할 수 없는 부분을 고정한다. 목적은 관측자료를 사고 방출 자료나 시설 전체 위험도로 잘못 바꾸지 않는 것이다.

dataset의 정책도 감사했다. 기본 fitting 금지, holdout 재학습 금지, component library 변경 금지, 관측 보간 금지가 모두 참이어야 통과한다. fit 날짜와 holdout 날짜가 겹치면 감사는 실패한다.

## 이 자료로 할 수 있는 일

현재 자료는 다음 작업의 근거로 사용할 수 있다.

1. 설비 모델이 어떤 관측 채널과 날짜를 읽었는지 기록한다.
2. fit 자료와 holdout 자료를 시간으로 분리했는지 확인한다.
3. 원시 자료를 받기 전에는 독립 검증 simulator를 실행하지 않았음을 증명한다.
4. 설비 topology가 아직 스크리닝 수준임을 PRISM 상태와 논문 방법에 표시한다.
5. 향후 원시 historian/DCS/PLC export가 도착했을 때 같은 감사 명령을 다시 실행할 기준을 제공한다.

## 아직 할 수 없는 일

이 관측자료만으로 다음 값을 만들거나 추정하지 않는다.

- 누출 구멍 크기, 방출 유량, 방출 지속시간
- 차단 성공확률, 재고 소진 이력, 액체·2상 flash/지상액체/비산액적 분할
- 사고 발생 빈도 또는 센서 신호에서 빈도로의 역추정
- SLABx-LH2 대기확산·점화·복사열 결과의 독립 검증
- 시설 전체 IR/F-N 또는 연간 위험

정상 유량 JSON, 센서 시계열 후보, 스크리닝 topology는 `ResolvedGasRelease`·`ResolvedLiquidRelease` provider packet이 아니다. 따라서 provider의 명시적인 사고 경계·종료 근거·질량/엔탈피 장부가 없는 자료는 사고 campaign으로 승격하지 않는다.

## PRISM 상태에 반영한 안전장치

`CURRENT_STATUS.json`과 `DEVELOPMENT_GOAL.json`에 감사 구현 여부, 4/2/2 case 분할, 21행·34채널, 8개 독립 시나리오, 방출 공개 0건, simulator 호출 0건, SHA-256을 기록했다. `physical_validation_claim`, `full_chain_claim`, `accident_release_claim`, `frequency_inference`는 모두 `false`로 유지한다.

이 기록은 IJHE용 방법·한계 표에 넣을 수 있는 근거 장부다. 독립 원시자료와 사고 방출 packet이 추가되기 전까지 PRISM의 시설 전체 위험 판정은 계속 `INCOMPLETE_EVIDENCE`로 남는다.
