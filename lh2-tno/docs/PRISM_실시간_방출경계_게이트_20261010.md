# PRISM 실시간 방출경계 게이트

실시간 모니터는 센서 상태를 곧바로 누출 크기나 빈도로 바꾸지 않는다. 외부 LH2
설비 모델이 계산한 `ResolvedGasRelease`·`ResolvedLiquidRelease`·양단 방출 경계를
받은 경우에만 피해 계산을 실행한다. 이번 게이트는 그 방출 경계가 시설 배치의
모든 설비에 연결됐고, 종료·차단·재고 장부가 닫혔는지를 별도로 보여준다.

## 판정 규칙

`FacilityRealtimeConsequenceMonitor`는 한 batch마다
`aggregate.equipment_release_path_accounting.strict_release_boundary`를 만든다.

- 모든 선언 설비의 frame과 provider 방출 경계가 있어야 한다.
- 종료근거는 `reviewed_isolation_success` 또는 `inventory_depletion`이어야 한다.
- 진단용 `synthetic_diagnostic_horizon`, 600초 절단, 자연 종료, 비상 릴리프,
  양단 파열은 연결 결과가 있어도 이 게이트를 통과시키지 않는다. 별도의 물리·운영
  검토가 필요하기 때문이다.
- 차단/재고 상태는 `ISOLATION_SUCCESS_DECLARED` 또는
  `INVENTORY_TERMINATION`이어야 한다.
- 재고 소진 사건은 질량 잔차가 `1e-8 kg` 이하이어야 한다. 차단 성공 사건은
  남은 재고가 있을 수 있으므로, 음수 잔차만 거부한다.

게이트가 통과하면 `strict_release_boundary_ready=true`가 되지만, 이것은 방출
경계의 구조적 완결성만 뜻한다. provider 자격화, SLABx-LH2 독립 물리검증, 문헌
빈도 검토, 연간 기상·인구·점화 branch, 시설 IR/F-N 승격은 별도 게이트로 남는다.
따라서 출력에는 항상 다음을 함께 기록한다.

```json
{
  "strict_release_boundary_ready": false,
  "blocking_reasons": ["storage-tank-01: synthetic diagnostic horizon remains"],
  "provider_qualification_evaluated": false,
  "independent_physical_validation_claim": false,
  "facility_ir_fn_promotion": false,
  "frequency_inference_performed": false
}
```

## 테스트 의미

합성 provider가 `synthetic_diagnostic_horizon`을 사용하면 방출→피해 계산은
성공해도 게이트는 보류된다. 같은 provider 결과라도 종료근거를 검토된 차단성공으로
명시하고 질량잔차가 유효하면 방출경계 게이트만 통과한다. 두 경우 모두 빈도를
센서에서 학습하지 않으며, 시설 QRA 결과로 자동 승격하지 않는다.

관련 구현과 검증은
`src/lh2_tno/service.py`의
`_strict_realtime_release_boundary_gate` 및
`tests/test_consequence_service.py`에 있다.
