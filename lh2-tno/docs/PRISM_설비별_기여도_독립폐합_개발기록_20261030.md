# PRISM 설비별 기여도 독립 폐합 개발 기록

## 목적

시설 위험도는 여러 설비의 결과를 더해서 만든다. 따라서 시설 전체 IR/F-N만 맞는지 확인하면 한 설비의 결과가 다른 설비로 잘못 들어간 문제를 놓칠 수 있다. 이번 감사는 저장된 risk atom을 `provider_packet_identity.component_id`로 다시 묶어 설비별 결합을 독립적으로 재현한다.

## 계산 방법

각 risk atom에 대해 다음 값을 사용한다.

```text
설비 IR = initiating_frequency_per_year
         × conditional_weight
         × receptor_harm
```

같은 설비에 속한 원자의 값을 합쳐 설비별 low/high IR을 만들고, `N ≥ 1` 규칙으로 설비별 F/N 곡선을 다시 만든다. 사건 수는 고유 `event_id`를 세고, risk atom 수는 원자 행을 센다. 마지막으로 high-endpoint IR을 기준으로 설비 순위를 다시 계산하고 기존 `component_contributions`와 `component_risk_ranking`을 비교한다.

이 과정에서 빈도를 다른 설비로 옮기지 않는다. 설비별 숫자가 0이어도 원자와 사건이 없다는 뜻으로 바꾸지 않으며, provider packet이나 물리 검증을 새로 만들어 내지 않는다.

## 현재 결과

권위 union 원장 `results/20261026/native_full_scope_union_assessment/`에서 다음을 확인했다.

- 34개 사건, 44개 case, 176개 risk atom
- 9개 설비 component가 원자에 실제로 연결됨
- 설비별 IR/F-N 표 재계산 불일치 0건
- 설비 순위 재계산 불일치 0건
- 빈도 재할당 0건
- 상태: `FACILITY_COMPONENT_CONTRIBUTIONS_CLOSED_DIAGNOSTIC`

이 결과는 “설비별 결과가 시설 조건부 장부에 어떻게 합쳐졌는가”를 닫은 것이다. 29개 operator-limited case, 실제 qualified provider packet 0개, 부분 사고범위, 시설 전체 QRA 보류에는 영향을 주지 않는다.

## 실행과 연결

독립 감사 구현은 `src/lh2_tno/facility_component_contribution_audit.py`에 있다. union 실행기는 `facility_component_contribution_audit.json`을 만들고, IJHE 완료 감사에는 `diagnostic_facility_component_contribution_closure` 검사를 추가한다. v0.6.0 readiness report의 `chain.facility_component_contribution_closure`에도 상태와 불일치 수가 남는다.

재현 명령의 핵심은 다음과 같다.

```powershell
python scripts/run_native_full_scope_union_assessment.py ...
python scripts/build_ijhe_completion_audit.py ... `
  --facility-component-contribution-audit `
  results/20261026/native_full_scope_union_assessment/facility_component_contribution_audit.json
python scripts/build_v060_readiness_report.py ... `
  --facility-component-contribution-audit `
  results/20261026/native_full_scope_union_assessment/facility_component_contribution_audit.json
```

단위 검증은 `tests/test_facility_component_contribution_audit.py`에 있으며, 전체 portable suite에서 통과해야 한다.
