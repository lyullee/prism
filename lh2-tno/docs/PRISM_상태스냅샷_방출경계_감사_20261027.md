# PRISM 상태 스냅샷→방출 경계 감사 (2026-10-27)

이번 보완의 목적은 “설비 공정 상태를 사고 방출 계산에 실제로 전달했는가”를 digest 문구만으로 판단하지 않는 것이다. PRISM은 정상 상태와 사고 시나리오를 분리한다. 상태에는 압력·온도·재고·상·위치와 정규화된 측정값만 들어가며, 누출 구경·지속시간·빈도·종료시각·resolved release는 들어갈 수 없다.

## 판정 규칙

`BOUND_AND_ECHOED`는 다음 세 가지를 모두 만족할 때만 부여한다.

1. 요청 또는 검증 기록에 `prism.equipment_state_snapshot.v1` 원문이 있다.
2. 원문을 다시 읽어 계산한 SHA-256이 `state_snapshot_digest`와 같다.
3. 외부 provider가 같은 digest를 `provider_state_snapshot_digest`로 echo한다.

digest만 있거나 provider가 “일치했다”고 표시한 것만 있는 경우는 `DECLARED_DIGEST_ONLY`로 남긴다. 원문이 없으면 계산 상태를 재현할 수 없기 때문이다. 원문과 digest가 다르면 `DIGEST_MISMATCH`로 차단한다.

기존 union campaign 파일에는 canonical 상태 원문이 보존되지 않은 시점이 있었지만, 현재 state-bound native campaign을 다시 결합해 기본 24개 사건 모두 `BOUND_AND_ECHOED`로 확인했다. 수직 handoff 5개와 inventory depletion 5개도 provider 입력에서 만든 상태 snapshot과 echo digest를 각 case identity에 보존해 확장 coverage 10/10 `BOUND_AND_ECHOED`가 되었다. 따라서 현재 34개 union 사건의 strict 상태 snapshot gate는 `PASS`다. 이 결과는 합성 model-prediction 입력의 연결을 확인한 것이며, 현장 상태 정확도·qualified provider·시설 QRA를 뜻하지 않는다.

대표 DynamicHEMPipe 기록은 다음을 함께 보존한다.

- 초기 압력 `500,000 Pa`, 온도 `27 K`, 2상 상태
- 위치 `[5, 0, 1] m`
- 초기 품질 `0.1`
- provider digest echo 일치
- provider 자연 종료 `model_pressure_equalization`
- 최종 압력 대기압 일치, 질량 잔차 `0 kg`
- 상태→방출→SLABx-LH2/SLABx→점화·피해 chain 실행

이 사례는 합성 1 m 배관과 합성 초기상태를 사용한 진단이다. 따라서 provider 적격성, 현장 빈도, 독립 물리검증, 시설 전체 IR/F-N을 열지 않는다.

## IJHE 감사 반영

`bind_native_full_scope_union_evidence.py --state-snapshot-binding-audit ...`로 union 감사에 `diagnostic_equipment_state_snapshot_binding` 검사를 추가했다. 최신 fail-closed 감사는 29개 검사 중 26개 PASS·3개 BLOCKED인 `INCOMPLETE_EVIDENCE`다. 기본 native 24개와 확장 10개를 합친 34개 사건의 상태 snapshot gate는 `PASS`이며, 남은 3개 blocker는 qualified provider packet·엄격한 사고범위·시설 전체 QRA다. 독립 물리검증은 제한된 SLABx-LH2 구성요소 증거가 PASS로 기록됐지만, 전체 시설 독립 검증 gate는 readiness 원장에서 별도로 계속 열려 있다.

향후 실제 설비 모델을 연결할 때는 각 설비·사건 요청에 동일한 snapshot 객체를 넣고, provider 응답에 echo digest를 남겨야 한다. 이 장부는 상태 전달만 검증하며 빈도나 피해 결과를 상태값에서 역산하지 않는다.
