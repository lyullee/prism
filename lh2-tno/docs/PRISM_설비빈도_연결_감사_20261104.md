# PRISM 설비별 문헌 빈도 연결 감사 (2026-11-04)

## 빈도를 어디에 적용하는가

PRISM에서 빈도는 “센서가 이상하다고 말한 횟수”가 아니다. 검토된 문헌 카탈로그의 사고 시작률을 확정된 설비와 사고 family에 붙이는 값이다.

```text
문헌 빈도 카탈로그
        ↓
확정된 asset ID·P&ID component kind
        ↓
사고 family와 release mode
        ↓
provider 방출 packet
        ↓
SLABx-LH2 확산·점화·IR/F-N
```

이 순서를 지키면 빈도와 피해 계산을 섞지 않는다. 빈도가 있어도 provider 방출 packet이 없으면 피해 결과는 계산하지 않는다.

## 이번 감사 결과

결과 파일은 [`equipment_frequency_binding_audit_current.json`](../results/20261104/equipment_frequency_binding_audit_current.json)이다.

| 항목 | 결과 |
|---|---:|
| 확정 설비 identity | 0 |
| 입력된 문헌 frequency event | 0 |
| 유효하게 연결된 frequency event | 0 |
| 미계산 사고 family | 12 |
| 빈도 추론 허용 | 아니오 |
| provider 방출 packet 요구 | 예 |
| 시설 QRA 허용 | 아니오 |

상태 `FREQUENCY_BINDING_WITHHELD`는 빈도 코드가 없다는 뜻이 아니다. 현재 외부 설비 자료에는 일반 시설용 asset/P&ID crosswalk가 없으므로 빈도를 붙일 대상이 아직 확정되지 않았다는 뜻이다. 미확정 설비에 0을 넣어 누락을 숨기지 않는다.

감사기는 후보 asset, 중복 event ID, 존재하지 않는 asset, 잘못된 provenance event를 사고 family에 귀속하지 않는다. 이런 행은 사건 자체와 family의 `frequency_bound`를 모두 차단하고 미계산 목록에 남긴다. 따라서 사건 배열에 숫자가 들어왔다는 사실만으로 family 빈도가 열린 것으로 표시되지 않는다.

## 문헌 빈도와 불확실성

실제 frequency event가 들어오면 다음 항목을 함께 보존한다.

* profile과 사고 family
* 연간 발생률과 단위
* 문헌 source와 source SHA-256
* hole, inventory depletion, 600 s, two-sided rupture 같은 release mode
* 문헌의 p05/p95 또는 lognormal 정보
* 문헌 빈도가 현장 검증값이 아니라는 limitation

문헌 p05/p95는 시설 전체의 신뢰구간으로 자동 합산하지 않는다. 설비 간 상관관계가 확인되지 않았기 때문이다. 현장 사고빈도 수집과 센서 기반 빈도 학습도 이 경로에 들어오지 않는다.

## 방출 packet과의 관계

빈도 event가 연결되더라도 다음 자료가 없으면 `facility_qra_allowed=false`로 남는다.

1. provider가 계산한 실제 사고 방출 이력
2. 시작시각과 종료 또는 차단시각
3. 차단 성공/실패와 잔류 재고
4. 전량 소진 또는 600초 제한의 명시적 종료 근거
5. 출구 열역학 상태와 질량수지

따라서 빈도는 “사고가 시작될 가능성”을 나타내고, 방출 packet은 “그 사고가 얼마나 오래·얼마나 많이 나왔는지”를 나타낸다. 둘 중 하나만으로 최종 피해를 만들지 않는다.

## 재현 명령

```powershell
python scripts/build_equipment_frequency_binding_audit.py `
  --equipment-scenario-coverage results/20261104/equipment_scenario_coverage_audit_current.json `
  --output results/20261104/equipment_frequency_binding_audit_current.json
```

문헌 provenance 원장이 준비되면 `--frequency-provenance`를 추가한다. 아직 crosswalk가 없거나 event가 없는 상태에서도 명령은 성공하며, 결과를 `FREQUENCY_BINDING_WITHHELD`와 미계산 family 목록으로 남긴다.

## IJHE 목표 감사 연결

최신 IJHE 원장에는 `diagnostic_equipment_frequency_binding` 행이 추가됐다.

* 전체 상태: `CONDITIONAL_DIAGNOSTIC_COMPLETE_STRICT_GATES_OPEN`
* 검사 수: 21개
* 핵심 연결 차단: 0개
* 엄격 승격 차단: 4개
* 빈도 연결 진단: `PASS` (현재 빈도를 억지로 연결하지 않았다는 정책 검증)

`PASS`는 12개 사고 family의 시설 빈도·피해 계산이 끝났다는 의미가 아니다. 문헌 event가 확정 설비에 연결되는 순간에도 provider 방출 packet 검증이 끝날 때까지 최종 피해와 시설 QRA는 닫혀 있어야 한다.
