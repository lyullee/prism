# PRISM 상태 장부 일관성 감사

## 목적

IJHE 준비 결과는 완료 감사, 시설 평가, 증거 요청서, 병합 시설 원장,
case coverage 보고서, 두 개의 상태 장부가 서로 같은 실행을 가리키고 완료 감사의 통합 체인 검사까지 통과할 때만
읽을 수 있다. 이 감사기는 이 파일들의 숫자와 포인터를 비교한다. 계산 결과를
새로 만들거나, 빈도를 추정하거나, 시설 IR/F-N을 승격하지 않는다.

## 실행

```powershell
python scripts/audit_status_consistency.py `
  --current-status CURRENT_STATUS.json `
  --development-goal DEVELOPMENT_GOAL.json `
  --audit results/20261024/ijhe_completion_audit_native_generic_scope_vertical_v16.json `
  --assessment results/20261024/native_generic_scope_vertical_merged_facility_assessment_population_v6.json `
  --evidence-request results/20261024/native_generic_scope_vertical_facility_evidence_request_v2.json `
  --ledger results/20261024/native_generic_scope_vertical_merged_facility_ledger_population_v3.json `
  --coverage results/20261024/native_generic_scope_vertical_case_packet_coverage_v1.json `
  --output results/20261024/ijhe_status_consistency_v7.json
```

현재 결과는 [`ijhe_status_consistency_v7.json`](../results/20261024/ijhe_status_consistency_v7.json)의
`CONSISTENT`이다. 20개 검사가 모두 통과했고, 감사 v16의 34개 검사·4개
차단, 29개 event·34개 조건부 case·136개 risk atom, 34개 요청 case와
qualified provider 0개가 서로 일치한다. 조건부 수치 계산과 엄격한 증거
충족을 구분하며, combined-chain·SLABx-LH2 검증근거·exact-cache realtime benchmark·domain-recovery gate를 확인한다. exact-cache는 20/20회, 중앙 31.47 ms, p95 33.23 ms로 1 Hz 진단을 통과하지만 fresh physics 2,685.50 ms에는 1 Hz 주장을 하지 않는다. SLABx-LH2와 realtime benchmark는 각각 피해영향 구성요소와 처리시간 진단 범위만 확인하므로 `facility_ir_fn_promotion`은 계속 `false`다.

JSON 중복 키도 입력 오류로 처리한다. 따라서 같은 상태 파일 안에 과거의
검사 수와 최신 검사 수가 동시에 들어가 최신 값이 가려지는 문제를 조기에
잡을 수 있다.
