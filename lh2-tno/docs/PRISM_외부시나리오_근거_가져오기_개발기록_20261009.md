# PRISM 외부 LH2 시나리오 근거 가져오기 기록

## 목적

액화수소검사지원센터의 운전순서 CSV를 PRISM이 참고할 수 있는 형태로 읽는다. 이 자료를 특정 센터 전용 모델로 고정하지 않고, 일반적인 옥외 액화수소시설에서 검토할 수 있는 사고 가족과 감시 신호의 후보를 찾는 데 사용한다.

실행 명령은 다음과 같다.

```powershell
.venv\Scripts\python.exe scripts/import_scenario_evidence.py `
  --root "C:\Users\lyul\Desktop\DocuData\액화수소검사지원센터 데이터" `
  --output results/20261009/inspection_center_scenario_evidence.json
```

## 이번 가져오기 결과

실제 자료에서 CSV 3개, 52개 행을 읽었다.

- 옥외 후보로 남긴 행: 41개
- 시험동·건물·밀폐 맥락으로 옥외 범위 밖에 둔 행: 11개
- 후보 사고 가족: `pipe_hole`, `valve_hole`, `vessel_hole`, `vent_hole`, `vaporizer_hole`, `inventory_over_600s`, `vertical_handoff`
- 후보 감시 신호: 압력, 온도, 유량, 밸브 상태, 수소 검지, 릴리프 상태, 환기 상태, 진공, 기밀시험

각 원본 파일에는 SHA-256 해시와 상대 경로가 기록된다. 각 행도 `파일:행번호` ID를 갖기 때문에 나중에 어떤 근거에서 후보가 나왔는지 다시 확인할 수 있다.

## PRISM 계산으로 승격하지 않는 것

운전 절차의 위험성 분류는 사고 발생 빈도가 아니다. 따라서 가져오기 결과에는 다음 값이 항상 명시적으로 `false`이다.

- 문헌 또는 현장 빈도 적용
- 센서 신호로 빈도 학습
- 설비 사고방출 provider packet 생성
- 시설 IR/F-N 위험도 주장

후보 가족 맵은 “이 절차를 보면 이 사고 유형을 검토할 수 있다”는 검색용 표이다. 실제 위험 계산에는 설비가 내보낸 사고 전용 이력, 개구와 포트, 종료 근거, 질량·에너지 장부를 갖춘 `prism.external_accident_history.v1` 또는 `prism.resolved_release.v1` packet이 별도로 필요하다. 후보 행만으로 문헌 빈도를 자동으로 만들거나 정상 운전 결과를 사고 방출로 바꾸지 않는다.

## 범용 시설 적용 방식

입력 경로가 바뀌면 같은 importer로 다른 옥외 LH2 시설의 CSV도 읽을 수 있다. 코드에는 검사센터 탱크 번호나 P&ID 태그를 필수값으로 넣지 않았다. 설비 연결은 이후 `EquipmentManifest`와 실제 provider 사고 export에서 수행한다.

`시험동`, `건물`, `밀폐`, `반밀폐`, `indoor`, `enclosed`가 포함된 행은 근거로 보존하지만 현재 선언한 옥외 범위의 실행 후보에서는 제외한다. 실내 확산·폭굉·도미노를 이 importer가 계산한다고 해석하면 안 된다.

## IJHE 감사 연결

`build_ijhe_completion_audit.py --scenario-evidence-report ...`를 사용하면 감사 결과에 `external_scenario_evidence_import`라는 진단 전용 check가 추가된다. 이 check가 통과해도 전체 시설 QRA 완료를 의미하지 않는다. 다음 네 가지 제한은 그대로 남는다.

1. 외부 `lh2dt` 7개 설비 클래스의 native `export_accident_history(request)`가 아직 없다.
2. 현재 provider 방출은 합성 또는 screening 결과라 적격 현장 packet이 아니다.
3. 선언된 사고 가족 중 일부는 provider 이력 또는 수직 handoff가 없어 미계산이다.
4. 전체 시설 IR/F-N은 완전한 사고 범위와 독립 검증이 확보될 때까지 보류된다.

이 기록의 핵심은 센터 자료를 버리지 않고 추적 가능한 일반형 후보 근거로 저장하되, 빈도와 최종 위험도를 임의로 만들어 내지 않는 것이다.
