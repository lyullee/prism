# PRISM reconstructed inspection-centre state connection (2026-10-16)

The original training/recovery workbooks were connected as a separate,
state-only demonstration. They are not mixed with the prediction-data
manifest and are not labelled as independent historian measurements.

## Input and classification

[`examples/inspection_center_reconstructed_state_manifest.json`](../examples/inspection_center_reconstructed_state_manifest.json)
selects one source sheet from each operating family:

| Source | PRISM component | Origin |
| --- | --- | --- |
| 2026-01-21 receiving workbook | reconstructed intake tank | `reconstructed` |
| 2026-01-24 storage workbook | reconstructed storage vent | `reconstructed` |
| 2026-04-15 supply workbook | reconstructed supply/vaporizer boundary | `reconstructed` |

The source workbooks explicitly describe graph restoration, video reading, or
training/recovery data. Therefore `reconstructed` is the conservative origin;
the adapter does not call these rows independent field measurements.

## Reproducible result

```powershell
python scripts/audit_observed_equipment_state.py `
  --manifest examples/inspection_center_reconstructed_state_manifest.json `
  --output examples/inspection_center_reconstructed_state_evidence.json
```

The result is `OBSERVATION_STATE_EVIDENCE_ONLY`:

- 3 sources and 3 reconstructed components
- 8,201 normalized state samples
- canonical snapshot schema: `prism.equipment_state_snapshot.v1`
- all samples retain origin `reconstructed`

The selected headers use explicit MPa/℃ labels. Differential-pressure columns
were omitted from this manifest because their unit is still unresolved. The
manifest also keeps pressure basis, calibration/quality, equipment identity,
and operating-mode binding as separate review gates.

## Boundary

This connection proves that reconstructed process rows can be normalized into
PRISM state snapshots. The state frame itself does not create an accident
release, release duration, isolation outcome, inventory depletion, frequency,
provider packet, or facility IR/F-N. A qualified equipment resolver and the
explicit operating mode input are still required before a state frame can
request a consequence calculation.

## Runtime mode and HAZOP handoff

The same three reconstructed sources were then passed through the runtime
frame builder with an explicit mode map:

```powershell
python scripts/build_observed_state_runtime_frames.py `
  --manifest examples/inspection_center_reconstructed_state_manifest.json `
  --source-root "C:\Users\lyul\Desktop\DocuData\액화수소검사지원센터 데이터" `
  --operating-mode-map examples/inspection_center_reconstructed_runtime_operating_modes.json `
  --output examples/inspection_center_reconstructed_runtime_frames.json

python scripts/audit_observed_hazop_runtime.py `
  --runtime-frames examples/inspection_center_reconstructed_runtime_frames.json `
  --hazop-table-set examples/inspection_center_hazop_runtime_tables.json `
  --now-s 43200 `
  --output examples/inspection_center_reconstructed_hazop_runtime_audit.json
```

The runtime result contains three frames with explicit `receiving`, `standby`,
and `supply` modes. The HAZOP audit selected one diagnostic supply-mode
`vaporizer_hole` scenario; the receiving and standby frames were below their
diagnostic thresholds and were recorded as `NO_DEVIATION`. The selected row
has `provider_release_required=true` and does not assign a frequency at the
HAZOP-selection boundary. This demonstrates the state → mode → HAZOP gate
without turning a reconstructed normal-state value into a leak or frequency.

## Diagnostic downstream chain for the selected scenario

The selected supply-mode row was then checked against one explicit generic
literature event and its existing model-prediction packet:

```powershell
python scripts/audit_observed_hazop_provider_binding.py `
  --observed-hazop-runtime-audit examples/inspection_center_reconstructed_hazop_runtime_audit.json `
  --provider-worklist results/20261110/native_full_scope_frequency_assessment_latest2/provider_worklist.json `
  --binding-map examples/inspection_center_reconstructed_hazop_provider_event_bindings.json `
  --output examples/inspection_center_reconstructed_hazop_provider_event_binding.json

python scripts/run_observed_hazop_provider_consequence_chain.py `
  --observed-hazop-runtime-audit examples/inspection_center_reconstructed_hazop_runtime_audit.json `
  --observed-hazop-provider-binding examples/inspection_center_reconstructed_hazop_provider_event_binding.json `
  --runtime-frames examples/inspection_center_reconstructed_runtime_frames.json `
  --provider-worklist results/20261110/native_full_scope_frequency_assessment_latest2/provider_worklist.json `
  --packet-evidence results/20261110/observed_hazop_storage_vaporizer_isolation_overlay/packet_evidence.json `
  --packet-root results/20261110/native_generic_scope_packets_latest2 `
  --manifest examples/generic_lh2_full_scope_manifest.json `
  --frequency-plan results/20261110/native_full_scope_frequency_assessment_latest2/frequency_plan.json `
  --provider-defaults-liquid examples/provider_request_defaults_liquid.json `
  --provider-defaults-relief examples/provider_emergency_relief_defaults.json `
  --template examples/equipment_consequence_template.json `
  --backend-config results/20261008/full_chain/backend_config.json `
  --now-s 43200 `
  --output examples/inspection_center_reconstructed_hazop_provider_consequence_chain.json
```

The identity audit bound 1/1 selected scenario to the generic
`ambient-vaporizer/G3` event. The chain executed one diagnostic provider
packet through the existing consequence service and current-weather IR
interface, producing one diagnostic risk atom in about 1.52 s. The packet is
marked `model_prediction` and `UNQUALIFIED_DIAGNOSTIC`; the geometry is a
diagnostic rebase to the provider exit, not reconstructed facility geometry.
The literature frequency is applied only after the explicit event binding and
is not learned from the sensor frame. The result therefore demonstrates
`state → explicit mode → HAZOP → provider packet → SLABx-LH2/TNO consequence →
conditional risk atom`, while facility IR/F-N promotion remains false. The
stored consequence payload reports
`END_TO_END_DIAGNOSTIC_EXECUTED` and retains the stages for equipment-resolved
gas exit, SLABx dispersion, ignition branches, radiation, blast zones, human
damage, and conditional risk. Its limitations remain attached to the payload;
this is a diagnostic model-prediction path rather than a qualified facility
result.

The machine-readable chain audit can be reproduced with:

```powershell
python scripts/audit_reconstructed_hazop_chain.py `
  --runtime-audit examples/inspection_center_reconstructed_hazop_runtime_audit.json `
  --provider-binding examples/inspection_center_reconstructed_hazop_provider_event_binding.json `
  --chain examples/inspection_center_reconstructed_hazop_provider_consequence_chain.json `
  --output examples/inspection_center_reconstructed_hazop_chain_audit.json
```

The audit reports `RECONSTRUCTED_DIAGNOSTIC_CHAIN_VERIFIED` with five checks.
It deliberately fails if the artifact claims provider qualification or facility
QRA promotion.
