# PRISM 외부 액화수소 설비 모델 준비도 감사 (2026-11-04)

## 목적

`액화수소 저장탱크_밴트 시스템` 프로젝트에서 만든 설비 디지털 트윈 입력을 PRISM의 일반 액화수소 시설 위험분석 흐름에 연결할 수 있는지 확인했다. 이 감사는 특정 검사센터를 그대로 복사하는 기능이 아니다. 외부 프로젝트에서 얻은 상태모델 입력과, 사고가 실제로 언제 시작되고 언제 끝났는지를 확인하는 방출 입력을 분리한다.

핵심 원칙은 다음과 같다.

* 탱크 형상과 상태모델 입력이 준비된 설비는 PRISM 입력 후보로 기록한다.
* 작업절차의 밸브 조작 의도는 사고 누출의 실제 시작시각·종료시각·차단상태가 아니다.
* 재구성한 시계열은 raw historian/DCS/PLC 원자료가 아니다.
* 위 자료가 없으면 SLABx-LH2 피해 계산을 실행할 수 있는 일반적인 계산 구조와 별개로, 해당 설비의 사고 방출·빈도·시설 전체 QRA를 승격하지 않는다.

## 확인한 자료

감사 입력은 다음 네 개의 원장이다.

1. `center_assets.json`: 외부 프로젝트의 설비 목록과 모델 유형
2. `center_tank_private_evidenced_inputs_audit.json`: 탱크 상태모델 입력 준비도
3. `center_connection_event_register_20261007.json`: 연결·밸브 이벤트와 물리시간/배관경로 상태
4. `center_observation_evidence_judgements.json`: 관측자료의 원자료·재구성·시간정렬·정확도 판단

원본 파일 경로와 SHA-256은 결과 JSON의 `sources`에 보존했다. 외부 자료가 바뀌면 다음 실행에서 해시가 달라져 어떤 입력을 사용했는지 다시 확인할 수 있다.

## 현재 결과

결과 파일은 [`external_equipment_model_audit_current.json`](../results/20261104/external_equipment_model_audit_current.json)이다.

| 항목 | 결과 | 의미 |
|---|---:|---|
| 외부 설비 수 | 12 | 탱크·기화기·재액화기·밸브·배관 카탈로그를 포함한다 |
| 상태모델 입력 준비 설비 | 2 | TK-1101, TK-1102가 현재 입력 후보이다 |
| 밸브 이벤트 | 36 | 절차/연결 이벤트 기록이며 사고 누출 사건 수가 아니다 |
| 물리시간이 배정된 이벤트 | 0 | 실제 시작·종료 시각이 없다 |
| event feedback channel | 0 | 밸브 명령이 실제 설비 응답과 연결되지 않았다 |
| raw historian 세션 | 0 | 검증된 DCS/PLC 원자료가 없다 |
| 재구성 세션 | 20 | 화면·문서 기반 재구성 자료이며 최종 정확도 자료가 아니다 |
| 설치 배관 실제 길이 | 미확정 | P&ID 도식 길이만으로 방출 재고를 계산하지 않는다 |
| 사고 방출 packet 승격 | 불허 | 시작·종료·차단·재고·질량수지 packet이 없다 |
| 빈도 추론 | 불허 | 센서나 절차 이벤트로 빈도를 거꾸로 추정하지 않는다 |
| 시설 QRA | 불허 | 설비 입력 준비도만으로 시설 전체 위험도를 만들지 않는다 |

따라서 감사 상태는 `STATE_MODEL_INPUTS_READY_RELEASE_BOUNDARY_UNVERIFIED`이다. 쉽게 말하면 “탱크 모델에 넣을 재료는 일부 준비됐지만, 누출 사고를 재현할 시간표와 방출 경계는 아직 확인되지 않았다”는 뜻이다.

## PRISM 연결 방식

이 원장은 IJHE 목표 감사의 `diagnostic_external_equipment_model_readiness` 진단 행으로 연결된다. 새 진단 행은 계산을 통과했다는 뜻이 아니라, 외부 모델을 어디까지 사용할 수 있는지 기록하는 장부다.

최신 IJHE 결과는 [`ijhe_objective_coverage_audit_with_external_equipment_model.json`](../results/20261104/ijhe_objective_coverage_audit_with_external_equipment_model.json)이다.

* 전체 상태: `CONDITIONAL_DIAGNOSTIC_COMPLETE_STRICT_GATES_OPEN`
* 핵심 연결 차단: 0개
* 엄격 승격 차단: 4개
* 외부 설비 준비도 진단: `PASS`
* 물리검증·qualified provider·시설 전체 QRA 승격: 여전히 닫힘

핵심 연결 차단이 0개라는 것은 기존의 합성/진단 경로에서 상태 snapshot → native 방출 → SLABx-LH2 → 조건부 피해·IR/F-N 계산 연결이 유지된다는 뜻이다. 외부 탱크 모델이 그 결과를 자동으로 실증 검증하거나 사고 빈도를 만들어 주는 것은 아니다.

## 다음에 받아야 할 자료

1. 일반 시설에서도 재사용할 수 있도록 설비 ID·P&ID port·밸브 ID crosswalk
2. DCS/PLC/raw historian 원본, 단위·스케일·교정표, 명령 timestamp
3. 사고 방출 packet: 개구 크기, 시작·종료, 차단 지연, 양단 파열 여부, 탱크 재고, 질량수지
4. 방출 경계에 대한 독립 holdout 비교자료

이 자료가 들어오기 전에는 TK-1101/TK-1102 상태모델을 “입력 후보”로만 사용한다. 자료가 들어오면 먼저 상태 snapshot을 검증하고, 다음으로 방출 packet과 SLABx-LH2 결과를 독립 검증한 뒤, 마지막으로 문헌 빈도와 시설 위험 계산에 연결한다.
