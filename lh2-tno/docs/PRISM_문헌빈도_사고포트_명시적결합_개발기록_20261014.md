# PRISM 문헌 빈도와 LH2 사고 포트의 명시적 결합

## 이번 보완의 목적

문헌 빈도는 “어떤 설비에서 사고가 시작될 가능성이 얼마나 되는가”를 말하고, 설비 모델은 “그 사고가 실제로 어느 방출구로 나가는가”를 계산합니다. 두 정보가 설비 이름만으로 연결되면 탱크의 정상 출구와 사고 출구가 섞이거나, 한 장치의 여러 방출구가 임의로 합쳐질 수 있습니다. 이번 보완에서는 이 연결을 별도의 검토된 crosswalk 파일로 고정했습니다.

포트는 센서값, provider packet, event 문자열에서 추론하지 않습니다. 분석자가 설비 manifest와 문헌 frequency plan을 보고 사고 전용 방출 포트를 직접 선언해야 합니다. PRISM은 선언된 포트가 실제 manifest에 존재하는지, 같은 설비에 속하는지, 두 끝단 파열이면 두 포트인지, provider 요청의 resolved release와 일치하는지만 검사합니다.

## 추가된 계약과 실행 방법

- `src/lh2_tno/frequency_port_binding.py`
  - 일반 frequency plan에는 `manifest`를 함께 받아 24개 이벤트를 다시 생성합니다.
  - 모든 이벤트가 명시적인 `port_ids`를 가지지 않으면 중단합니다.
  - provider release 포트와 crosswalk 포트가 다르면 중단합니다.
  - provider 결과에서 frequency 포트를 역으로 만들지 않습니다.
- `scripts/bind_frequency_port_crosswalk.py`
  - 일반 LH2 campaign에 crosswalk를 적용합니다.
- `scripts/bind_frequency_port_result.py`
  - frequency plan이 저장되지 않은 vertical handoff·inventory extension 결과에 명시적인 event-port map을 적용합니다.
- `examples/generic_lh2_frequency_port_crosswalk.json`
  - 저장탱크, 배관, 밸브, vent, pump, vaporizer, reliquefier의 사고 포트를 선언한 합성 예시입니다.

예시 실행은 다음과 같습니다.

```powershell
python scripts/bind_frequency_port_crosswalk.py `
  --campaign results/20261031/native_generic_scope_packets_pipefix/campaign_rebound_state_bound.json `
  --crosswalk examples/generic_lh2_frequency_port_crosswalk.json `
  --manifest examples/generic_lh2_full_scope_manifest.json `
  --output results/20261014/goal_continuation_port_bound/campaign.json `
  --audit results/20261014/goal_continuation_port_bound/frequency_port_binding_audit.json
```

## 확인된 결과

합성 generic LH2 base campaign에서는 7개 설비, 24개 문헌 이벤트가 모두 사고 포트에 결합되고 provider 요청과의 포트 불일치는 0건이었습니다. vertical handoff 5개와 inventory depletion 5개도 `terminal_pipe.out`을 별도로 명시해 결합했습니다.

이 세 결과를 다시 union하면 34개 event, 44개 case, 176개 risk atom이 생성됩니다. 새 facility ledger는 34/34 이벤트를 port-scoped로 확인하고 case·risk atom 포트 불일치 0건을 기록합니다. 따라서 “문헌 빈도 → 설비 사고 포트 → 방출 packet → 피해 영향”의 식별 연결은 진단 원장 안에서 닫혔습니다.

이 결과는 시설 전체 QRA 승인을 의미하지 않습니다. 현재 포트 crosswalk의 provenance는 `synthetic_demonstration_only`이고, provider packet은 qualified 현장 packet이 아닙니다. 방출 종료·재고 소진·일부 사고군·독립 물리검증이 아직 열려 있으므로 facility total IR/F-N은 계속 withheld 상태입니다. 2026-10-14 completion audit는 포트 결합 차단이 제거된 `INCOMPLETE_EVIDENCE`이며, 남은 차단은 방출 경계, provider 자격, 사고 범위/독립 검증, 시설 합성 범위입니다.

## 실제 설비 적용 시 입력해야 할 것

실제 액화수소 시설에서는 합성 예시 포트를 복사하지 않고 다음을 설비 모델 검토 결과로 채워야 합니다.

1. 각 탱크·배관·밸브·펌프·기화기·재액화기의 사고 방출 포트 ID
2. 양단 파열로 계산할 설비의 두 방출 포트
3. 각 포트가 어느 운전 모드와 HAZOP 시나리오에서 유효한지
4. 차단시간, 재고량, 방출 종료 기준을 제공하는 설비 상태 packet
5. 포트와 방출 packet의 source digest 및 검토자/검토일

이 정보가 없으면 PRISM은 사고 포트를 추정하지 않고 해당 event 또는 facility QRA를 차단합니다. 이는 통합 흐름도에서 현장 입력과 운전 모드가 HAZOP 판단을 거친 뒤, 설비·공정 모델, 문헌 빈도, SLABx-LH2, 위험도 집계가 같은 scenario identity를 공유해야 한다는 원칙과 동일합니다.
