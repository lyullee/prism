## Interpretation for the general LH2 module

The reviewed map confirms a small set of pressure and temperature tag units
from the operating procedure. That is useful evidence for preparing a future
state adapter. It is not enough to bind the entire workbook to an equipment
snapshot because the remaining columns still need reviewed units, tag-to-asset
identity, pressure basis, calibration/quality records, timestamps, and an
explicit stream-to-component mapping.

The PRISM adapter therefore remains fail-closed:

1. A caller must provide an exact `tag`, `unit`, and `quality` binding for each
   selected source column.
2. The normalizer must establish the pressure basis and freshness before a
   state snapshot is accepted.
3. A normal-state row never creates a hole, release duration, isolation result,
   inventory depletion, or annual frequency.
4. A qualified equipment provider still owns the accidental-release packet;
   only that packet can enter the SLABx-LH2 consequence chain.

This result improves traceability of the real data while preserving the
general-facility scope and the literature-based frequency policy.

## Unit-consistency gate for the runtime manifest

The runtime state manifest was compared separately with the reviewed unit
map:

```powershell
python scripts/audit_observed_unit_consistency.py `
  --manifest examples/inspection_center_observed_state_manifest.json `
  --reviewed-map examples/inspection_center_reviewed_signal_unit_map.json `
  --output examples/inspection_center_unit_consistency_audit.json
```

The result is `BLOCKED_UNIT_CONFLICT` (8 bindings):

- `PT1206` and `PT1105A` are declared as `MPa` in the runtime manifest but
  `bar` in the reviewed procedure evidence.
- `TT1106` is the only binding whose unit declarations match exactly.
- Five bindings have no reviewed unit claim (`DPT1101`, `PT1101`, `TT1116`,
  including repeated `DPT1101` use).

PRISM does not select `MPa` or `bar` from the numeric ranges. The state
snapshot gate therefore remains closed until the owner supplies a reviewed
resolution for each selected tag, including pressure basis and calibration or
quality evidence. This is a data-contract correction, not a change to the
general LH2 facility model or to the literature-frequency policy.

## Explicit unit labels in the original workbooks

The original XLSX files contain a separate, stronger raw-signal clue: their
header cells explicitly label `PT1206`, `PT1105A/B`, `PT1101`, `PT1106`, and
`PT1107` as `MPa`, and the temperature tags as `℃`. The header-only audit
found 168 claims across 17 workbooks with no conflicting header labels:

```powershell
python scripts/audit_workbook_header_units.py `
  --source-root "C:\Users\lyul\Desktop\DocuData\액화수소검사지원센터 데이터" `
  --output examples/inspection_center_workbook_header_unit_evidence.json
```

The resulting candidate map is
[`examples/inspection_center_workbook_header_signal_unit_map.json`](../examples/inspection_center_workbook_header_signal_unit_map.json).
Comparing the runtime manifest with this raw-header map gives five exact
matches, zero unit conflicts, and three unreviewed differential-pressure
signals. The earlier `bar` claims are retained as procedure **setpoint
context**; they are not silently used as the raw workbook unit.

This improves the evidence boundary without opening the state gate. Pressure
basis (absolute versus gauge), calibration/quality records, equipment identity,
and the three DPT units still require explicit review. The resulting status is
`REVIEWED_UNIT_COVERAGE_INCOMPLETE`, with frequency learning, provider creation,
and facility QRA still disabled.
