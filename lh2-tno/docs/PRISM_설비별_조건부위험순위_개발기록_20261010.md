# PRISM 설비별 조건부 위험 순위 장부

## 목적

시설 원장은 여러 설비의 사고 원자를 한 번만 합산하면서도 `component_contributions`에 설비별 IR/F-N을 보존합니다. 이번 보완은 이 값을 운영자가 바로 읽을 수 있도록 설비별 우선순위 장부로 펼칩니다.

이 순위는 이미 계산된 위험 원자를 다시 계산하지 않습니다. 각 설비에서 수용점별 연간 IR을 읽고, 두 불확실성 끝점에서 가장 큰 수용점 값을 찾아 높은 끝점부터 정렬합니다. 사람이나 수용점을 합산하지 않으므로 여러 수용점을 합쳐 위험을 부풀리지 않습니다.

## 출력 계약

`prism.facility_risk_ledger.v1`에 다음 필드가 추가됩니다.

```json
{
  "component_risk_ranking": {
    "status": "AVAILABLE",
    "component_count": 2,
    "ranking_basis": "descending peak receptor annual IR at the high uncertainty endpoint; diagnostic triage only",
    "frequency_reallocation_performed": false,
    "facility_ir_fn_promotion": false,
    "rows": [
      {
        "rank": 1,
        "component_id": "liquid-transfer-line-01",
        "peak_annual_ir_low_high": [1.0e-7, 2.0e-7],
        "peak_receptor_id_low_high": ["worker-01", "worker-01"],
        "status": "PARTIAL",
        "frequency_is_not_reallocated": true
      }
    ]
  }
}
```

`peak_annual_ir_low_high`는 설비별 모든 수용점 중 가장 큰 IR을 낮은·높은 끝점으로 각각 기록합니다. 이 값은 “어느 설비를 먼저 검토할까?”를 정하는 진단용 순위이며, 설비 간 빈도를 다시 나누거나 누락 설비를 0으로 처리하지 않습니다. `facility_ir_fn_promotion=false`는 원장에 합성 packet, 부분 사고범위, 미검증 입력이 있어도 시설 전체 IR/F-N 승격을 시도하지 않는다는 뜻입니다.

## 해석 예시

- 순위 1 설비의 `status`가 `EXECUTED_OPERATOR_LIMITED`이면 계산 경로는 도달했지만 provider 경계나 운전자 제한이 남아 있다는 뜻입니다.
- `strict_uncomputed_case_count`가 양수이면 해당 설비의 일부 사고·기상·차단 branch가 엄격 계산에서 빠져 있으므로 순위만으로 방호 결론을 내리지 않습니다.
- 모든 `peak_annual_ir_low_high`가 0이면 수용점에서의 조건부 피해가 0으로 계산된 것입니다. 이는 누락 위험을 0으로 가정했다는 뜻이 아닙니다.

현재 generic+vertical 병합 원장의 상태 장부는 이 순위를 계산할 수 있는 29개 사건·34개 case·136개 risk atom을 가지고 있지만, 34개 qualified provider case가 없고 주요 사고군과 독립 물리검증도 완결되지 않았습니다. 따라서 순위는 조건부 진단 화면에만 사용하며, IJHE 완료 감사의 `INCOMPLETE_EVIDENCE`와 시설 IR/F-N 보류 상태는 그대로 유지합니다.

## 검증

`tests/test_facility_ledger.py`는 두 설비의 같은 원자를 한 번만 합산하고, 높은 IR 끝점·수용점·순위 정렬·빈도 재할당 금지·시설 IR/F-N 승격 금지를 함께 확인합니다. 최신 CI의 전체 계약 검사가 통과해야 이 장부를 배포 가능한 코드로 봅니다.
