# 다중 사건·기상·방호 분기 실행기 — 2026-10-09

## 이번에 추가한 것

현재 개발 소스에 `RiskCampaign`과 `ResearchPipeline.facility_risk()`를 추가했다. 공개 0.6.0 배포에는 이 기능이 없으며 아직 새 PyPI/DOI 버전을 발행하지 않았다.

각 문헌 LOC를 다음처럼 연결한다.

`설비/사건 → 방출·차단 분기 → 연간 기상·인구 조건 → 실제 LH2 방출/확산/피해 → 점화별 피해 → 기존 TNO IR/F-N 함수`

주요 파일은 `src/lh2_tno/campaign.py`, `sensitivity.py`, `cli.py`, `worker.py`다. 외부 TNO 코드 자체를 바꾸지 않고 소스 pin을 검사한 별도 worker에서 `risk.total_individual_risk`와 `risk.fn_curve`를 호출한다.

## 계산 회계

각 수용점의 IR 기여는 `개시 빈도 × 연간 조건 확률 × 방출/방호 분기 확률 × 점화 분기 확률 × 해당 분기의 인명 피해`다. 네 가중치를 각각 한 번만 곱한다. 고정 위치에 계속 있는 사람의 IR에는 인구 재실확률을 다시 곱하지 않는다.

F-N은 각 사건/연간 조건/방호/점화 결과를 먼저 분리하여 사건별 기대 사망자 수를 구하고 native TNO 함수에서 누적한다. 인구는 중복 없는 옥외 집단이며 수용점 위치를 대표 위치로 사용한다. 사람별 사망의 독립성이나 공동 확률분포를 새로 가정하지 않는다. F-N의 가로축은 기존 엔진의 기대 사망자 수 관례다.

방출/방호 분기와 연간 조건의 확률 합이 1이어야 한다. 모든 생성 LOC에는 물리 요청 또는 명시적 미계산 사유가 있어야 한다. 빈도를 이미 넣은 요청을 campaign에 다시 넣을 수 없다. 누출 직경·부품·단일 설비 노출·종료 사유는 기존 `bind_event`가 대조한다.

## 결과가 부분 계산일 때

- `known_contribution_annual_ir_low_high`: 계산된 범위에서의 기여.
- `declared_scope_annual_ir_low_high`: 선택 범위가 모두 실행됐을 때만 값이 있다.
- `total_facility_annual_ir_low_high`: 미계산·제외 설비·합성 방출 종료가 있으면 `null`이다.
- F-N도 알려진 기여·선택 범위·전체 시설을 같은 기준으로 구분한다.
- `uncomputed_cases`: 미지원 LOC, backend 실패, 공간 잘림과 사유.
- `coverage`: 개시 빈도의 계산 비중. **위험도를 그 비율만큼 계산했다는 뜻이 아니다.** 드문 전량 방출의 피해가 더 클 수 있다.
- `risk_atoms`: 빈도·연간 조건·점화별 피해를 보관하여 물리 계산을 반복하지 않고 빈도 민감도를 비교한다.

## 실행 방법

개발 소스를 editable 설치한 환경과 검토된 외부 backend를 사용한다. `backend.json`에는 실제 외부 모델·interpreter·해시를 지정한다.

```powershell
python -m pip install -e "./lh2-tno[test]"
python prism.py --mode lh2 lh2-tno/examples/consequence_facility.json --backend backend.json --risk-campaign lh2-tno/examples/risk_campaign_diagnostic.json --frequency-sensitivity lh2-tno/examples/frequency_sensitivity_diagnostic.json --output campaign_result.json
```

예제의 풍속·인구·빈도 보정·분기 확률·방출 시간은 합성 진단값이다. 시설 설계 기본값으로 복사하지 않는다.

## 실제 외부 모델 실행 결과

정렬된 서풍의 3/4 m/s 조건 × 고정 탱크 상태에서의 0.2/0.4초 방출: 새 물리 계산 4건 통과. source 질량 장부, SLABx-LH2 전이/SLABx 확산, 점화별 피해와 native TNO 합산까지 실행했다. 최초 성공 묶음에서 사례당 약 4.02–4.18초, 묶음 전체 약 16.64초였다. 반복 실행의 p95/p99나 운영 1 Hz를 입증하는 자료는 아니다.

G1 전량 순간 방출과 G2 600초 방출은 각 2개 기상 조건에서 명시적 미계산으로 유지한다. 배관·밸브·벤트도 이 예제의 물리 사고 범위에서 제외돼 있다. 따라서 전체 시설 IR/F-N은 `null`이다.

방출은 시간 간격을 전체 방출 시간과 같게 둔 **고정 upstream 상태 진단**이다. 실제 설비 모델에서 차단 응답·재고 소진을 새로 풀어 얻은 결과가 아니다.

## 실패 시험에서 확인한 보완 항목

같은 실제 출구를 유지하며 풍향을 90도 바꾼 사례는 near-field/확산 경로가 180초 제한시간을 넘겼다. source 시간 간격 0.2초에 0.4초 방출을 요청한 과도 사례는 `source ended early; incomplete release horizon cannot be extrapolated`로 실패했다. 실패를 무시하거나 0으로 합산하지 않았고 `stress_probe_result.json`에 보존했다.

검토한 외부 source의 `_advance_tank`는 D/S 상태를 사용하고 포화 endpoint의 P/T interface에 0.05 K 보정을 적용하며, 배압 인근/저압 출구에서 history를 일찍 종료한다. 단순히 마지막 유량을 끝까지 연장하거나 남은 구간을 0으로 채워 종료 검증을 대신하지 않는다. 다음 방출 개발에서는 기존 설비 PH/재고 모델의 상태·종료 경계를 우선 사용하고 배압 접근/비임계 유량과 누출 질량·에너지 feedback을 명시해야 한다.

풍향 확장의 다음 검사는 전이의 풍향 정렬 기준, 단계별 반복 계산 비용과 유효 handoff를 분리한다. 노즐 방향을 바람에 맞춰 돌려 원래 실패 사례를 성공으로 바꾸지 않는다. 성공 예제와 실패 시험을 별도 입력으로 보관한다.

## 빈도 민감도

각 빈도 자산의 명시한 배수로 저장된 `risk_atoms`를 다시 가중한다. 예제 배수 0.1/1/10은 진단 범위이며 문헌 신뢰구간이나 고장률 분포가 아니다. 1배 결과를 native 합산 기준값과 대조한다. IR/F-N 기여, 계산된 범위의 기대 사망자 기준 자산 순위를 내며 미계산 자산의 순위는 보류한다. 미계산 사고는 배수를 바꿔도 그대로 남는다.

문헌 로그정규 분포의 샘플링·상관 가정 비교와 전체 위험의 통계적 불확실성 분석은 아직 후속 작업이다. 이번 민감도 기능만으로 단계 D 완료를 주장하지 않는다.
