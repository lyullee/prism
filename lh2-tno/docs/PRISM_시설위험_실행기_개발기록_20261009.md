# 다중 사건·기상·방호 분기 실행기 — 2026-10-09

## 이번에 추가한 것

현재 개발 소스에 `RiskCampaign`과 `ResearchPipeline.facility_risk()`를 추가했다. 공개 0.6.0 배포에는 이 기능이 없으며 아직 새 PyPI/DOI 버전을 발행하지 않았다. G1에는 SLABx-LH2의 명시적 finite-inventory liquid-jet operator를 연결했지만, 일정 upstream 상태와 열림 spray-energy 가정 때문에 결과를 `EXECUTED_OPERATOR_LIMITED`로 표시한다. 추가로 provider-resolved liquid/two-phase exit를 `ResolvedLiquidRelease`로 받아 pool·확산·피해까지 연결한 단일 진단을 실행했다.

각 문헌 LOC를 다음처럼 연결한다.

`설비/사건 → 방출·차단 분기 → 연간 기상·인구 조건 → 실제 LH2 방출/확산/피해 → 점화별 피해 → 기존 TNO IR/F-N 함수`

주요 파일은 `src/lh2_tno/campaign.py`, `sensitivity.py`, `cli.py`, `worker.py`다. 외부 TNO 코드 자체를 바꾸지 않고 소스 pin을 검사한 별도 worker에서 `risk.total_individual_risk`와 `risk.fn_curve`를 호출한다. `source_duration_mode=model_natural`을 선택하면 통합 LH2 source가 압력 평형으로 일찍 끝낸 실제 시간 이력을 사용하며, 마지막 유량을 요청 시간까지 연장하지 않는다.

## 계산 회계

각 수용점의 IR 기여는 `개시 빈도 × 연간 조건 확률 × 방출/방호 분기 확률 × 점화 분기 확률 × 해당 분기의 인명 피해`다. 네 가중치를 각각 한 번만 곱한다. 고정 위치에 계속 있는 사람의 IR에는 인구 재실확률을 다시 곱하지 않는다.

F-N은 각 사건/연간 조건/방호/점화 결과를 먼저 분리하여 사건별 기대 사망자 수를 구하고 native TNO 함수에서 누적한다. 인구는 중복 없는 옥외 집단이며 수용점 위치를 대표 위치로 사용한다. 사람별 사망의 독립성이나 공동 확률분포를 새로 가정하지 않는다. F-N의 가로축은 기존 엔진의 기대 사망자 수 관례다.

방출/방호 분기와 연간 조건의 확률 합이 1이어야 한다. 모든 생성 LOC에는 물리 요청 또는 명시적 미계산 사유가 있어야 한다. 빈도를 이미 넣은 요청을 campaign에 다시 넣을 수 없다. 누출 직경·부품·단일 설비 노출·종료 사유는 기존 `bind_event`가 대조한다.

## 결과가 부분 계산일 때

- `known_contribution_annual_ir_low_high`: 계산된 범위에서의 기여.
- `declared_scope_annual_ir_low_high`: 선택 범위가 모두 실행됐을 때만 값이 있다.
- `total_facility_annual_ir_low_high`: 미계산·제외 설비·합성 방출 종료가 있으면 `null`이다.
- F-N도 알려진 기여·선택 범위·전체 시설을 같은 기준으로 구분한다.
- `uncomputed_cases`: 미지원 LOC, backend 실패, 공간 잘림과 사유.
- `coverage`: 개시 빈도의 계산 비중. **위험도를 그 비율만큼 계산했다는 뜻이 아니다.** 드문 전량 방출의 피해가 더 클 수 있다.
- `coverage.by_component`: 시설의 각 component별로 생성된 사건 수·개시빈도·실행/미계산 건수·제외 사유를 기록한다. `executed_case_count`는 수치 실행된 사례를 세고, `fully_validated_case_count`, `operator_limited_case_count`, `domain_incomplete_case_count`를 별도로 둔다. `PARTIAL`, `EXCLUDED`, `EXECUTED`, `NO_EVENT_GENERATED`를 명시해 설비별 결합 여부를 사건 ID 추정 없이 확인한다.
- 통합 시설 원장의 `component_coverage`는 이 회계를 한 단계 더 보존한다. provider packet의 `component_id`가 있으면 그것을 사용하고, 없으면 event의 `model_component_id`로 case를 설비에 배정한다. 각 설비 행에는 event 수, event·기상·방출 branch·점화 branch를 합친 고유 조건 case 수, 실제 실행·조건부 미계산·엄격 보류 행 수, operator-limited/domain-incomplete/failed 수, risk atom 수와 `strict_gate_categories`가 들어간다. 조건부 수치는 중복 case를 한 번만 세고, 엄격 보류 수치는 설명에 필요한 원자료 행을 보존한다. 이 원장은 설비별 결합과 증거 수집 순서를 보여주는 회계이며 누출 빈도를 추론하거나 빈도 0을 배정하지 않는다. `component_contributions[component_id].coverage`와 `conditional_diagnostic_facility_coverage.component_case_accounting`에도 같은 행을 복사해 downstream 감사가 하나의 파일에서 확인할 수 있다.
- `risk_atoms`: 빈도·연간 조건·점화별 피해를 보관하여 물리 계산을 반복하지 않고 빈도 민감도를 비교한다.

## 양단 파열 연결 진단

Purple `TNO_PIPE`의 G1 full-bore rupture는 한 출구로 축약하지 않는다. `ResolvedGasReleaseSet`은 동일 사건 ID와 공유 재고를 가진 두 개의 provider-resolved outward gas exit, 서로 다른 포트·위치, 각 출구의 PH/면적/속도/시간 장부를 확인한다. 배관 길이·수량 빈도를 하나의 물리 위치에 배정할 때는 `location_weight`와 근거를 별도로 입력한다.

`scripts/validate_two_sided_rupture.py`는 외부 설비 provider의 출구 계산을 두 포트에 보존한 뒤 각 끝을 SLABx-LH2/SLABx/TNO 체인에 보내고, 동일 initiating event의 수용점 피해를 Frechet union 상한으로 결합한다. 합성 기하·재고·기상에서 2개 기상 사례를 실행했고, 최대 질량 잔차는 `0.0 kg`, 건별 새 물리시간은 약 `8.568–8.625 s`, 캠페인 p95/p99는 `8.622/8.625 s`였다. G2 단일 구멍 경로는 별도 `UNCOMPUTED`로 남겼고, cross-endpoint plume·압력·재고 feedback은 `EXECUTED_OPERATOR_LIMITED`와 시설 total 보류 사유로 기록했다. 결과는 `results/20261009/two_sided_rupture/`에 저장한다.

## 수직 벤트 handoff 연결 진단

수직 전용 출구를 PRISM이 임의로 수평으로 돌리지 않도록 `VerticalGasHandoff` 계약을 추가했다. provider는 원래 수직 포트와 별도로 downstream에서 사용할 수평 handoff 위치·단위 방향·속도·밀도·온도·수소 질량분율·단면 크기·provenance를 함께 제공해야 한다. PRISM은 이 handoff 단면에서만 근거리 jet/SLAB 경로를 시작하고, 원래 포트 높이와 사건 위치 검증은 보존한다. handoff가 없는 수직 출구나 수직·수평이 섞인 방향은 계속 명시적으로 거절한다.

`scripts/validate_vertical_vent.py`는 외부 `lh2dt`의 steady provider 출구를 이용해 이 계약을 점검했다. 합성 provider 시계별 수평 handoff 상태를 선언한 `AREA_100%` 경로를 두 기상 조건에 연결하여 2건을 `EXECUTED_OPERATOR_LIMITED`로 실행했다. 각 사례의 질량 잔차는 `0.0 kg`, 새 물리 계산 시간은 약 `3.033–3.161 s`, p95/p99는 `3.155/3.160 s`, 전체 campaign은 약 `6.502 s`였다. 나머지 네 area-bin은 provider handoff 자료가 없어 `UNCOMPUTED`로 남겼고 시설 전체 IR/F-N은 보류했다.

이 진단은 수직 포트의 provider handoff·혼합상태·downstream 연결을 검증한 것이며, 실제 수직 제트의 부력·장애물·교차 plume 상호작용이나 현장 출구 자료를 검증한 결과가 아니다. 현재 handoff state는 provider 방출 시계별로 연결되지만 합성값이다. 실제 provider의 variable-state 물성·부력·장애물 상호작용은 별도 검증이 필요하다. 산출물은 `results/20261009/vertical_vent/`에 보관한다. 새 프로세스 3회 반복 benchmark에서는 campaign 내부 p50/p95/p99가 `7.170/7.352/7.368 s`, process wall p50/p95/p99가 `12.005/12.245/12.266 s`였다. 표본이 3회뿐인 탐색값이며 1 Hz나 운영 SLA를 뜻하지 않는다. benchmark 결과는 `results/20261009/vertical_vent_timing/benchmark.json`에 보관한다.

## 설비 디지털 트윈 출구를 시설 위험으로 연결한 별도 진단

`scripts/validate_equipment_campaign.py`에서는 외부 `lh2dt`의 `VentStack/SteadyNetwork`가 계산한 두 개의 LH2-service PH 상태를 사용했다. PRISM은 유량을 다시 계산하지 않고, 대기압 출구의 PH·EOS 온도/밀도·면적 연속·Mach≤0.3·누적 질량/정적 엔탈피를 `ResolvedGasRelease`로 확인했다. 이어서 하나의 `LH2_PIPE` `AREA_100%` 위치를 두 기상 조건에 연결하여 SLABx-LH2/SLABx 확산, 점화별 피해, native TNO IR/F-N 합산을 실제 실행했다.

RiskCampaign 결과의 `timing`에는 이제 한 번의 캠페인에서 실행된 fresh physics case 시간의 `case_min_ms`, `case_median_ms`, `case_p95_ms`, `case_p99_ms`, `case_max_ms`가 함께 저장된다. p95/p99는 사례 간 분포를 요약한 값이며, 반복 실행 지연시간·운영 SLA·1 Hz 신규 물리 계산 성능을 의미하지 않는다.

두 사례의 방출 질량은 약 0.001803 kg이며 최종 질량 잔차는 0 kg이었다. 사례당 약 4.23–4.31초, 두 사례 전체 약 8.83초가 관찰됐다. 다른 pipe LOC 8건은 `UNCOMPUTED`로 보존하고 전체 시설 IR/F-N을 `null`로 유지했다. 이 결과는 설비 경계가 시설 실행기에 들어가는 연결 증거이며, transient 탱크·밸브 feedback이나 독립 물리 검증을 뜻하지 않는다. 실행 산출물은 `results/20261009/equipment_campaign/`에 있다.

기존 G3 4건과 G1 2건은 시간 간격을 전체 방출 시간과 같게 둔 **고정 upstream 상태 진단**이다. G1의 finite-inventory 수치는 현재 source operator의 질량 폐합을 확인하지만, 실제 설비의 차단 응답·탱크 재고 feedback을 새로 풀어 얻은 결과가 아니다. 별도로 압력 200 kPa, 요청 5초, 간격 0.2초의 통합 source를 실행한 결과 모델은 0.2초 구간 하나만 반환했다. `model_natural` 체인은 유효 방출시간을 0.2초로 기록하고 방출→확산→점화→피해와 질량 장부를 완료했으며, 질량 잔차는 0 kg이었다. 이 검증은 wrapper의 시간·질량 연결을 확인한 것이고, source 모델의 압력 평형 예측 자체를 독립 검증한 것은 아니다.

## 탱크·밸브 차단 feedback을 연결한 transient 진단

새 `scripts/validate_equipment_isolation.py`는 steady 출구를 복사하지 않고 외부 `lh2dt`의 `LayeredTankNetworkSimulator`와 `CommandedValve`를 실제로 호출한다. 합성 수평 탱크를 포화 상태에서 초기화하고, 증기 셀을 외부 경계 포트로 연결한다. 문헌 `LH2_PIPE`의 5개 area-bin(0.01%, 0.1%, 1%, 10%, 100%)마다 밸브 면적을 독립적으로 지정한다. 각 area-bin에서 한 provider 실행은 밸브를 0.25초까지 열고 이후 닫는 isolation-success 명령을 사용하고, 다른 실행은 차단 실패를 선언하여 0.5초 진단시계까지 열린 상태를 유지한다. 각 provider의 방출 유량과 대기압 PH 출구를 PRISM의 `ResolvedGasRelease`로 변환하여 두 barrier branch를 같은 누출 크기 사건에 연결했다.

이 진단의 실제 결과는 다음과 같다.

- 방출 이력 0.5초, 0.01초 간격, 50개 provider 구간.
- `AREA_100%` 성공 분기: 0.25초 전 최대 유량 약 `9.72e-5 kg/s`, 차단 뒤 최대 유량 `0 kg/s`, 누적 방출량 약 `2.4296e-5 kg`.
- `AREA_100%` 실패 분기: 0.5초 진단시계 동안 차단 후 구간이 없고, 시계 내 최대 유량 약 `9.72e-5 kg/s`, 누적 방출량 약 `4.8585e-5 kg`이다. 작은 area-bin에서는 유량과 질량이 면적에 따라 감소한다.
- 5개 area-bin의 합성 초기 재고는 모두 약 `66.086 kg`; 성공 분기 최대 질량 잔차는 `2.88e-14–4.36e-14 kg`, 실패 분기는 `1.68e-14–2.80e-14 kg`였다. 에너지 잔차의 최대는 성공 `2.63e-9–5.37e-9 J`, 실패 `2.20e-9–4.82e-9 J`였다.
- 5개 누출 크기 × 2개 차단 분기 × 2개 기상, 총 20건을 SLABx-LH2/SLABx 피해와 native TNO IR/F-N까지 실행했다. `UNCOMPUTED` 사례는 0건이지만, 합성 진단 종료와 합성 장벽확률 때문에 시설 전체 연간 위험도는 여전히 `null`이다.
- 20건의 새 물리 계산 시간은 건별 약 `7.8–49.5초`, 중앙값 약 `20.0초`, 전체 약 `469.4초`였다. 이는 현재 격자·시계·PC에서의 단일 실행 관찰값이며 1 Hz, 반복 p95/p99 성능을 뜻하지 않는다.

이는 **5개 선언 누출 크기 각각에서 주어진 명령의 차단 성공과 차단 실패가 서로 다른 방출 이력으로 시설 피해 계산에 전달되는지**를 확인한 것이다. barrier 성공확률 `0.99`는 입력된 합성 분기값이며 현장 차단 신뢰도나 요구시 실패확률이 아니다. 성공 종료는 `reviewed_isolation_success`, 실패 종료는 `synthetic_diagnostic_horizon`으로 각각 기록했다. 실패 분기는 재고 소진을 계산하지 않고 0.5초까지만 유지하므로 시설 전체 완결 계산으로 사용할 수 없다. 실제 actuator 지연, 밸브 고장 시 재고 방출, 액체·2상 flash, 현장 설비 치수 보정은 포함하지 않았다. 또한 103 kPa 근처 합성 압력과 100 kPa 외기라는 낮은 압력차의 수평 저 Mach 경계로 실행했으므로, 고압 또는 underexpanded 출구에 이 결과를 일반화하지 않는다. provider가 소유한 유량을 PRISM이 다시 계산하지 않았다.

## 양수 재고 종료 adapter의 추가 실행

앞의 layered transient 경로와 별도로 `scripts/validate_equipment_inventory.py`에 `HomogeneousTank`/`DynamicNetworkSimulator` 기반의 양수 재고 종료 adapter를 추가했다. provider를 최대 0.5초씩 다시 만들면서 탱크 상태의 질량이 `1.3405e-4 kg` 이하가 되는 순간 종료하고, 그 마지막 유효 구간만 `ResolvedGasRelease`로 넘긴다. 다섯 LH2 pipe area-bin에 면적을 독립 적용하며, 이 방식은 현재 layered simulator에 없는 zero-mass callback을 흉내 내지 않고 0 kg 상태나 미래 유량을 쓰지 않는다.

다섯 누출 크기를 두 기상 조건에 연결한 결과 10건이 `EXECUTED`, `UNCOMPUTED`는 0건이었다. `AREA_0.01%`부터 `AREA_100%`까지 provider가 각각 1.5/0.5/0.5/0.5/0.0625초에서 종료했고, `AREA_100%`는 남은 질량 `1.0793137e-4 kg`, 누적 방출 `2.6236187e-5 kg`를 반환했다. 다섯 사례의 최대 질량 잔차는 `1.34e-20 kg`, 에너지 잔차는 `1.69e-13 J`였고, 시설 실행은 방출→확산→점화별 피해→native TNO IR/F-N까지 통과했다. 건별 새 물리시간은 약 1.59–2.31초, 전체 약 20.85초였다. `synthetic_release_horizon_present=false`와 모든 `termination.basis=inventory_depletion`을 확인했으며 declared-scope total IR/F-N은 계산됐다. 다만 초기 상태·밸브·threshold·시설 입력이 합성이고 물리 검증 자료가 없으므로 실제 시설 위험 완료로 세지 않는다. 액체/2상 layered tank, 실제 actuator 신뢰도, 고압/underexpanded 출구, 전량 방출과 양단 파열의 교차상호작용, handoff 없는 수직 vent 및 실제 수직 제트 물리는 계속 미계산이다. 상세 기록은 `docs/PRISM_재고소진_연결_개발기록_20261009.md`에 있다.

### LayeredTank 재고 소진을 아직 지원하지 않는 이유

외부 `lh2dt`의 `LayeredTankState`는 액체·증기 각 셀의 질량을 **엄격히 양수**로 요구한다. 현재 `LayeredTankNetworkSimulator`도 적분 중 재고가 0이 되는 사건에서 멈추거나 마지막 유효 상태를 반환하는 종료 콜백을 제공하지 않는다. 따라서 PRISM이 셀 질량을 0으로 덮어쓰거나 남은 방출을 600초까지 연장하면 provider의 보존식과 상태 계약을 위반한다. 이번에 구현한 양수 threshold는 `HomogeneousTank` 경로에만 적용했고, layered tank의 실제 전량 방출이나 액체/2상 재고 종료로 해석하지 않았다. LayeredTank 경로를 확장하려면 provider 쪽의 event-safe threshold, 마지막 구간 질량·에너지 잔차, 잔류 재고를 함께 반환하는 계약이 필요하다.

실행 산출물은 `results/20261009/equipment_isolation_campaign/`의 성공·실패 provider 입력·응답, resolved release, campaign 결과, verification에 보관한다. 이 transient 경로는 기존 steady 경계 진단과 별도 기록으로 유지한다.

## 실패 시험에서 확인한 보완 항목

같은 실제 출구를 유지하며 풍향을 90도 바꾼 사례는 near-field/확산 경로가 180초 제한시간을 넘겼다. 자연 종료 모드를 사용하지 않는 상태에서 source 시간 간격 0.2초에 0.4초 방출을 요청한 과도 사례는 `source ended early; incomplete release horizon cannot be extrapolated`로 실패했다. 이제 `model_natural` 모드에서는 이 조기 종료를 실패로 숨기지 않고, 모델이 반환한 마지막 구간까지를 유효 방출로 기록한다. 실패를 무시하거나 0으로 합산하지 않았고 `stress_probe_result.json`과 자연 종료 검증 스크립트에 보존했다.

검토한 외부 source의 `_advance_tank`는 D/S 상태를 사용하고 포화 endpoint의 P/T interface에 0.05 K 보정을 적용하며, 배압 인근/저압 출구에서 history를 일찍 종료한다. 단순히 마지막 유량을 끝까지 연장하거나 남은 구간을 0으로 채워 종료 검증을 대신하지 않는다. 다음 방출 개발에서는 기존 설비 PH/재고 모델의 상태·종료 경계를 우선 사용하고 배압 접근/비임계 유량과 누출 질량·에너지 feedback을 명시해야 한다.

풍향 확장의 다음 검사는 전이의 풍향 정렬 기준, 단계별 반복 계산 비용과 유효 handoff를 분리한다. 노즐 방향을 바람에 맞춰 돌려 원래 실패 사례를 성공으로 바꾸지 않는다. 성공 예제와 실패 시험을 별도 입력으로 보관한다.

## 빈도 민감도와 문헌 불확실성

각 빈도 자산의 명시한 배수로 저장된 `risk_atoms`를 다시 가중한다. 예제 배수 0.1/1/10은 진단 범위이며 문헌 신뢰구간이나 고장률 분포가 아니다. 1배 결과를 native 합산 기준값과 대조한다. IR/F-N 기여, 계산된 범위의 기대 사망자 기준 자산 순위를 내며 미계산 자산의 순위는 보류한다. 미계산 사고는 배수를 바꿔도 그대로 남는다.

이번 단계에 `uncertainty.py`와 `--frequency-uncertainty`를 추가했다. 각 생성 자산에 `p05`, `published`, `fixed`, `p95` 중 하나를 명시하고, 해당 자산의 모든 LOC가 같은 분위수 방향을 공유한다. p05/p95는 catalogue에서 실제로 계산된 `FrequencyEvent.marginal_p05_per_year`와 `marginal_p95_per_year`만 사용한다. `fixed`는 공개 분위수 근거가 없는 사건의 선언된 catalogue 빈도를 그대로 유지하는 혼합-catalogue 선택지이며 0 또는 새 분포를 뜻하지 않는다. 경계가 없는 TNO Purple 사건에 p05/p95를 요청하면 오류로 중단하며 중앙값/발행값을 자동 대체하지 않는다.

이 결과는 저장된 `risk_atoms`의 빈도만 재가중하고 물리 계산을 다시 하지 않는다. `within_asset_shared_quantile`은 한 자산의 LOC가 같은 분위수 방향을 공유하고, `independent_event_bounds`는 사건별 분위수를 별도로 지정한다. 두 시나리오를 함께 주면 상관 가정 민감도를 비교할 수 있다. 별도 `sample_literature_frequency_distributions`는 catalogue에 공개된 로그정규 `mu`/`sigma`가 있는 사건만 표본화해 known contribution의 p05/p50/p95를 계산한다. 물리·기상·방호·점화 항은 고정하며, 미계산 LOC는 모든 시나리오에서 그대로 미계산으로 남는다. 이번 보완으로 `asset_rank_stability`에 표본별 평균 순위와 1위 확률을 낮은/높은 복사율 끝점별로 기록한다. 이는 계산된 known contribution 안의 우선순위 안정성 지표이며, 미계산 사고를 포함한 시설 전체 우선순위가 아니다. 시설 전체가 완전하지 않으면 결과를 전체 시설 credible interval로 부르지 않는다. 반복 seed 검토와 완전 시설 최종 구간은 아직 후속 작업이다. 이번 기능만으로 단계 D 완료를 주장하지 않는다.

## 확인과 남은 일

### 600초 전량방출 진단

`scripts/validate_long_horizon_inventory.py --allow-pin-refresh`로 `inventory_over_600s` 사건을 실제 provider와 연결했다. 합성 10 m³ 탱크, 100000 W 벽면열, 1000 kg 상한 입력에서 provider는 60초 간격 10개 구간으로 600초 전체 이력을 반환했다. 이 이력은 SLABx-LH2 source → SLABx 확산 → 유한 체적 관측연산자 → 점화·화염복사·TNO 손상 계산까지 통과했고, `END_TO_END_DIAGNOSTIC_EXECUTED`, `operator_limited=false`, 최종 질량 잔차 `0.0 kg`, 최신 처리시간 약 `36.83 s`를 기록했다. 결과는 `results/20261009/long_horizon_inventory/`에 저장한다.

이 사례는 실제 설비 입력이나 현장 검증이 아니다. backend의 외부 TNO tree pin이 저장된 config와 달라 명시적 `--allow-pin-refresh`를 사용했고, 이전/관측 digest를 결과에 남겼다. 합성 열부하·재고·위치·기상으로 시설 전체 연간 위험을 주장하지 않으며, 현재 campaign의 G2는 실제 시설 경로가 없으므로 계속 `UNCOMPUTED`로 둔다.

이전 단계 기록에서는 기존 154개에 campaign 20개, 민감도 7개, source 자연 종료 8개, 문헌 빈도 불확실성 6개, inventory liquid-jet 3개, equipment inventory-depletion 계약 1개, 물리 검증 증거 계약 4개, 포트 좌표 결합 계약 1개, 양단 파열·위치 배분·공유 재고 계약 5개, 수직 handoff 계약·거부 시험 2개, liquid/two-phase provider 계약·포트·airborne 거부·worker closure 시험 4개를 추가하여 총 218개 portable 검사를 통과했다. 이 숫자는 당시 스냅샷이며 현재 전체 portable suite 수는 상태 장부와 README의 최신 값을 따른다. 가중치 중복, F-N의 사건 분리, 누락·실패·영역 잘림, operator-limited 상태, 잘못된 빈도/누출 크기, 기상·방호 확률 폐합, 예산 초과, 인구 중복, 민감도 재가중, 자연 종료 이력의 무연장, p05/p95 근거 누락, 로그정규 분포 근거 누락, liquid-jet 질량 분할, 양수 재고 종료 provenance, 외부 증거 해시 drift와 hold-out gate를 검사한다. CLI에서도 실제 모델을 새로 실행하여 campaign와 빈도 민감도를 함께 확인한다.

설비별 상태·PH 방출·재고 feedback, 모든 주요 LOC·양단 파열의 교차상호작용·수직 handoff의 실제 물리 검증, 점화/차단 정책 공급기, 위치 배분, 문헌 분포 상관 민감도, 독립 실험과 반복 처리시간은 계속 진행할 목표다. 목표 상태는 active이며 전체 완료가 아니다.

실행 근거는 `results/20261009/campaign_step1/`의 실제 사례 파일, campaign/CLI 결과, stress probe, backend 설정, 단위 검사 XML과 verification에 보관한다. 실측 원자료와 외부 모델 소스를 Git에 추가하지 않는다.

## provider-resolved 액체·2상 출구 연결 진단

`scripts/validate_equipment_liquid_release.py`는 pinned SLABx-LH2 `liquid_jet_source`의 각 left-held interval을 `ResolvedLiquidRelease`로 변환했다. provider는 총 유량, 대기압 flash 기체, 지면 액체, 액적 비행시간·충돌 위치를 소유한다. PRISM은 이 값을 재계산하지 않고 기체를 극저온 전이·SLABx에, 지면 액체를 DynamicLH2PoolX에 전달했다.

`results/20261009/equipment_liquid_release/`에 provider 입력·응답, resolved boundary, 시설·요청, 전체 결과와 검증 요약을 보존했다. 2초 provider history의 총 재고는 `1.3210337112 kg`, 최종 질량 잔차는 `7.55×10⁻¹⁵ kg`, 전체 실행시간은 약 `14.24 s`였다. 결과 상태는 `END_TO_END_DIAGNOSTIC_EXECUTED`이지만 `operator_limited=true`, `physical_validation_claim=false`다. 단계별 시간은 source 0.71 s, pool 0.98 s, 근거리·확산 11.99 s, 관측연산자 0.20 s, 화재·피해 0.12 s였다.

시설 포트는 `phase=two_phase`로 명시해야 하며 gas-only port와의 결합은 실패한다. provider history에 airborne liquid이 남으면 PRISM은 이를 기체로 대체하지 않고 거절한다. 따라서 이 결과는 액체·2상 경계 연결의 실행 증거이지, LayeredTank의 실제 액체/2상 재고 소진, spray-energy 폐합, 현장 실험 검증, 빈도 결합 또는 전체 시설 annual IR/F-N 완료를 뜻하지 않는다.

## IJHE 완료 감사의 외부 provider 증거 판정 보완

완료 감사기(`scripts/build_ijhe_completion_audit.py`)가 외부 provider 증거 장부의 필드 이름이 바뀌어도 사고 방출 증거를 추정하지 않도록 보완했다. 새 필드인 `external_provider_evidence_release_inventory_status`가 있으면 사용하고, 이전 장부의 `external_provider_evidence_accident_release_promotion_status`만 있을 때는 그것을 호환 입력으로 읽는다. 실제 시설 사고 패킷 여부도 명시 필드가 없으면 qualified packet 수와 `QUALIFIED_ACCIDENT_RELEASE_EXPORT` 상태만으로 보수적으로 판정한다. 정상 운전·스크리닝 유량을 사고 방출로 승격하지 않는다.

2026-10-09 provider 재귀 인벤토리의 최신 결과는 559개 JSON을 검사해 정상·스크리닝 유량 24개, 사고 방출 후보 0개, qualified 사고 방출 0개를 기록했다. 따라서 완료 감사 결과는 `INCOMPLETE_EVIDENCE`이며 외부 실제 시설 packet은 `false`, release inventory는 `NO_ACCIDENT_RELEASE_EXPORT`, qualified packet은 `0`으로 남는다. 이 판정은 누락을 숨기지 않고 전체 시설 annual IR/F-N 승격을 차단한다. provider 방출 작업목록의 24개 미계산 사건도 완료 감사에 포함되어, 현재 11개 확인 항목 중 7개가 차단 상태다. 주요 사고 12개 범위 매트릭스·시설 위험도·물리 검증·빈도 불확실성·처리시간 증거가 모두 충족되기 전에는 IJHE 제출 완료로 표시하지 않는다.

완료 감사 CLI는 이제 `--provider-worklist`로 실제 작업목록 JSON을 직접 읽는다. 상태 장부의 요약값과 작업목록 파일이 다르면 파일 기준으로 판정하며, 24개 사건 중 packet 0개와 `UNCOMPUTED_PROVIDER_PACKET` 24건을 별도 차단 근거로 남긴다.

시설 평가 CLI의 결과를 완료 감사에 직접 넣을 때는 평가 JSON의 `frequency_uncertainty` 래퍼도 자동으로 해제한다. 이전에는 campaign의 `literature_frequency_uncertainty` 래퍼만 인식해 현재 혼합 평가의 5개 빈도 시나리오가 0개로 보일 수 있었다. `tests/test_completion_audit.py`에 두 래퍼를 각각 검사하는 회귀시험을 추가했고, 최신 감사는 `results/20261014/ijhe_completion_audit_current.json`에 보존했다. 최신 판정은 11개 검사 중 7개 차단이며, 불완전한 시설을 빈도 불확실성 완료로 승격하지 않는다.

필드 호환성과 campaign 래퍼 uncertainty 장부 회귀시험을 포함한 portable 검사는 265개가 통과했다. 최신 감사 결과는 `results/20261009/provider_release_full_chain_diagnostic/ijhe_completion_audit.json`에 저장하며, provider의 실제 사고 방출 export가 추가되면 같은 CLI를 다시 실행해 차단 항목과 증거를 갱신한다.

campaign 결과 파일을 `--uncertainty-result`로 직접 전달하는 경우에는 uncertainty 장부가 최상위가 아니라 `literature_frequency_uncertainty` 아래에 들어 있다. 완료 감사기는 이 래퍼를 명시적으로 풀어 4개 시나리오가 존재한다는 사실을 기록하고, 그 뒤에도 `facility_credible_interval=false`이면 전체 시설 신뢰구간으로 승격하지 않는다. 따라서 이번 보완은 기존 빈도 불확실성 증거를 누락 없이 보이게 한 것이며, 불완전한 시설 범위를 완전한 것으로 바꾼 것이 아니다.

## 비상 릴리프 방출을 임의 누출과 분리한 연결

문헌 `TNO_RELIEF_DEVICE`의 `maximum_relief_discharge` LOC가 기존 일반 누출 binding에서 거절되던 경계를 보완했다. 이제 provider가 `event_kind=emergency_relief`인 `ResolvedGasRelease`를 제공하고, 요청이 `source_operator=equipment_emergency_relief`와 `release_termination.basis=emergency_relief_discharge`를 명시할 때만 해당 빈도를 방출→확산→점화→피해 chain에 결합할 수 있다. `normal_vent`와 random failure opening이 있는 accidental leak은 이 경로에 들어갈 수 없다. 범위 매트릭스는 이 이벤트를 `vent_hole` 행으로 기록하며, 패킷이나 case가 없으면 `NO_CASE_EXECUTED`/`UNCOMPUTED`로 남긴다. 이번 추가는 릴리프 경계 계약과 fail-closed 연결을 구현한 것이며 실제 시설 릴리프 packet·밸브 setpoint·방출 이력의 검증을 대신하지 않는다.

provider가 탱크의 전체 재고 소진을 계산한 기체 방출 history는 이제 hole 누출로 바꾸지 않고 `equipment_inventory_depletion` operator와 `inventory_depletion` 종료근거로 `instantaneous_inventory` 문헌 사건에 직접 binding할 수 있다. 액체·2상 provider history는 `equipment_liquid_release`로 같은 사건에 결합한다. 정확히 600초의 provider history는 기체의 `equipment_inventory_over_600s` 또는 액체·2상의 `equipment_liquid_over_600s` operator와 `inventory_over_600s` 종료근거를 요구한다. 세 경로 모두 provider의 duration·질량·엔탈피/상분율 장부를 보존하며, 짧은 시계열·센서값·정상 유량을 재고 방출로 승격하지 않는다. 합성 provider 계약 검증 3건(gas 2, liquid 1)을 추가했으며 실제 센터 provider packet은 여전히 0건이다.

## RealtimeConsequenceMonitor의 frame deadline 장부

`src/lh2_tno/service.py`의 `RealtimeConsequenceMonitor`는 정규화된 센서 frame을 `ConsequenceService`에 전달하고, 한 번의 갱신에 대해 입력 자료 age, source frame 간격, exact-cache hit 또는 fresh physics 실행, 처리시간과 deadline 상태를 함께 기록한다. deadline을 넘으면 결과를 오래된 cache로 조용히 바꾸지 않고 `realtime.deadline_status="MISSED"`로 남긴다.

`RealtimeFrequencyBinding`을 같이 선언하면 실시간 피해 결과에 문헌 빈도를 연결할 수 있다. 이 binding은 사건·자산·출처 digest와 현재 기상확률, 방출 branch 확률, 재실확률을 별도 입력으로 받아 provider가 반환한 수용점 피해와 곱한다. 모든 설비가 명시된 binding과 유효한 `harm_given_observed_release_low_high`를 가진 경우에만 `current_weather_annual_ir_low_high`를 기록하며, 누락 설비·누락 빈도·누락 피해는 `WITHHELD`로 남긴다. 이 값은 현재 기상 조건의 조건부 IR 진단이고, 센서 빈도 학습·누출 역추정·시설 연간 IR/F-N 승격이 아니다. F/N은 인구별 기대 사망자와 여러 기상·사고 family가 닫힌 별도 campaign에서만 계산한다.

이 monitor는 누출 구경·방출 지속시간·개시빈도를 센서에서 추정하지 않으며, provider resolver가 검증된 방출 경계를 제공하지 않으면 기존 계약대로 거절한다. 이번 추가의 MET/MISSED 시험은 synthetic `Pipeline` 계약 시험이며 1 Hz 신규 물리 계산이나 운영 SLA를 입증하지 않는다. 실제 물리 처리시간은 기존 fresh-case와 반복 benchmark 장부를 사용하고, 운영 배포 전에는 같은 hardware와 실제 provider packet으로 p50/p95/p99·자료 age·deadline 초과·회복시간을 다시 측정해야 한다.

## 2026-10-14 설비 모델 진단 adapter와 native export 분리

설비 모델 감사가 외부 모델의 native 사고 export와 PRISM 측 진단 adapter를 한 상태로 섞지 않도록 `diagnostic_release_adapter` 필드를 추가했다. 일반 LH2 매니페스트의 저장탱크·배관·밸브·벤트·펌프·기화기·재액화기는 각 `export_lh2dt_*_prism_packet.py` adapter가 있어 7건이 `DIAGNOSTIC_RELEASE_ADAPTER_BOUND`로 기록된다. 경계 컴포넌트는 adapter가 없다.

새 live 감사 `results/20261014/equipment_accident_export_interface_audit_live.json`은 component 8건, 진단 adapter 7건, qualified accident release 0건, 상태 `STATE_ONLY_BOUND`를 반환했다. worklist도 각 항목에 adapter 상태와 모듈을 보존하면서, 합성·스크리닝 adapter가 qualified provider packet을 대체하지 않는다는 차단 사유를 남긴다. 이 변경은 진단 연결 경로를 더 정확히 보여주지만, 외부 `export_accident_history(request)` 구현·현장 종료/재고 장부·독립 물리검증·시설 IR/F-N을 완료시키지 않는다.

## 2026-10-24 조건부 실시간 expected-death F/N 기여

`RealtimePopulationBinding`을 추가해 명시적인 수용점별 인구 장부를 실시간 시설 monitor에 전달할 수 있게 했다. 모든 accepted component가 같은 수용점 집합과 문헌 빈도·피해 endpoint를 갖는 경우 `conditional_current_weather_expected_death_fn_low_high`를 계산하고, p05/published/p95 빈도 민감도도 동일한 피해 결과에 재가중한다. 인구·수용점이 누락되면 0으로 채우지 않고 `WITHHELD`로 남긴다. 이 값은 현재 기상 조건의 조건부 expected-death 기여이며 `facility_fn_available=false`, `facility_annual_risk_available=false`, `frequency_learning=false`를 유지한다. 2026-10-24 portable suite는 541개 검사를 통과했다.

같은 날 시설 ledger의 F/N 빈 배열 의미도 명시했다. `conditional_diagnostic_facility_expected_death_fn_diagnostics`는 `CURVE_AVAILABLE`, `SUB_ONE_EXPECTED_DEATH_LEVEL_ONLY`, `ZERO_EXPECTED_DEATH_AT_DECLARED_RECEPTORS`, `NO_RISK_ATOMS`를 구분한다. 따라서 20 m 수용점에서 risk atom은 계산됐지만 N≥1에 도달하지 않은 결과를 계산 누락으로 오해하지 않는다. 저장된 near-receptor 결과는 `scripts/build_near_receptor_facility_assessment_summary.py`로 원장에 다시 통과시켜 N=1 누적빈도 `4.68e-5/year`를 확인할 수 있으며, 시설 전체 QRA 승격은 계속 보류한다. 이 보완 후 portable suite는 541개 검사를 통과했다.
