# PRISM packet 자격 준비도 감사 (2026-10-24)

## 목적

외부 `lh2dt` 사고방출 결과가 worklist의 event/component/port/opening과 정확히 맞아도, 그것만으로 실제 설비의 적격 사고 packet이 되는 것은 아니다. 이번 보완은 정확히 맞은 packet마다 **왜 아직 자격 승격을 할 수 없는지**를 기계적으로 기록한다.

이 감사는 빈도를 만들지 않는다. 센서나 정상 운전자료로 사고 방출을 추정하지도 않는다. `qualified_actual` packet과 시설 IR/F-N은 기존 fail-closed 규칙을 그대로 따른다.

## 구현

`src/lh2_tno/provider_worklist_evidence.py`의 evidence-only 감사가 exact packet을 선택할 때 다음 정보를 함께 보존한다.

- `input_origin`과 provider가 선언한 `termination_basis`
- `verification.status`와 provider 제한사항
- `qualification_readiness.status`와 승격 차단 사유
- 전체 감사의 `status_counts`, `blocker_counts`, `input_origin_counts`

현재 차단 사유는 다음처럼 분리된다.

| 차단 사유 | 뜻 |
|---|---|
| `qualification_sidecar_missing` | `prism.provider_qualification_evidence.v1`가 아직 없음 |
| `physical_validation_evidence_missing` | 독립 물리검증 ID·digest가 없음 |
| `operator_limited_input` | 실행 기록이 operator-limited 경계임 |
| `synthetic_or_screening_boundary_declared` | 합성 형상·진단 시계·screening 경계를 provider가 명시함 |
| `termination_leaves_declared_inventory_residual` | 방출 종료시점에 재고가 남아 있어 전량 방출로 볼 수 없음 |

`BLOCKED_REVIEW`는 계산 실패라는 뜻이 아니다. 방출 packet과 피해 chain을 진단 목적으로 계산했지만, 실제 시설 QRA의 입력으로 승격하기 위한 증거가 더 필요하다는 뜻이다.

## 현재 native 일반 LH2 결과

재현 명령:

```powershell
python scripts/audit_provider_worklist_packet_evidence.py `
  --provider-worklist results/20261024/native_generic_scope_worklist_with_native_binding_v1.json `
  --results-root results `
  --output results/20261024/native_generic_scope_packet_evidence_qualification_readiness_v14.json
```

결과:

| 항목 | 값 |
|---|---:|
| worklist 사건 | 24 |
| 후보 사건 | 24 |
| exact/strict packet | 24 |
| qualification-ready | 0 |
| `BLOCKED_REVIEW` | 24 |
| input origin `model_prediction` | 24 |
| consequence-chain 기록 | 24 |
| qualification sidecar | 0 |
| 독립 물리검증 evidence | 0 |
| 빈도 자동 연결 | 없음 |
| 시설 IR/F-N 승격 | 없음 |

24개 모두에서 `qualification_sidecar_missing`, `physical_validation_evidence_missing`, `operator_limited_input`, `synthetic_or_screening_boundary_declared`가 남는다. 저장탱크·기화기·벤트·재액화기 일부 사건에서는 종료시점 재고가 남는다는 추가 사유도 별도 기록된다. 양단 파열은 두 endpoint를 exact-match한 뒤 동일한 준비도 감사에 들어간다.

이 결과를 완료감사에 연결한 최신 기록은 `results/20261024/ijhe_completion_audit_native_generic_scope_vertical_v19.json`이다. 완료감사는 34개 검사 중 30개를 통과하고 4개 승격 차단을 유지한다. packet readiness 정보가 들어와도 exact packet identity와 qualified actual evidence를 같은 것으로 취급하지 않는다. 상태장부 대조 `results/20261024/ijhe_status_consistency_v10.json`도 `CONSISTENT`이며 시설 IR/F-N 승격은 false다.

## 다음 입력 계약

각 시설 사고 사건을 승격하려면 provider가 실제 설비 상태와 사고 경계로 packet을 다시 내보내고, 별도 qualification sidecar에 다음을 제공해야 한다.

1. `event_id`, `component_id`, 사고 port, 개구와 위치·방향의 exact identity
2. provider source/result SHA-256 digest
3. 시작·종료시계와 종료 이유, 초기·최종 재고와 질량·에너지 잔차
4. 실제 형상·기상·차단 입력의 provenance
5. `prism.provider_qualification_evidence.v1`의 evidence ID
6. 방출 경계에 대한 독립 물리검증 또는 명시적 검증 공백

이 자료가 들어오면 기존 `scripts/build_provider_packet_evidence.py`와 `scripts/audit_provider_catalog_coverage.py`가 exact digest를 다시 확인한다. 준비도 감사의 `BLOCKED_REVIEW`가 자동으로 `qualified_actual`로 바뀌지는 않는다.


이번 보완에서 감사기는 `provider_qualification.json`/`qualification.json`과 `physical_validation.json`/`physical_validation_evidence.json`/`validation.json` sidecar를 자동 인식한다. 응답에 포함된 qualification도 같은 규칙으로 검사하며, event·component·port와 provider source/result digest가 모두 맞을 때만 sidecar 존재로 기록한다. 불일치 sidecar는 누락과 구분된 차단 사유로 남고, 이 검사는 빈도나 시설 QRA를 자동 승격하지 않는다.
