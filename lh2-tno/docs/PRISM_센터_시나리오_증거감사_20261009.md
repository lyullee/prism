# 액화수소검사지원센터 시나리오·시계열 증거 감사

2026-10-09에 `scripts/audit_center_scenario_evidence.py`로 프로젝트 폴더를 읽기 전용 감사했다.
이 감사는 센터 전용 모델을 PRISM 일반 설비 모델로 승격하는 작업이 아니다. CSV의 사고 후보 설명과 Excel의 운전 상태 이력을 보존하고, 방출 packet으로 승격할 때 필요한 누락 필드를 명확히 하는 단계다.

## 확인된 자료

- 사고·운전 시나리오 CSV 3개, 52개 행
- 시계열·운전 Excel 17개
- sequence 시트 21개, time-series 시트 43개
- CSV에서 확인한 후보 사고 가족: `pipe_hole` 11, `valve_hole` 23, `vaporizer_hole` 4, `vent_hole` 4, `vessel_hole` 1, `inventory_over_600s` 1
- 파일 해시와 상대 경로는 `results/20261009/provider_evidence/center_scenario_evidence_audit.json`에 저장했다.

자료에는 플랜지 연결, 벤트 개방·폐쇄, 압력 상승 감시, 공급 개시, 주 배관 개방, 기화기 통과와 같은 위험 후보가 선언되어 있다. 일부 Excel에는 압력·온도·차압 시계열도 있다. 이 정보는 설비 상태와 사고 후보를 정하는 데 사용할 수 있다.

## PRISM 승격 판정

현재 `qualified_packet_count`는 **0**이다. 센터 자료의 행·시트는 다음 provider 사고 packet 필드를 갖고 있지 않다.

- `provider_export_schema`, 사고 종류와 고유 사건 ID
- 설비·포트·ENU 위치·방출 방향
- 시간별 질량 유량과 실제 종료시각
- 사용 가능 재고·누적 방출 질량·질량/엔탈피 폐합
- provider가 소유한 종료 근거와 결과 digest

따라서 시나리오의 `누출_위험`, `화재_위험`, `폭발_위험` 문장이나 PT/TT/DPT 시계열을 방출량으로 바꾸지 않았다. 문헌 빈도도 부여하지 않았다. 해당 자료는 `SCENARIO_ONLY_PROVIDER_PACKET_MISSING`으로 남긴다.

## 다음 입력 계약

센터 또는 다른 일반 액화수소 설비 모델이 실제 사고 방출을 계산하면, 시나리오 행의 후보 family와 실제 component/port를 대조한 뒤 `prism.resolved_release.v1` 또는 양단 파열의 `prism.resolved_release_set.v1` packet을 내보내야 한다. 그때 PRISM은 개구·재고·시간·종료를 strict 검증하고 `FrequencyPlan`과 exact-match한 사건만 SLABx-LH2→점화→피해→IR/F-N으로 보낸다. 나머지는 계속 `UNCOMPUTED`로 기록한다.

재현 명령:

```powershell
python scripts/audit_center_scenario_evidence.py `
  --source-root "<액화수소검사지원센터 데이터>" `
  --output results/20261009/provider_evidence/center_scenario_evidence_audit.json
```
