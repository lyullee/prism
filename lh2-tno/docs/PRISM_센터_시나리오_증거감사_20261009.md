# 액화수소검사지원센터 시나리오·시계열 증거 감사

2026-10-09에 `scripts/audit_center_scenario_evidence.py`로 프로젝트 폴더를 읽기 전용 감사했다.
이 감사는 센터 전용 모델을 PRISM 일반 설비 모델로 승격하는 작업이 아니다. CSV의 사고 후보 설명과 Excel의 운전 상태 이력을 보존하고, 방출 packet으로 승격할 때 필요한 누락 필드를 명확히 하는 단계다.

## 확인된 자료

- 사고·운전 시나리오 CSV 3개, 52개 행
- 시계열·운전 Excel 17개
- sequence 시트 21개, time-series 시트 43개
- 43개 시트에서 timestamp/일시 시간축과 PT·TT·DPT 같은 센서 열을 확인
- 시간축을 해석할 수 있었던 시트는 43개이며, 관측된 중앙 샘플 간격은 1초 7개, 60초 26개, 900초 10개
- CSV에서 확인한 후보 사고 가족: `pipe_hole` 11, `valve_hole` 23, `vaporizer_hole` 4, `vent_hole` 4, `vessel_hole` 1, `inventory_over_600s` 1
- 파일 해시와 상대 경로는 `results/20261009/provider_evidence/center_scenario_evidence_audit.json`에 저장했다.

자료에는 플랜지 연결, 벤트 개방·폐쇄, 압력 상승 감시, 공급 개시, 주 배관 개방, 기화기 통과와 같은 위험 후보가 선언되어 있다. 일부 Excel에는 압력·온도·차압 시계열도 있다. 이 정보는 설비 상태와 사고 후보를 정하는 데 사용할 수 있다.

시계열의 시간축과 센서 열은 읽기 전용으로 확인했다. 샘플 간격은 센서 상태가 얼마나 자주 기록됐는지를 보여주는 관측값일 뿐, 누출 빈도나 누출 크기를 뜻하지 않는다. 시간축에 날짜가 없는 `00:00` 같은 값은 시간대만 보존했으며 실제 달력 날짜를 추정하지 않았다. 센서 열에는 설비 ID·센서 위치·압력 기준(게이지/절대)·provider 방출 소유권이 붙어 있지 않아 43개 후보 시트를 모두 `TELEMETRY_CANDIDATE_METADATA_INCOMPLETE`로 남겼다.

## PRISM 승격 판정

현재 `qualified_packet_count`는 **0**이다. 센터 자료의 행·시트는 다음 provider 사고 packet 필드를 갖고 있지 않다.

- `provider_export_schema`, 사고 종류와 고유 사건 ID
- 설비·포트·ENU 위치·방출 방향
- 시간별 질량 유량과 실제 종료시각
- 사용 가능 재고·누적 방출 질량·질량/엔탈피 폐합
- provider가 소유한 종료 근거와 결과 digest

따라서 시나리오의 `누출_위험`, `화재_위험`, `폭발_위험` 문장이나 PT/TT/DPT 시계열을 방출량으로 바꾸지 않았다. 문헌 빈도도 부여하지 않았다. 해당 자료는 `SCENARIO_ONLY_PROVIDER_PACKET_MISSING`으로 남긴다.

## provider packet 요청 catalog

후속 provider 작업을 명확히 하기 위해 `scripts/build_provider_packet_request_catalog.py`가 후보 family가 있는 시나리오 38행을 `prism.provider_packet_request_catalog.v1` 작업 목록으로 변환한다. 각 요청에는 원본 파일·행·설비·운전단계의 provenance, 후보 사고 family, 필요한 `prism.resolved_release.v1` 필드와 family별 종료 조건이 들어간다. 이 결과는 방출 packet 자체가 아니며 `promotion_status=REQUESTED_PROVIDER_PACKET`, `frequency_assigned=false`, `qualified_packet_count=0`을 유지한다.

현재 catalog의 후보 요청 수는 `pipe_hole` 11, `valve_hole` 23, `vaporizer_hole` 4, `vent_hole` 4, `vessel_hole` 1, `inventory_over_600s` 1이다. 한 행이 두 family 후보를 가질 수 있으므로 family 합계와 요청 행 수는 다를 수 있다. 산출물은 `results/20261009/provider_evidence/center_provider_packet_request_catalog.json`이다.

이 감사 결과는 센서 기반 빈도 학습을 추가하지 않는다. 실시간 연결을 하려면 먼저 센서 열을 일반 설비 모델의 `component_id`·`port_id`·위치·물성 기준과 매핑하고, 그 모델이 시간별 질량유량·재고·종료근거를 가진 `prism.resolved_release.v1` 또는 `prism.resolved_release_set.v1` packet을 내보내야 한다. 그 뒤에만 PRISM의 resolver가 상태를 방출 경계로 전달한다.

## 다음 입력 계약

센터 또는 다른 일반 액화수소 설비 모델이 실제 사고 방출을 계산하면, 시나리오 행의 후보 family와 실제 component/port를 대조한 뒤 `prism.resolved_release.v1` 또는 양단 파열의 `prism.resolved_release_set.v1` packet을 내보내야 한다. 그때 PRISM은 개구·재고·시간·종료를 strict 검증하고 `FrequencyPlan`과 exact-match한 사건만 SLABx-LH2→점화→피해→IR/F-N으로 보낸다. 나머지는 계속 `UNCOMPUTED`로 기록한다.

재현 명령:

```powershell
python scripts/audit_center_scenario_evidence.py `
  --source-root "<액화수소검사지원센터 데이터>" `
  --output results/20261009/provider_evidence/center_scenario_evidence_audit.json

python scripts/build_provider_packet_request_catalog.py `
  --audit results/20261009/provider_evidence/center_scenario_evidence_audit.json `
  --output results/20261009/provider_evidence/center_provider_packet_request_catalog.json
```
