# PRISM 실증데이터 상태증거 연결 (2026-10-30)

## 목적

액화수소검사지원센터의 운전 자료를 사고빈도나 사고 방출 packet으로 바꾸지 않고,
설비 상태 snapshot이 실제 계측 자료에서 재현되는지 확인하는 진단 증거로 연결했다.
이 경계는 PRISM이 관측자료를 사용하면서도 현장 사고빈도를 학습했다고 잘못 해석하지
않도록 하기 위한 것이다.

## 결과

생성된 원장은 [`examples/inspection_center_observed_state_evidence.json`](../examples/inspection_center_observed_state_evidence.json)이며 다음을 기록한다.

- 상태: `OBSERVATION_STATE_EVIDENCE_ONLY`
- 원자료: 3개
- 관측 sample: 8,955개
- 연결 component: 3개
- canonical snapshot schema: `prism.equipment_state_snapshot.v1`
- 모든 관측 origin: `historian_measured`

이 원장은 completion audit의 `diagnostic_observed_equipment_state_evidence` 검사로 소비된다.
이번 연결은 최신 union completion audit의 36개 검사 중 31개 PASS·5개 BLOCKED 원장에
diagnostic 관측상태 근거로 반영되어 있다.
관측자료 검사는 diagnostic-only이며, 다음 정책을 원장에 고정한다.

| 정책 | 값 |

| 사고빈도 추정 | `false` |
| 센서 기반 빈도 학습 | `false` |
| provider packet 승격 | `false` |
| 독립 물리검증 주장 | `false` |
| 시설 IR/F-N 주장 | `false` |

## 재현 명령

Python bundled runtime 또는 `openpyxl`이 설치된 Python으로 다음을 실행한다.

```powershell
python scripts/audit_observed_equipment_state.py `
  --manifest examples/inspection_center_observed_state_manifest.json `
  --output examples/inspection_center_observed_state_evidence.json
```

전체 union 감사와 readiness report를 다시 만들 때는 `bind_native_full_scope_union_evidence.py`
호출에 다음 인자를 추가한다.

```text
--observed-state-evidence examples/inspection_center_observed_state_evidence.json
```

그 뒤 `CURRENT_STATUS.json`의 readiness·completion audit SHA-256 포인터를 갱신한다.
원자료가 이동했거나 해시가 달라지면 audit는 성공 상태를 유지하지 않고 입력 오류를
반환해야 한다.

## 해석 범위

이 자료는 intake·storage vent·supply/vaporizer boundary의 상태 범위를 보여 주는 실증
관측자료다. 배관 파열, 밸브 hole, 펌프 hole, 전량 방출, 차단 성공률, 방출 종료시간,
점화확률 또는 시설 인구·기상 분포를 관측자료만으로 산출하지 않는다. 따라서 문헌 빈도
원장과 native 사고 exporter의 방출·피해 계산을 대체하지 않으며, qualified provider
packet과 시설 전체 IR/F-N 승격도 열지 않는다.
