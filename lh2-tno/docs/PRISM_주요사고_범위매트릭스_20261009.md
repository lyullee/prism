# PRISM 주요 사고 범위 매트릭스 (2026-10-09)

## 목적

시설 위험 결과를 읽을 때 가장 먼저 확인해야 할 것은 “숫자가 나왔는가”가 아니라 “어떤 사고를 실제로 계산했는가”이다. `accident_scope.py`는 한 캠페인의 사건·방출 요청·계산 case를 주요 사고 가족으로 다시 분류한다. 이 보고서는 피해영향 계산기를 대신하지 않고, 선언한 옥외 액화수소 범위가 어디까지 연결되었는지 감사한다.

현재 기본 가족은 다음 12개다.

`vessel_hole`, `pipe_hole`, `valve_hole`, `vent_hole`, `pump_hole`, `vaporizer_hole`, `reliquefier_hole`, `liquid_two_phase`, `inventory_depletion`, `inventory_over_600s`, `two_sided_rupture`, `vertical_handoff`

각 행은 `EXECUTED`, `PARTIAL`, `UNCOMPUTED`, `NO_EVENT_GENERATED` 또는 물리 실행 실패 상태를 가진다. `NO_EVENT_GENERATED`는 계산 결과가 0이라는 뜻이 아니라 그 사고를 나타내는 빈도 사건을 만들지 않았다는 뜻이다. `PARTIAL`은 계산 결과가 일부 있어도 미계산·operator-limited·domain-incomplete case가 남아 있다는 뜻이다.

## 빈도 해석

`generated_initiation_frequency_per_year`는 해당 행에 분류된 문헌 빈도 사건의 합이다. 같은 사건이 `vessel_hole`과 `liquid_two_phase`처럼 여러 행에 걸릴 수 있으므로 행별 빈도를 합쳐 시설 빈도로 만들면 안 된다. 매트릭스는 이 원칙을 각 행의 `frequency_rows_are_not_additive_across_families`에 기록한다. 문헌 p05/p95는 별도 불확실성 실행에서 known contribution을 재가중하는 입력이며, 미계산 사고가 있는 시설의 전체 credible interval이 아니다.

## 실행 예

```powershell
python lh2-tno/scripts/build_accident_scope_matrix.py `
  --equipment-manifest lh2-tno/examples/equipment_manifest.json `
  --risk-campaign results/20261009/provider_release_full_chain_diagnostic/equipment_campaign.json `
  --result results/20261009/provider_release_full_chain_diagnostic/campaign_result.json `
  --output results/20261009/provider_release_full_chain_diagnostic/accident_scope_matrix.json
```

종료 코드가 0이어도 보고서의 `matrix_complete`와 `blocking_reasons`를 확인해야 한다. 현재 합성 provider 전체 경로 진단은 저장탱크 구멍·액체/2상·재고소진 행에 부분 결과가 있고, 배관의 미계산 사건과 밸브·벤트·펌프·증발기·재액화기·양단 파열·수직 handoff의 미생성 행이 남는다. 따라서 시설 전체 IR/F-N은 계속 보류된다.

## IJHE 제출용 사용 원칙

논문에는 사고 가족별 생성 사건 수, 실행 case 수, 미계산 이유, 시설 전체 위험도 승격 여부를 표로 제시한다. provider가 실제 사고 방출 packet을 내보내지 않은 경우에는 `NO_ACCIDENT_RELEASE_EXPORT`와 매트릭스의 미계산 행을 함께 보고하고, 합성 packet 결과를 현장 검증 결과처럼 쓰지 않는다. 이 표가 모두 `EXECUTED`가 되고 전체 시설 위험도와 독립 물리 검증 근거가 있을 때에만 선언 범위의 완결을 주장할 수 있다.
