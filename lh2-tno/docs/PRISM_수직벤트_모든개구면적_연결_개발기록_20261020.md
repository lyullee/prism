# PRISM 수직 벤트 모든 개구면적 연결 기록

## 목적

수직 벤트의 누출 크기 구간을 하나만 대표 계산하지 않고, 문헌 빈도표의 다섯 개 면적 구간을 각각 설비 provider 계산으로 만들고 PRISM의 방출→SLABx-LH2/SLABx→피해 chain에 연결한다. 이 기록은 일반 옥외 액화수소 시설에서 사용할 수 있는 진단 경로를 설명한다. 특정 검사센터의 설비나 현장 빈도를 코드에 고정하지 않는다.

## 이번 실행

실행 폴더는 `results/20261020/vertical_vent_all_bins/`이다. `AREA_0.01%`, `AREA_0.1%`, `AREA_1%`, `AREA_10%`, `AREA_100%`를 각각 별도 provider 입력으로 만들었다. 각 입력은 해당 면적에 맞는 개구 직경과 동일한 event ID를 사용한다. 따라서 작은 누출을 큰 누출 계산으로 대신하지 않는다.

그 결과 5개 사건과 두 기상 조건의 10개 case가 모두 provider vertical handoff를 소비했다. 각 case에는 provider source/result digest, 종료 시각, 방출 질량·에너지 장부, SLABx handoff 방향과 시계가 남는다. 최대 질량 잔차는 0 kg으로 기록됐다. 시설 namespace로 다시 연결한 결과는 `results/20261020/vertical_handoff_rebound_facility_result_all_bins.json`이다.

## 처리시간

새 물리 계산 case는 10건이다. 이 실행에서 case 처리시간은 최소 약 1.38초, 중앙값 약 1.87초, p95 약 3.12초, p99 약 3.18초였고 전체 campaign은 약 21.21초였다. 이 수치는 한 번 실행한 합성 진단의 측정치다. 반복 실행에 대한 서비스 수준이나 1 Hz 신규 물리 계산을 보장하지 않는다.

## 시설 결합 결과

새 vertical 결과를 기존 native packet, two-sided rupture, inventory depletion, isolation success/failure campaign과 함께 시설 원장에 결합했다.

- 41개 사건
- 70개 case
- 272개 risk atom
- 11개 예상 설비 component
- 조건부 worker-01 IR/F-N 진단값은 존재하지만 시설 전체 위험도 승격은 보류

최신 원장은 `results/20261020/native_campaign_with_vertical_all_bins_two_sided_inventory_isolation_facility_ledger.json`, 평가 요약은 `results/20261020/native_campaign_with_vertical_all_bins_two_sided_inventory_isolation_facility_assessment.json`이다. 사고범위 병합표는 `results/20261020/generic_vertical_all_bins_two_sided_inventory_isolation_merged_scope_matrix.json`이다.

저장소에 포함한 간결한 검토용 요약은 [`examples/vertical_all_bins_facility_summary.json`](../examples/vertical_all_bins_facility_summary.json)이다. 전체 원장과 평가 JSON은 재현 실행이 만든 결과 폴더에서 확인한다.

## 무엇이 해결됐나

이전에는 `AREA_100%`만 provider vertical handoff로 계산하고 나머지 네 면적을 미계산으로 남겼다. 이제 다섯 면적 모두 실제 provider 호출과 피해 chain 실행 기록이 있다. 병합 원장도 설비 campaign의 신선 물리 계산 건수와 case별 p95/p99 처리시간을 보존한다.

## 아직 완료로 부르지 않는 이유

다음 이유로 이 결과는 시설 전체 QRA가 아니라 조건부 진단이다.

1. vertical provider의 handoff와 종료 모델은 합성 입력이며 독립 물리검증이 없다.
2. 일부 case는 `EXECUTED_OPERATOR_LIMITED`이고 일부 사고 family는 여전히 `PARTIAL`이다.
3. 모든 현장 설비의 qualified 사고 방출 packet과 독립 검증 자료가 없다.
4. 현재 빈도는 문헌값이며 현장 사고빈도나 센서 학습값으로 바꾸지 않았다.
5. 시설 전체 IR/F-N은 위 조건이 모두 닫힐 때까지 `null`로 유지한다.

## 재현 명령

```powershell
python scripts/validate_vertical_vent.py --all-area-bins --output-dir results/20261020/vertical_vent_all_bins
python scripts/rebind_vertical_handoff_campaign.py `
  --vertical-result results/20261020/vertical_vent_all_bins/campaign_result.json `
  --facility-id generic-lh2-full-scope-example `
  --namespace generic-lh2-full-scope-example/vertical-handoff `
  --asset-id vertical-handoff-vent `
  --component-id vertical-handoff-terminal-pipe-01 `
  --receptor-map near_worker=worker-01 `
  --receptor-map downwind_worker=worker-01 `
  --receptor-map side_worker=worker-01 `
  --receptor-map distant_worker=worker-01 `
  --output results/20261020/vertical_handoff_rebound_facility_result_all_bins.json
```

원장 결합과 IJHE 감사의 최종 상태는 `results/20261020/ijhe_completion_audit_all_bins.json`에서 확인한다. 감사는 27개 검사를 수행하며 현재 차단 항목은 부분 사고범위와 시설 IR/F-N 보류 두 가지다.
