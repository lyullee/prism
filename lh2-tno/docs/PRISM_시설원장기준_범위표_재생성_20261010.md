# PRISM 시설 원장 기준 범위표 재생성 (2026-10-10)

## 발견한 문제

union 결과의 `scope_matrix.json`은 세 개의 원천 캠페인 범위표를 가족별로 합쳤고,
`facility_assessment.json`의 시설 원장은 실제로 병합된 case의 `scenario_families`를
사용했다. 두 장부가 서로 다른 층에서 만들어져 다음과 같은 표면 불일치가 생겼다.

| 사고군 | 기존 범위표 | 실제 시설 원장 | 원인 |
| --- | ---: | ---: | --- |
| `pipe_hole` | 10 event / 15 case | 15 event / 25 case | vertical handoff도 배관 누출 family로 태그됨 |
| `liquid_two_phase` | 21 event / 21 case | 17 event / 17 case | provider가 기체 경계에서 종료한 4개 packet은 2상 overlay를 제거함 |

이는 누출 계산을 새로 만든다는 뜻이 아니며, 원장에 실제로 들어간 사건과 case의
범위를 범위표가 그대로 보여주지 못한 장부 일관성 문제였다. 가족별 빈도 행은 서로
더하지 않는 view이므로, 이 차이를 임의로 합산해 시설 위험도를 키우면 안 된다.

## 수정 내용

`scripts/run_native_full_scope_union_assessment.py`는 union 후 `merge_scope_matrices`의
선언값을 그대로 저장하지 않고, 병합된 시설 원장을 먼저
`repair_facility_ledger_scenario_families`로 보완한 다음
`build_scope_matrix_from_facility_ledger`로 최종 범위표를 재생성한다.

이제 최종 범위표와 시설 원장은 같은 event ID·case ID·family tag를 기준으로 한다.
원천 캠페인 범위표는 `source_campaign_scope_matrices`에 digest와 함께 provenance로
남긴다. `EXECUTED_OPERATOR_LIMITED`는 수치 계산이 끝났어도 적격 근거가 보류된
상태이므로 `PARTIAL`과 strict gate를 그대로 유지한다.

`facility_scope_matrix`의 행에는 `fully_validated_case_count`,
`operator_limited_case_count`, `domain_incomplete_case_count`, `failed_case_count`를
명시해 evidence request와 union 검증 요약이 같은 분해를 사용하게 했다.

## 현재 결과

2026-10-10 재생성 결과는 34 event·44 case이며 조건부 계산은 모두 이어진다.
`pipe_hole`은 15 event·25 case, `liquid_two_phase`는 17 event·17 case로
시설 원장과 일치한다. 원장-범위표 일관성 감사는 `CONSISTENT_SCOPE_LEDGER`가
되지만, operator-limited 입력과 실제 provider packet·물리 검증이 없는 사실은
변하지 않으므로 시설 전체 IR/F-N 또는 QRA 자격을 승격하지 않는다.

재현 명령은 [vertical handoff·inventory depletion union 기록](PRISM_native_일반LH2_vertical_handoff_union_20261026.md)의
union 명령을 사용한다. 독립 감사는 다음과 같이 실행한다.

```powershell
python scripts/audit_scope_ledger_consistency.py `
  --scope-matrix results/20261026/native_full_scope_union_assessment/scope_matrix.json `
  --facility-ledger <facility_risk_ledger.json> `
  --output <scope_ledger_consistency.json>
```

`<facility_risk_ledger.json>`은 `facility_assessment.json` 안의
`facility_risk_ledger` 객체를 추출한 파일이어야 한다. 감사 결과의
`facility_qra_claim`은 계속 `false`다.
