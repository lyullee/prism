# PRISM 설비 모델 결합 계약

이 문서는 일반 옥외 액화수소 설비의 공정 모델을 PRISM에 연결할 때, 부품별로 무엇이 이미 연결되고 무엇이 아직 사고 방출 packet으로 연결되지 않았는지 기록한다. 특정 검사센터의 태그를 기본값으로 사용하지 않는다.

## 감사 명령과 결과

```powershell
python scripts/audit_equipment_model_binding.py `
  --manifest examples/generic_lh2_full_scope_manifest.json `
  --binding examples/generic_lh2_native_model_binding.json `
  --output results/20261009/equipment_manifest_audit/model_binding_audit.json
```

2026-10-09의 최초 카탈로그 결과는 `STATE_ONLY_BOUND`였다. 외부 `lh2dt_models` 클래스는 연결됐지만 사고 export 필드가 `missing`으로 남아 있었다.

2026-10-14 이후에는 외부 모델의 native 사고 export와 PRISM 쪽 진단 adapter를 별도 필드로 기록한다. 소스 감사에서 저장탱크·배관·밸브·벤트·펌프·기화기·재액화기 7개 모두 `export_accident_history(request)`가 확인됐고, PRISM 카탈로그는 이를 `examples/generic_lh2_native_model_binding.json`에 `supported`로 선언한다. 이 선언은 strict adapter로 변환할 수 있는 인터페이스가 있다는 뜻이며 qualified provider 종료·현장 geometry·현장 빈도·자격 packet이 생겼다는 뜻은 아니다. 경계 컴포넌트는 사고 빈도 대상이 아니므로 별도 인터페이스로 남긴다. `results/20261022/native_binding_reconciliation.json`은 두 장부가 7/7 일치하는지 확인하고, `provider_packet_promoted=false`, `frequency_inference_performed=false`, `facility_qra_claim=false`를 고정한다. 진단 adapter 결과의 `synthetic_diagnostic`/`screening_only` 근거는 사고 packet·빈도·시설 IR/F-N으로 승격하지 않는다.

## PRISM으로 넘어가는 데이터

정상 상태는 압력·온도·액면·유량·상·제어 상태처럼 `validate_equipment_process_state()`가 허용하는 상태 snapshot으로만 전달한다. 이 snapshot에는 누출 크기, 사고 지속시간, 재고 소진, 빈도, `ResolvedGasRelease` 또는 `ResolvedLiquidRelease`가 들어갈 수 없다.

사고 계산을 시작하려면 외부 모델이 별도 사고 계산을 수행하고 다음 정보를 포함한 `prism.resolved_release.v1` packet을 내보내야 한다.

- 실제 사고 포트와 component ID
- 시간별 방출 유량과 실제 종료시각
- 질량·엔탈피 장부
- 차단 성공·실패 branch와 근거
- 액체·2상인 경우 flash 기체·지상 액체·액적 분할
- 문헌 `FrequencyPlan`과 exact-match할 실제 개구

이 packet이 도착하면 PRISM은 packet을 strict 검증하고, 빈도를 별도로 붙인 뒤 SLABx-LH2/SLABx → 점화 → 피해 → IR/F-N으로 보낸다. 모델 클래스 이름이나 정상 유량만으로 이 packet을 만들지 않는다.

이번 단계에서 `src/lh2_tno/equipment_release_adapter.py`를 추가해 provider 응답을 packet으로 변환하는 경계를 한 곳으로 통합했다. `scripts/validate_equipment_campaign.py`, `scripts/validate_equipment_isolation.py`, `scripts/validate_equipment_inventory.py`는 이제 같은 어댑터를 사용한다. 어댑터는 provider가 선언한 시간 이력·종료 근거·질량·엔탈피 장부를 그대로 검증하고, 필드 누락·정상 vent·장부 불일치를 거부한다. 이는 PRISM 쪽 변환 계약을 완성한 것이며, 외부 `lh2dt` 모델이 사고 packet을 직접 export한다는 뜻은 아니다.

## 현재 결론

설비별 공정 모델의 **상태 결합 경로, native 사고 export 인터페이스, PRISM-side packet 변환 계약은 확인**되었다. `native interface`는 외부 클래스가 방출 이력과 종료·질량 장부를 반환할 수 있다는 뜻이다. 현장 설비 geometry·차단 순서·실측 상태와 결합된 실제 provider packet catalog는 **아직 완료되지 않았다**. 그래서 IJHE 완료 감사의 실제 provider packet·주요 사고 범위·시설 IR/F-N gate는 계속 차단된다.

재현 보고서에는 manifest digest `ca0add67a1148e4a184b132e97864b14e70146c4415b2cac2aebaacb105f694c`와 현재 binding catalog SHA-256 `0756BC3B172F88263E9ECC3594DEE818478D5A9D10C2397790BB960A17ED2025`가 저장된다. 이전 catalog digest `599003e609d18b034b401593df54153f75ee10c93cac8a22909f7a40f0f40f89`는 native 외부 모델만 기록하던 스냅샷이다.

## 2026-10-14 공통 adapter 실행기

설비 종류와 adapter 파일을 실제 실행 단계에서 연결하기 위해 `src/lh2_tno/diagnostic_adapter_runner.py`를 추가했다. `DiagnosticAdapterRunner.from_binding_catalog()`가 catalog의 7개 진단 adapter를 읽고, `resolve_provider_class()`가 각 클래스에 공통 `export_accident_history(request)` 메서드가 있는지 확인한다. host가 설비별 provider 인스턴스를 `register_provider()`로 명시적으로 등록해야만 `execute()`가 gas/liquid/inventory/emergency-relief strict export 경계를 호출한다. provider 생성자와 사고 조건은 자동으로 만들지 않는다.

실행 감사 `results/20261014/diagnostic_adapter_registry_audit_live.json`에서 7/7 adapter 클래스 해석과 메서드 확인에 성공했다. provider 인스턴스는 0개이고 qualified packet도 0개이므로, 이 결과는 실행 계약 연결을 검증한 것이며 사고빈도·시설 IR/F-N·현장 물리 검증을 의미하지 않는다. 상세 사용법과 승격 조건은 [공통 실행기 개발기록](PRISM_설비진단_adapter_공통실행기_개발기록_20261014.md)에 기록했다.
## 2026-10-24 상태 보정

외부 모델 소스 감사가 갱신되어 7개 설비 클래스의 native `export_accident_history(request)` 메서드와 종료·질량 원장이 확인됐다. 최신 감사 [`native_equipment_model_binding_audit_v1.json`](../results/20261024/native_equipment_model_binding_audit_v1.json)은 8개 manifest component를 읽어 사고 방출 인터페이스 7개, 진단 adapter 7개, qualified accident-release component 0개를 분리 기록한다. 경계 component가 state-only이므로 전체 상태는 `STATE_ONLY_BOUND`로 표시되지만, 이는 7개 native 사고 인터페이스가 없다는 뜻이 아니다. native method와 합성 adapter는 호출 계약의 증거이며, 실제 시설 입력·provider 자격·독립 물리검증·시설 IR/F-N을 승격하지 않는다.
