# PRISM 외부 LH2 현장자료 입력 계약

## 목적

PRISM이 외부 액화수소 실증자료를 읽을 수 있는 최소한의 공통 형식을 추가했다. 이 기능은 실증자료를 곧바로 위험도나 사고빈도로 바꾸지 않는다. 먼저 **방출원, 날씨, 장애물, 수소 농도 관측, 공통 시계**가 같은 사건을 가리키는지 확인하고, 나중에 SLABx-LH2 계산 결과와 비교할 수 있도록 증거의 경계를 고정한다.

## 확인한 자료

`DEGALI_TRANSFER_2026-09-21` 아래의 PRESLHY E35 Trial 10 묶음을 입력으로 확인했다.

- 방출원 자료: 208행
- 날씨 자료: 92행
- 수신기 농도 관측: 5,053행
- 장애물 형상과 공통 시계 JSON 존재
- 사건 ID: `preslhy-e35-trial-10-2019-09-13`
- 범위: 야외 LH2 자유장(`lh2_free_field`)

입력 어댑터는 각 파일의 경로·SHA-256·열 이름·행 수·사건 ID를 기록한다. 원자료를 PRISM 저장소로 복사하지 않고 원본 경로와 요약만 남긴다.

`source_boundary.csv`에 `time_s`와 `mass_flow_kg_s`가 있으면 어댑터는 관측
시계와 방출량을 추가로 요약한다. 최신 Trial 10 재검사에서는 208개 시료,
관측창 207 s, 양의 유량 시료 시작 2 s, 관측시계 사이의 left-held 질량
적분 27.506655159 kg을 기록했다. 마지막 시료 이후의 유량은 연장하지 않는다.
이 값은 측정 source-term 비교를 위한 관측 연산자이며 provider 방출 종료,
초기·최종 재고, 차단 성공을 뜻하지 않는다. 해당 세 근거는 모두 명시적으로
`false`로 남는다.

## 현재 판정

현재 원본 매니페스트가 선언한 해시와 실제 세 파일의 바이트가 일치하지 않는다.

- `source_boundary.csv`
- `weather.csv`
- `common_clock.json`

따라서 엄격한 해시 검증 실행은 중단되며, 진단용 `--skip-hash-verification` 실행은 상태를 `RESTRICTED_EXTERNAL_FIELD_EVIDENCE_HASH_DRIFT`로 기록한다. 이 결과는 자료의 구조와 행 수를 확인했다는 뜻이지, 데이터가 변하지 않았다는 뜻이 아니다. 해시 드리프트가 해소되기 전에는 검증 매트릭스에 물리검증 근거로 올리지 않는다.

이 제한 상태를 IJHE 목표 감사에도 연결했다. 다음 감사 결과에는 기존 15개 핵심·엄격 게이트와 별도로 `diagnostic_external_outdoor_field_evidence` 행이 추가된다.

```powershell
python scripts/build_ijhe_objective_coverage_audit.py `
  # 기존 2026-10-31 통합 감사 입력은 생략하지 않고 그대로 전달한다 `
  --external-field-evidence results/20261103/external_field_evidence/preslhy_trial10_unverified.json `
  --output results/20261103/ijhe_objective_coverage_audit_with_external_field.json
```

현재 결과는 `CONDITIONAL_DIAGNOSTIC_COMPLETE_STRICT_GATES_OPEN`이며 17개 행, 핵심 차단 0개, 엄격 차단 4개다. 외부자료 행은 `PASS`로 기록되지만 관측 구조·정책을 확인한 것뿐이다. `source_boundary`·`weather`·`common_clock`의 해시 drift, `model_comparison_ready=false`, `physical_validation_claim=false`, `frequency_inference_performed=false`, `facility_qra_claim=false`가 함께 남아 있다. 따라서 이 행은 기존 물리검증·provider·시설 QRA 게이트를 통과시키지 않는다.

$env:PYTHONPATH = ".;src"

원본 매니페스트의 해시가 아직 정리되지 않은 상태에서 구조를 진단할 때만 다음 옵션을 사용한다.

```powershell
python scripts/audit_external_field_evidence.py `
  --manifest "C:\path\to\field-evidence-manifest.json" `
  --output results/20261103/external_field_evidence/preslhy_trial10_unverified.json `
  --skip-hash-verification
```

## PRISM에서 허용되는 사용 범위

허용되는 것은 다음뿐이다.

1. 방출 질량유량과 수신기 농도 관측의 사건 ID·시간축 연결 확인
2. SLABx-LH2의 같은 방출 조건 계산 결과와 관측자료를 비교할 입력 준비
3. 날씨와 장애물 형상을 모델 비교 조건으로 기록
4. 행 수, 파일 해시, 시간창, 센서 식별자 등의 재현성 기록

다음 결과는 이 자료만으로 만들지 않는다.

- 설비 사고빈도 또는 센서에서 역산한 누출빈도
- 공급자(provider)의 사고 방출 패킷 자격
- 점화 확률, 화재·폭발 결과, IR/F-N 곡선
- 시설 전체 QRA의 완결 판정
- `physical_validation_claim=true` 또는 `full_chain_validation_claim=true`

SLABx-LH2 자료도 현재는 제한된 성능·구성요소 근거다. 관측자료와 동일한 방출 경계, 기상, 센서 시간 연산자를 가진 모델 결과가 별도로 만들어져야 `model_comparison_ready`를 열 수 있다. 그 뒤에도 독립 검증과 설비별 provider packet 심사가 필요하다.

## 모델-관측 비교 계약

이번에 `prism.external_field_model_comparison.v1` 비교 장부를 추가했다. 모델 결과는 다음을 별도 JSON으로 내보내야 한다.

- `event_id`, `common_clock_id`, `receptor_geometry_id`
- 관측자료의 `coordinate_reference`와 동일한 좌표계 선언
- 센서 ID별 `position_enu_m`과 `concentration_history[*].h2_volume_percent`
- `time_alignment.method` (`exact` 또는 `linear`), 명시된 `transport_delay_s`, `prediction_time_offset_s`
- `source_boundary_binding.mode` (`independent_model` 또는 `measured_source_replay`)
- 모델이 사용한 방출자료의 SHA-256과 provider release 계약 검증 여부

비교기는 좌표계와 센서 위치를 허용오차 안에서 다시 확인하고, 관측시각에서 선언된 운반지연과 시간 오프셋을 뺀 시각만 모델 이력에서 찾는다. 예측 구간 밖으로 외삽하지 않으며, 시간·센서·사건·좌표계가 맞지 않으면 실패하거나 `BLOCKED_NO_MATCHED_SAMPLES`로 남긴다. 계산되는 지표는 표본 수, 센서 수, bias, MAE, RMSE, 최대 절대오차, 관측·예측 peak이다.

```powershell
$env:PYTHONPATH = ".;src"
python scripts/compare_external_field_model.py `
  --field-evidence results/20261103/external_field_evidence/preslhy_trial10.json `
  --model-prediction C:\path\to\prism.external_field_model_prediction.v1.json `
  --output results/20261103/external_field_model_comparison/preslhy_trial10.json
```

`measured_source_replay`는 관측 방출을 다시 넣어 본 진단이므로 독립 물리검증이 아니다. 해시 drift가 있는 현 자료에서는 비교 결과도 `RESTRICTED_FIELD_MODEL_COMPARISON_HASH_DRIFT`로 제한된다. 비교가 수치적으로 끝나도 `physical_validation_claim`, `full_chain_validation_claim`, `facility_qra_claim`, `frequency_inference_performed`는 모두 `false`이며, 별도 독립 모델·원자료 해시 정리·IJHE 증거심사가 있어야 검토 후보가 된다.

### 좌표방향 감도 진단

현장 공개자료는 `source-relative metres`라고만 선언하고 x·y의 방위축을 제공하지 않는다. 그래서 같은 방출 이력에 방출방위만 286°, 106°, 135°, 45°로 바꾼 별도 진단을 수행했다. 결과는 [`preslhy_trial10_orientation_sweep_unverified.json`](../results/20261103/external_field_model_comparison/preslhy_trial10_orientation_sweep_unverified.json)에 있다.

| 방출방위 | 예측 peak (vol%) | RMSE (vol%) | 해석 |
|---:|---:|---:|---|
| 286° | 0.00 | 31.1029 | 모든 센서 예측이 0으로 남아 방향 불일치 진단 |
| 106° | 33.05 | 30.8354 | 농도 신호는 생기지만 peak가 낮음 |
| 135° | 28.27 | 28.4666 | 네 방향 중 RMSE가 가장 낮지만 여전히 제한된 재생 |
| 45° | 33.64 | 30.7544 | 농도 신호는 생기지만 peak가 낮음 |

이 표는 방출방위를 관측자료에 맞춰 선택한 결과가 아니다. 축 정의를 모르는 상태에서 가능한 규약 차이를 드러낸 것이며, 방향을 최적화하거나 물리검증을 주장하지 않는다. 원자료 제공자가 축 정의를 확인하거나 독립 모델이 같은 좌표계로 결과를 내야 다음 게이트로 이동할 수 있다.

PRESLHY Trial 10에 대한 현재 재생 결과는 [`preslhy_trial10_replay_prediction.json`](../results/20261103/external_field_model_comparison/preslhy_trial10_replay_prediction.json)과 [`preslhy_trial10_replay_unverified.json`](../results/20261103/external_field_model_comparison/preslhy_trial10_replay_unverified.json)에 남겼다. 31개 센서의 위치 오차는 0 m였고, 5,053개 관측 중 4,960개가 매칭되었다. 그러나 측정 질량유량을 고정 기체 경계로 재생한 진단은 예측 peak 0 vol%, 관측 peak 87.7818 vol%, RMSE 31.1029 vol%를 보였다. 비교 장부는 이 조건을 `coordinate_orientation_review_required=true`로 표시하고, 현장 공개자료에 방위축 정의가 없다는 점과 PRISM 재생에서 사용한 풍향·방출방향 가정을 함께 기록한다. 이는 현재 재생 가정이 현장 농도장을 설명하지 못한다는 결과이며, 모델 검증 통과가 아니다. 원시 전체 chain 결과는 외부 임시 보관물의 SHA-256으로만 연결되어 있다.

비교 장부를 검증근거 매트릭스에 넣으면 해시 drift 때문에 `EVIDENCE_MATRIX_REVIEW_REQUIRED`가 된다. 이 상태는 자료 구조·비교 수치·제한 정책은 기록됐지만, 원자료 무결성과 독립 물리검증 게이트가 열리지 않았음을 뜻한다.

## 개발 게이트와 다음 작업

현재 외부자료 입력 게이트는 작동하지만 해시 드리프트로 닫혀 있다. 다음 작업은 원자료 제공자가 세 파일을 재발행하거나 매니페스트를 재생성해 해시를 일치시키는 것이다. 일치 후에도 다음 IJHE 게이트는 별도로 남는다.

- 실제 설비별 방출 경계와 차단·재고 소진 자료
- 설비별 provider qualification sidecar
- 공통시계·센서 기하·운반지연이 고정된 독립적인 SLABx-LH2 또는 실험 비교
- 시설 전체 사고빈도·점화·IR/F-N 연결

이 기록의 의도는 외부 실증자료가 있다는 이유만으로 전체 위험평가가 끝났다고 표시하지 않고, 자료가 실제로 뒷받침하는 범위만 PRISM에 전달하는 것이다.
