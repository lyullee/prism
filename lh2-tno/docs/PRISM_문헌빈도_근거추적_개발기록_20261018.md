# PRISM 문헌 빈도 근거 추적 개발 기록 (2026-10-18)

## 무엇을 추가했는가

`src/lh2_tno/frequency.py`가 만든 각 initiating event에는 이미 문헌 프로파일, 출처 문자열, 원자료 SHA-256, 카탈로그 digest, 중앙값과 p05/p95 범위가 들어 있다. 이번 보완에서는 이 값을 사건별로 다시 모아, **어떤 설비의 어떤 누출구간이 어떤 문헌 출처와 연결되었는지** 한 파일에서 추적할 수 있게 했다.

```powershell
python scripts/build_frequency_provenance_report.py `
  --manifest examples/generic_lh2_full_scope_manifest.json `
  --frequency-plan examples/generic_lh2_full_scope_frequency_plan.json `
  --output results/20261018/generic_lh2_frequency_provenance_current.json
```

현재 일반 LH2 예제의 보고서는 `results/20261018/generic_lh2_frequency_provenance_current.json`에 생성되며, 7개 설비 빈도 프로파일과 24개 사건 행을 기록한다.

외부 bridge 결과의 사건을 같은 provenance 보고서에 넣을 때는 다음처럼 명시적인
handoff 출처를 함께 전달한다.

```powershell
python scripts/build_frequency_provenance_report.py `
  --manifest examples/generic_lh2_full_scope_manifest.json `
  --frequency-plan examples/generic_lh2_full_scope_frequency_plan.json `
  --precomputed-events examples/external_frequency_event_catalogue.json `
  --precomputed-events-provenance "legacy taxonomy bridge; source SHA-256 recorded in event rows" `
  --output results/20261107/external_frequency_provenance.json
```

JSON이 객체이면 `events` 배열을 읽고, 배열이면 그대로 읽는다. PRISM은 이 행을
복사하거나 재계산하지 않고 exact replay를 확인한다.

## 보고서가 확인하는 것

1. 매니페스트가 `EXECUTABLE`인지 확인한다. 좌표, 물성, 포트가 빠진 설비는 빈도 사건을 만들지 않는다.
2. 빈도 계획의 프로파일이 패키지된 검토 카탈로그에 실제로 존재하는지 확인한다.
3. 프로파일의 `source_sha256`가 카탈로그의 `source_files`에 등록된 원자료 해시인지 확인한다.
4. 생성된 사건의 `catalogue_digest`가 같은 카탈로그 snapshot을 가리키는지 확인한다.
5. 계획에 선언된 각 프로파일이 실제 event row를 생성했는지 확인한다.
6. 현장 사고 등록부나 센서 경보를 빈도 보정으로 사용했는지 여부를 명시적으로 `false`로 기록한다.

외부 legacy/TNO 사건을 `FrequencyPlan.precomputed_events`로 연결한 경우에는
패키지 카탈로그 digest와 외부 사건 digest를 억지로 같게 비교하지 않는다. 외부
generator가 만든 event row를 그대로 재생했는지, 각 row의 source/source SHA/event
catalogue digest와 plan의 handoff provenance가 존재하는지를 별도 검사한다. 보고서의
`frequency_plan.event_generation_mode`는 `external_precomputed`,
`external_event_catalogue.frequency_arithmetic_owner`는
`external_precomputed_event_generator`로 기록된다. 이 구분은 외부 빈도를 현장
빈도나 센서 학습으로 승격하지 않으며, 이후에도 provider 방출·물리검증·시설 QRA
gate를 닫아 두기 위한 것이다.

구조 검사가 통과하면 상태는 `PASS_WITH_SCOPE_LIMITATIONS`이다. 이는 문헌 출처와 계산 연결이 보존됐다는 뜻이며, 실제 설비의 개수·길이·분류와 LH2 현장 검증이 끝났다는 뜻은 아니다. 해시가 맞지 않거나 이벤트가 생성되지 않으면 `FAILED_PROVENANCE_INTEGRITY`로 종료한다.

## 현재 문헌 근거와 한계

- TNO Purple Book 기반 일반 설비 프로파일은 패키지 카탈로그의 원자료 PDF 해시를 보존한다.
- LH2 5개 flow-area bin은 Brooks, Ehrhart & LaFleur (2021) Table 2의 snapshot과 `SAND2021-11595C` 식별자를 보존한다. 원자료 연결은 카탈로그에 기록된 DOI/보고서 URL과 SHA-256으로 추적한다.
- p05/p95는 각 event의 주변분포 범위다. 사건 간 상관을 모르는 상태에서 합산한 값은 시설 전체 credible interval이 아니다.
- 현재 입력 매니페스트는 합성 예제다. 실제 시설에서는 탱크·배관·밸브·펌프·벤트·열교환기 측면과 노출 길이를 검토한 뒤 같은 보고서를 다시 생성해야 한다.
- 현장 빈도 수집과 센서 기반 빈도 학습은 사용하지 않는다. 사고가 이미 관측된 경우에도 그 신호로 누출 크기나 initiating frequency를 역추정하지 않는다.
- 물리 검증 주장은 별도 gate로 남아 있으며 이 보고서의 `physical_validation_claim=false` 정책을 바꾸지 않는다.

이 기록은 IJHE 원고에서 빈도표를 재현할 때 사용할 provenance 표의 입력이다. 시설 전체 IR/F-N은 여전히 provider packet, 사고 범위, 실제 기하와 물리 검증 gate가 모두 충족될 때만 승격한다.
