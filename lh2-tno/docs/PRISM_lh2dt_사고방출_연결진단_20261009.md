# 외부 `lh2dt` 사고 방출 이력 연결 진단

## 목적

액화수소 설비 디지털트윈 프로젝트의 외부 `lh2dt_models`가 정상 공정상태와 유량을 계산하는 것을 확인한 뒤, 명시적인 탱크·밸브 고장 진단을 PRISM의 방출 이력 입력으로 내보낼 수 있는지 점검했다. 이 기록은 센터 설비의 사고 이력이나 현장 빈도를 만들기 위한 문서가 아니다. 외부 모델에 사고 방출 export 계약이 아직 없기 때문에, 합성 진단을 통해 필요한 연결 지점과 남은 물리 조정 항목을 재현하는 것이 목적이다.

## 확인한 외부 모델의 상태

외부 모델은 `HomogeneousTank`, `Valve`, 배관·네트워크·기화기·재액화기 등의 상태와 정상 유량 계산을 제공한다. 그러나 현재 소스와 문서에서 다음을 모두 갖춘 PRISM 사고 packet export API는 확인되지 않았다.

- 사고 원인과 고장 개구의 명시적 식별자
- 사고 시작 시각부터 실제 종료까지의 방출 이력
- 차단 성공·실패 또는 재고 소진에 따른 종료 근거
- 누적 질량·엔탈피 장부와 출구 위치·방향
- PRISM `provider_export_schema`와 exact component/port context

따라서 정상 유량 JSON이나 상태 snapshot을 사고 packet으로 바꾸지 않았다. 실제 설비의 24개 provider 요청도 여전히 `UNCOMPUTED_PROVIDER_PACKET`이다.

## 일반 LH2 작업목록과의 exact-match 진단

추가로 문헌 기반 일반 LH2 작업목록의 저장탱크 `AREA_0.01%` 사건을 선택해, 외부 `lh2dt.LayeredTankNetworkSimulator`가 계산한 양수 재고 threshold 이력을 브리지 인자에서 명시적으로 다음 경계에 연결했다.

| 항목 | 값 |
|---|---|
| event | `generic-lh2-full-scope-frequency-example/storage-shell/AREA_0.01%` |
| component | `storage-tank-01` |
| accident port | `tank-accident-out` |
| opening | `0.0127 m` |
| boundary | `resolved_atmospheric_liquid_exit` |
| provider model | `lh2dt.LayeredTankNetworkSimulator` |
| diagnostic duration | `0.001 s` |
| termination | positive inventory threshold (`inventory_depletion`) |

`audit_provider_catalog_coverage.py` 결과는 24개 사건 중 **1개 exact match, 23개 provider packet 부재**인 `PARTIAL_EXACT_MATCH`다. 이는 설비·포트·개구·경계 형식이 맞는지 확인하는 장부 단계다. provider의 양수 threshold·형상·차단조건과 시설 기상·빈도가 합성이므로, 이 결과를 실제 provider packet·빈도·시설 QRA로 승격하지 않았다. 현재 실제 설비의 적격 사고 packet 수는 계속 0건이다.

이 경계의 provider 질량 잔차는 `2.71e-19 kg`, SLABx 상대 유량 오차는 `0.119%`, SLABx→PRISM 전체 chain의 질량 잔차는 `0 kg`이었다. packet 식별자는 실제 작업목록 값으로 보존하고, 최종 피해 chain만 예제 시설의 `storage/storage.out` 포트로 명시적 rebinding하여 실행했다. 따라서 이 실행은 “실제 설비 QRA”가 아니라 **LayeredTank 상태 feedback과 작업목록 경계의 연결 진단**이다.

재현 명령은 다음과 같다.

```powershell
$py = "C:\Users\lyul\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe"
$dt = "C:\Users\lyul\Desktop\DocuData\액화수소 저장탱크_밴트 시스템\lh2dt_models"
$slabx = "C:\Users\lyul\Desktop\DocuData\SLABx_LH2\slabx-lh2"
& $py scripts/validate_layered_tank_inventory_slabsx.py `
  --lh2dt-root $dt --slabx-root $slabx --time-step-s 0.001 `
  --target-release-kg 0.0001 --full-open-area-m2 0.00012667686977437442 `
  --facility-component-id storage-tank-01 --facility-port-id tank-accident-out `
  --chain-component-id storage --chain-port-id storage.out `
  --event-id 'generic-lh2-full-scope-frequency-example/storage-shell/AREA_0.01%' `
  --output-dir results/20261009/layered_tank_exact_packet_repro3
& $py scripts/audit_provider_catalog_coverage.py `
  --provider-worklist results/20261009/provider_evidence/generic_lh2_provider_release_worklist.json `
  --provider-release-catalog results/20261009/provider_evidence/generic_lh2_provider_release_catalog_layered_exact.json `
  --output results/20261009/provider_evidence/generic_lh2_provider_catalog_coverage_layered_exact.json
```

## 합성 진단 export

`scripts/export_lh2dt_accident_history.py`는 외부 모델에 다음을 명시하여 짧은 진단을 실행한다.

- 1 m³ 탱크, 500 kPa 포화 상태, 액체 체적분율 0.7
- 지름 0.01 m의 명시적 실패 개구와 방출계수 0.8
- 대기압 101,325 Pa, 온도 288.15 K, 3 m/s 바람
- 0.05 s 간격, 총 0.2 s의 고정 진단 시계

실행 예시는 다음과 같다.

```powershell
$py = "C:\Users\lyul\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe"
$dt = "C:\Users\lyul\Desktop\DocuData\액화수소 저장탱크_밴트 시스템\lh2dt_models"
$env:PYTHONPATH = (Resolve-Path src).Path
& $py scripts/export_lh2dt_accident_history.py `
  --lh2dt-root $dt `
  --output-dir results/20261009/external_lh2dt_bridge
```

진단은 4개 방출 구간을 만들었고, 외부 모델 질량 감소량은 `0.03191147405505035 kg`, 방출 이력 적분량은 `0.03191147405505211 kg`이었다. 질량 장부 잔차는 약 `1.76e-15 kg`로 닫혔다. 이 결과는 외부 모델의 한 진단 시계가 보존된다는 뜻이지, 실제 탱크 사고의 정확도나 시설 사고빈도를 입증하는 뜻이 아니다.

재고 소진 종료를 별도로 진단하려면 초기 재고보다 작은 양수 threshold를 명시한다. 아래 예시는 0.2 s 안에 합성 threshold를 넘긴 뒤 `termination_basis=inventory_depletion`으로 기록한다.

```powershell
& $py scripts/export_lh2dt_accident_history.py `
  --lh2dt-root $dt `
  --output-dir results/20261009/external_lh2dt_inventory `
  --duration-s 0.2 `
  --termination-threshold-mass-kg 44.3641658303
```

이 threshold는 실제 탱크의 완전 소진값이 아니라 provider가 멈출 양수 진단 경계다. 따라서 짧은 고정 시계와 구분하여 `equipment_liquid_release` operator에 연결할 수 있지만, 여전히 현장 재고나 실제 사고 지속시간을 의미하지 않는다.

생성되는 `provider_export.json`의 schema는 `lh2dt.external_accident_export.diagnostic.v1`이다. 이는 기존 SLABx 브리지의 입력 형식이며, 아직 `prism.resolved_release.v1` 실제 provider packet으로 승격하지 않는다. 파일에는 `synthetic_diagnostic=true`, `provider_packet_promoted=false`, 현장 빈도 미추론과 물리검증 미주장이 기록된다.

## SLABx-LH2 경계 비교 결과

외부 모델이 소유한 총 유량과 SLABx-LH2가 계산한 대기 partition의 경계는 5% 상대오차 gate로 확인한다. 다음 명령은 gate를 통과시키지 못한 경우에도 모든 구간 오차와 차단 사유를 JSON으로 남긴다.

```powershell
$py = "C:\Users\lyul\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe"
$slabx = "C:\Users\lyul\Desktop\DocuData\SLABx_LH2\slabx-lh2"
& $py scripts/audit_lh2dt_slabsx_rate_boundary.py `
  results/20261009/external_lh2dt_bridge/provider_export.json `
  --slabx-root $slabx `
  --output results/20261009/external_lh2dt_bridge/slabx_rate_boundary_audit.json
```

처음 압력·온도만 전달하는 경로에서는 외부 모델과 SLABx가 포화 2상 상태를 서로 다르게 해석해 12%대 오차가 발생했다. 이 경로를 그대로 통과시키지 않고, provider가 반환한 엔탈피·엔트로피를 사용하는 `src/lh2_tno/slabx_provider_boundary.py`를 추가했다. 어댑터는 provider 상태의 등엔트로피 HEM 임계유량을 독립적으로 계산한 뒤, SLABx의 flash·액적·지면 도달 helper에 그 경계를 전달한다. 총 유량의 최종 소유자는 계속 외부 설비 모델이며, 5% gate 안에서만 SLABx partition을 결합한다.

수정된 경계는 `RATE_GATE_PASS`였다.

| 항목 | 결과 |
|---|---:|
| 구간 수 | 4 |
| 허용 상대오차 | 5.0% |
| 첫 구간 provider 유량 | 0.159588 kg/s |
| 첫 구간 SLABx 유량 | 0.159613 kg/s |
| 첫 구간 상대오차 | 0.015324% |
| 최대 상대오차 | 0.015324% |
| provider packet 승격 | 아니오 |
| 시설 QRA 승격 | 아니오 |

기존 LayeredTank export처럼 엔트로피가 없는 과거 자료는 기존 압력·온도 screening 경로로 남겨 호환성을 유지한다. 새 `lh2dt` export는 엔트로피를 반드시 포함하며 provider-state-aware 경계를 사용한다. 이 수정은 계수나 빈도를 보정한 것이 아니라, 포화 2상 경계에서 누락됐던 상태량을 전달한 것이다.

## PRISM 최종 피해 체인 진단

경계 gate 통과 후 합성 `storage` 설비를 provider 유체 기준으로 rebasing한 예제 시설에 연결해 다음 단계까지 실행했다.

- 상태: `END_TO_END_DIAGNOSTIC_EXECUTED`
- 방출 이력: 4개 구간, 총 0.2 s
- PRISM 최종 질량 잔차: `0 kg`
- 처리시간: 약 `17.6 s` (현재 PC, 합성 0.2 s 사건)
- 실행 단계: source 0.697 s, 근거리/확산 16.239 s, cloud observation 0.205 s, 피해·위험 0.140 s
- 시설 property basis: provider `ParaHydrogen`에 맞춘 합성 예제 rebasing

이 실행은 방출→SLABx→풀/확산→점화·화재/폭발 피해까지의 소프트웨어 연결을 검증한다. 합성 시설과 진단 horizon을 사용했기 때문에 연간 빈도, 실제 설비 IR/F-N, 독립 실험 검증을 의미하지 않는다. 결과는 `results/20261009/external_lh2dt_bridge/slabx_bridge_chain/verification.json`에 저장된다.

## 현재 연결 수준

현재 구현은 다음 순서까지 재현 가능하다.

1. 외부 `lh2dt` 탱크·밸브 상태에서 명시적 합성 사고 방출 이력을 생성한다.
2. provider 시간축과 질량 장부를 검증하고 PRISM/SLABx 브리지 입력으로 저장한다.
3. provider 엔탈피·엔트로피를 사용해 SLABx-LH2의 upstream 경계를 일치시킨다.
4. 같은 개구의 flash·액적·지면 partition을 계산하고 총 유량 차이를 비교한다.
5. 5% 안이면 `ResolvedLiquidRelease`를 만들고, PRISM 풀·확산·점화·피해 체인으로 전달한다. 초과하면 연결을 차단한다.

아직 다음은 완료되지 않았다.

- 실제 설비의 사고 포트·고장 개구·차단 branch와 외부 모델의 매핑
- `lh2dt` 자체의 표준 사고 packet export
- provider-state-aware 경계의 독립 실험 검증과 실제 설비의 flash/분무 검증
- 실제 provider packet과 문헌 `FrequencyPlan`의 exact-match 결합
- 이 외부 모델 결과를 이용한 시설 전체 IR/F-N

따라서 이 진단은 외부 모델 방출→SLABx→PRISM 피해 계산을 실제로 실행한 연결 증거지만 IJHE용 최종 물리 검증 결과는 아니다. 다음 개발은 실제 사고 export 계약을 외부 모델에 추가하고, provider-state-aware 경계를 실제 설비 포트·차단·재고 소진 branch에 반복한 뒤 독립 데이터로 flash와 방출률을 검증하는 데 집중한다.
