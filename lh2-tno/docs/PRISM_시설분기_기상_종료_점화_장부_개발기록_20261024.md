# PRISM 시설 분기·기상·종료·점화 장부 개발 기록

## 이번 변경의 목적

시설 위험 원자는 이미 `annual_condition_id`, `release_branch_id`,
`ignition_branch`를 갖고 있었습니다. 이번 변경은 이 세 값을 시설 원장과
시설 평가 결과에서 사람이 직접 확인할 수 있는 장부로 펼칩니다.

이 장부는 새로운 빈도를 만들지 않습니다. 한 원자가 어느 연간 기상조건,
어느 방출·차단·종료 경로, 어느 점화 결과에 속하는지만 보존합니다. 따라서
같은 원자를 사고 가족별 화면에서 다시 보더라도 위험을 두 번 더하지 않습니다.

## 출력 위치

- `src/lh2_tno/facility_ledger.py`
  - `scenario_branch_accounting`을 시설 ledger에 기록합니다.
  - `annual_conditions`에는 연간 확률, `weather` 또는 `weather_state`,
    provenance, 사건 수, 원자 수를 기록합니다.
  - `release_branches`에는 방출 branch, 기상조건 목록, 점화 목록,
    `provider_packet_identity.termination_bases`의 개수를 기록합니다.
  - `ignition_branches`에는 점화 branch, 사건 수, 원자 수,
    양의 기대 사망 원자 수를 기록합니다.
  - `cross_product_count`는 실제 계산된
    `(annual_condition, release_branch, ignition_branch)` 조합 수입니다.
- `src/lh2_tno/facility_assessment.py`
  - 새 ledger와 이전에 저장된 ledger를 모두 읽습니다.
  - 이전 ledger에 장부가 없으면 보존된 risk atom과 annual condition에서
    진단용 장부를 재구성합니다.
- `release_termination_inventory_ledger`
  - 각 event·방출 branch·연간조건 case에 대해 provider 지속시간, 종료시각,
    차단 상태, 재고 소진 상태, 누적 방출량과 질량 잔차를 보존합니다.
  - `UNCOMPUTED`, operator-limited, domain-incomplete 행은 별도 상태로 남고
    누출량 0으로 바꾸지 않습니다.
- `src/lh2_tno/completion_audit.py`
  - IJHE 완료 감사의 조건부 시설 위험 evidence에 장부를 포함합니다.

## 해석 규칙

`status=EXPLICIT_BRANCH_ACCOUNTING`이면 계산된 원자에 세 분기 차원이
명시되어 있다는 뜻입니다. `NO_RISK_ATOMS`이면 입력 원자가 없어 분기를
만들 수 없다는 뜻입니다. 종료 근거가 없는 provider packet은 빈 값으로
남으며, PRISM이 `inventory_depletion`이나 `isolation_success`를 추정하지
않습니다.

이 장부가 생겨도 시설 총 IR/F-N이 자동으로 열리지는 않습니다. 적격 사고
방출 packet, 전체 사고범위, 독립 물리검증과 실제 설비·수용점 자료가 모두
필요합니다. 현재 개발 상태에서는 기존과 같이 문헌 빈도, 합성/스크리닝
방출, 부분 범위를 진단용으로만 보고합니다.

## 검증

분기 metadata, 종료 근거 개수, 점화 branch, 감사 evidence에 대한 회귀검사를
추가했습니다. 최신 29-event·136-risk-atom 병합 원자를 다시 읽은 결과 3개
연간 기상조건, 2개 방출 branch, 4개 점화 branch, 12개 실제 조합이 확인됐고,
시설 총위험은 기존처럼 보류됐습니다. 전체 portable suite는 **546개 통과**했습니다.
