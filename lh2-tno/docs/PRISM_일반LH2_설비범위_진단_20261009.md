# PRISM 일반 액화수소 설비 범위 진단

이 기록은 특정 검사센터의 데이터를 빈도로 바꾸는 결과가 아니다. 일반적인 실외 액화수소 시설에서 설비별 빈도 프로파일을 어떻게 선택하고, 선택할 수 없는 설비를 어떻게 멈춰 세우는지 확인하는 합성 계약 시험이다.

## 입력

- `examples/generic_lh2_full_scope_manifest.json`
- `examples/generic_lh2_full_scope_frequency_plan.json`
- 실행 모듈: `src/lh2_tno/frequency_scope.py`

합성 시설에는 저장탱크, 액체 이송배관, 밸브, 압력방출 벤트, 펌프, 기화기, 재액화기, 경계 컴포넌트를 넣었다. 각 컴포넌트에는 위치·수소 물성 기준·포트가 있고, 실제 설비 자료가 아니라는 점을 `configuration_origin`과 `source_provenance`에 남겼다.

사고 방출을 연결할 수 있는 설비에는 `tank-accident-out`, `line-accident-out`, `valve-accident-out`, `pump-accident-out`, `vaporizer-accident-out`, `reliquefier-accident-out-1/2`와 같은 별도 사고 출구 포트를 둔다. 공정 정상 출구와 사고 출구를 섞지 않기 위한 경계이며, 이 포트만 provider의 방출 장부와 결합할 수 있다. 경계 컴포넌트에는 사고 포트를 만들지 않는다.

## 현재 문헌 프로파일로 실행되는 범위

다음 다섯 설비는 현재 검토된 카탈로그 프로파일로 initiating event를 생성한다.

| 설비 | 프로파일 | 생성되는 사건의 의미 |
| --- | --- | --- |
| 저장탱크 | `LH2_VESSEL` | 카탈로그의 누출 구경별 탱크 사건 |
| 액체 이송배관 | `LH2_PIPE` | 길이와 직경을 반영한 배관 사건 |
| 밸브 | `LH2_VALVE` | 밸브 연결부 누출 사건 |
| 압력방출 벤트 | `TNO_RELIEF_DEVICE` | 대기 직접 방출이 확인된 최대 방출 사건 |
| 펌프 | `TNO_PUMP_STANDARD` | 연결배관 직경을 기준으로 한 펌프 사건 |
| 기화기 | `TNO_HX_OUTSIDE_TUBES` | 수소가 튜브 외부에 있다는 설계 분류를 전제로 한 열교환기 사건 |
| 재액화기 | `TNO_HX_INSIDE_WEAK_SHELL` | 수소가 약한 쉘 내부 튜브에 있다는 설계 분류를 전제로 한 열교환기 사건 |

이 입력에서 총 24개의 initiating event가 생성된다. 이 숫자는 실제 사고 건수나 센터의 현장 빈도가 아니며, 문헌 카탈로그가 합성 입력에 적용되는지 확인하는 코드 경로의 결과다.

기화기·재액화기의 프로파일 선택은 컴포넌트 종류만 보고 자동으로 결정한 것이 아니다. `classification_basis`에 열교환기 내부의 위험 유체 위치를 명시했기 때문에 선택할 수 있다. 실제 시설에서는 도면·설계자료로 이 조건을 확인하지 못하면 해당 자산을 제외하고 provider별 고장범위를 요청해야 한다.

## 의도적으로 계산하지 않는 범위

경계 컴포넌트는 사고 설비로 빈도를 부여하지 않는다. PRISM은 경계에 0을 넣거나 밸브·배관 빈도를 복사하지 않는다. 열교환기 분류가 실제 설비에서 확인되지 않으면 기화기·재액화기도 같은 방식으로 명시적 제외 상태로 되돌려야 한다.

또한 이 진단은 방출 질량·지속시간·차단·재고 장부를 만들지 않는다. 따라서 액체 2상 방출, 600초 재고 방출, 양단 파열, 수직 handoff 및 시설 IR/F-N은 이 시험만으로 완료된 것으로 표시되지 않는다. 후속 `provider.resolved_release.v1` 또는 `provider.resolved_release_set.v1` packet이 들어와야 consequence campaign으로 승격할 수 있다.

## 재현

```powershell
$env:PYTHONPATH = "src"
python -c "from pathlib import Path; from lh2_tno.equipment_manifest import EquipmentManifest; from lh2_tno.frequency import FrequencyPlan; from lh2_tno.frequency_scope import audit_frequency_scope; m=EquipmentManifest.from_json(Path('examples/generic_lh2_full_scope_manifest.json')); p=FrequencyPlan.model_validate_json(Path('examples/generic_lh2_full_scope_frequency_plan.json').read_text()); print(audit_frequency_scope(m,p)['status'], audit_frequency_scope(m,p)['generated_event_count'])"
```

예상 출력은 `EXECUTABLE 24`이다. 이 결과가 `EXECUTABLE`인 뜻은 빈도 범위가 명시적으로 닫혔다는 뜻이며, 설비 방출부터 피해영향·시설 위험도까지 완성됐다는 뜻은 아니다. 실제 센터 감사 결과의 provider packet 수는 별도 증거 장부에서 계속 0건으로 관리한다.
