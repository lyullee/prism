# PRISM 외부 액화수소 설비 모델의 정상상태·사고방출 계약 감사

검토일: 2026-10-10  
대상: `액화수소검사지원센터 모델링` 프로젝트의 액화수소 설비 디지털트윈 출력과 PRISM의 일반 액화수소 시설 위험평가 경계

## 결론

현재 외부 디지털트윈은 탱크·배관·밸브·벤트·펌프·기화기·재액화기 등의 정상 공정상태와 동적 네트워크 보존을 계산한다. PRISM은 별도 진단 adapter로 사고 방출을 계산할 수 있다. 그러나 외부 디지털트윈의 실제 클래스에는 `export_accident_history(request)`가 없으므로, 그 adapter의 출력은 외부 설비가 직접 만든 적격 사고 packet으로 승격하지 않는다.

이번 감사 결과는 다음과 같다.

| 구분 | 결과 | 의미 |
|---|---:|---|
| 외부 모델 클래스 | 8개 바인딩 소스 확인 | 정상상태 모델 소스는 존재한다 |
| 외부 native 사고 export | 0개 | 외부 클래스 자체는 PRISM 사고방출 계약을 제공하지 않는다 |
| PRISM 진단 adapter | 7개 계약 확인 | 합성·진단 packet을 만들 수 있지만 현장 적격 packet은 아니다 |
| qualified provider packet | 0개 | 설비별 재고·차단·종료·독립검증이 결합된 packet은 없다 |
| 빈도·시설 IR/F-N | 승격하지 않음 | 이 감사는 빈도를 추정하거나 시설 QRA를 열지 않는다 |

따라서 정상 공정상태→사고 방출→피해 chain의 연결은 아직 **진단 연결**이다. 현장 설비 모델과 PRISM을 실제로 결합하려면 외부 모델에 사고 요청/방출 이력 export와 종료·질량 원장을 추가하거나, PRISM이 외부 모델의 명시된 사고 경계 계약을 받아야 한다.

## 무엇은 이미 연결됐는가

외부 모델 출력에서 다음을 읽고 PRISM의 진단 근거로 사용할 수 있다.

- 층상 탱크의 액체·기체 셀과 상태량
- 배관·밸브·펌프·기화기·재액화기의 정상 상태와 동적 step
- 공통 시계, 유량, 누적 질량·에너지 장부
- 8개 합성 운전 시나리오의 보존 검사
- 20261008 탱크 시험 패키지와 두 저장탱크 `TK-1101`, `TK-1102`의 재현 정보

이 값들은 `upstream_port_state`로 전달할 후보가 된다. 포화 상태에서는 P–T만으로 액체·기체를 구분할 수 없으므로 압력·엔탈피·phase/quality·셀 식별자를 함께 보내야 한다. 이미 계산된 유량을 다시 구멍 크기만으로 계산하면 안 된다.

## 무엇이 아직 없는가

외부 모델 소스 감사에서 모든 설비 클래스에 대해 다음이 확인되지 않았다.

- 사고 요청을 받는 native `export_accident_history(request)`
- 사건별 `component_id`·`port_id`·상·셀의 정확한 사고 경계
- 차단 시각을 포함한 방출 시간 이력
- 재고 소진 또는 허용 잔량에 대한 종료 근거
- 구간·누적 방출 질량 및 에너지 원장
- 독립 검증과 실제 설비 조건을 함께 가진 qualified provider packet

PRISM의 `scripts/export_lh2dt_*_prism_packet.py` adapter는 위 공백을 진단용으로 메우지만, 소스 모델의 사고 export가 되었다고 주장하지 않는다. 현재 IJHE 완료 감사의 `equipment_model_binding_to_accident_release` 검사는 이 외부 계약 감사가 들어오면 native export가 없는 경우 차단된다.

## 재현 명령

```powershell
python scripts/audit_lh2dt_native_contract.py `
  --binding examples/generic_lh2_native_model_binding.json `
  --external-root "C:\Users\lyul\Desktop\DocuData\액화수소 저장탱크_밴트 시스템\06_액화수소_디지털트윈_물리모델" `
  --prism-root . `
  --output results/20261026/native_full_scope_union_assessment/external_lh2dt_model_contract_audit.json
```

현재 기록은 [`external_lh2dt_model_contract_audit.json`](../results/20261026/native_full_scope_union_assessment/external_lh2dt_model_contract_audit.json)이다. 이 파일은 `NATIVE_ACCIDENT_EXPORT_MISSING`, 외부 사고 export 0개, PRISM 진단 adapter 계약 7개로 기록한다.

IJHE 완료 감사를 다시 만들 때는 다음 입력을 추가한다.

```powershell
--external-equipment-model-contract-audit `
  results/20261026/native_full_scope_union_assessment/external_lh2dt_model_contract_audit.json
```

이 입력은 기존 39개 검사를 유지하면서 외부 모델 계약을 기존 설비 모델 결합 검사에 추가한다. 현재 결과는 39개 검사 중 33개 PASS·6개 BLOCKED이며, 외부 native 사고 export 부재가 별도 차단 사유로 표시된다.

## 다음 구현 순서

1. 외부 모델에 포트별 사고 요청과 `resolved_release` 호환 export를 추가한다.
2. 정상 운전 stream과 사고 release를 `event_kind`와 `event_id`로 분리한다.
3. 액체·기체·수직 벤트 포트를 각각 보존하고 P–h·phase/quality를 검증한다.
4. 밸브 차단, 재고 소진, 잔량 기준을 방출 packet과 설비 장부 양쪽에 기록한다.
5. 동일 packet을 SLABx-LH2·점화·피해·시설 집계로 넘기되, qualified provider와 독립 물리검증이 생길 때까지 시설 IR/F-N은 계속 보류한다.

이 계약이 채워지면 설비별 결합은 가능하다. 그때도 문헌 빈도는 별도 입력으로 유지하며, 센서 상태를 빈도로 역추정하지 않는다.
