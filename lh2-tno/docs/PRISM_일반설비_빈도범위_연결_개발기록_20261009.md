# PRISM 일반 설비 빈도 범위 연결 기록

2026-10-09. 일반 `EquipmentManifest`를 문헌 빈도와 연결할 때 프로파일을 설비 종류나 압력에서 자동으로 추정하지 않도록 별도 범위 감사기를 추가했다.

## 무엇을 검사하는가

`scripts/validate_equipment_frequency_scope.py`는 다음 두 입력을 함께 받는다.

- 설비 중립 `EquipmentManifest`
- 검토자가 작성한 `FrequencyPlan`

각 설비는 빈도 자산으로 정확히 선택되거나, 계산에서 제외하는 이유가 명시되어야 한다. 선택된 자산은 PRISM의 기존 문헌 catalogue로 사건을 생성한다. 빈도 자산이 없는 설비를 0으로 놓거나, 탱크·배관·밸브라는 이름만 보고 프로파일을 붙이지 않는다.

이 도구는 `ConsequenceRequest`를 만들지 않는다. 따라서 `EXECUTABLE`은 “구조와 빈도 범위가 모두 유효하다”는 뜻이며, 방출 provider·방출 지속시간·피해 모델·시설 전체 IR/F-N이 완료되었다는 뜻이 아니다.

외부 TNO/legacy 사건을 이미 검토된 사건 행으로 받는 경우에도 같은 감사기를 사용할 수 있다. `FrequencyPlan.precomputed_events`에 행을 붙이면 범위 감사는 `event_generation_mode=external_precomputed`와 외부 산술 소유자를 남기고, PRISM은 행을 exact replay한다. 외부 행의 빈도를 다시 계산하거나 패키지 catalogue의 profile로 대체하지 않으며, 출처·방출 provider·물리검증·시설 QRA gate는 별도로 유지한다.

재현 예제의 결과는 `results/20261107/external_frequency_scope_audit.json`에 있으며,
1개 외부 사건을 exact replay하여 `EXECUTABLE`을 반환한다. 이 상태는 빈도 범위
계약이 유효하다는 뜻이고, provider 방출·피해 계산·시설 QRA가 완료됐다는 뜻은 아니다.

## 합성 예제 확인

```powershell
.venv\Scripts\python.exe lh2-tno/scripts/validate_equipment_frequency_scope.py `
  --manifest lh2-tno/examples/equipment_manifest.json `
  --frequency-plan lh2-tno/examples/equipment_frequency_plan.json `
  --output frequency_scope_audit.json
```

예제는 저장탱크 `LH2_VESSEL` 1개와 이송배관 `LH2_PIPE` 1개의 사건을 생성하고, 수요 경계는 명시적 제외로 기록한다. 합성 입력이므로 실제 시설 빈도나 피해를 주장하지 않는다.

## 검사센터 자료의 현재 한계

검사센터 export는 아직 P&ID 포트, 좌표, 실제 제어 상태와 provider 방출 이력이 확인되지 않아 `EquipmentManifest` 단계에서 `PARTIAL`이다. 따라서 빈도 범위를 추가하더라도 센터 시설 위험 계산으로 승격하지 않는다. 실제 포트·상태·방출 이력이 채워진 뒤 일반 매니페스트와 별도 `FrequencyPlan`을 작성하여 설비별 사고경로를 연결해야 한다.

## 다음 승격 조건

1. 실제 설비별 사고 포트와 물성·좌표를 `EXECUTABLE` 매니페스트로 제공한다.
2. 각 탱크·배관·밸브·펌프·기화기·벤트에 검토된 문헌 profile과 physical scope를 배정한다.
3. 각 frequency event에 provider의 방출 request 또는 명시적 `UNCOMPUTED` 사유를 연결한다.
4. 실행된 사건만 방출→확산→점화→피해→IR/F-N으로 보내고, 하나라도 빠지면 known contribution과 total을 분리한다.

이번 단계의 결과는 빈도 누락을 숨기지 않는 연결 계약과 합성 예제이며, 현장 사고빈도 수집이나 센서 기반 빈도 학습을 추가한 것이 아니다.
