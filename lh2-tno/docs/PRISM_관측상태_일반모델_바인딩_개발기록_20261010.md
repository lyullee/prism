# 관측 상태→시설 중립 정상 모델 바인딩

검사센터에서 읽은 상태 시계열을 일반 액화수소 설비 디지털트윈의 정상 상태 모델에 연결하는 진단 장부를 추가했다. 목표는 특정 검사센터 태그를 PRISM 코드에 고정하는 것이 아니라, 압력·온도·차압과 같은 관측 신호가 어떤 일반 설비 모델 후보에 들어갈 수 있는지와 필수 신호가 모두 있는지를 명확히 기록하는 것이다.

## 입력과 실행

```powershell
python scripts/audit_observed_state_model_binding.py `
  --observed-state-evidence examples/inspection_center_observed_state_evidence.json `
  --component-mapping-manifest examples/inspection_center_observed_component_mapping_manifest.json `
  --model-binding-catalog examples/generic_lh2_model_binding.json `
  --output results/20261026/native_full_scope_union_assessment/observed_state_model_binding_audit.json
```

입력은 세 가지다.

1. `inspection_center_observed_state_evidence.json`: 세 관측 component와 신호 목록.
2. `inspection_center_observed_component_mapping_manifest.json`: 관측 component와 일반 설비 종류의 후보 매핑. 현재는 `storage_tank`, `vent_stack`, `vaporizer`로 명시한다.
3. `generic_lh2_model_binding.json`: 시설 중립 모델의 패키지·클래스·revision, 정상 상태 export 지원 여부, 진단 adapter, 사고 방출 export와 종료 원장 상태.

## 현재 결과

현재 장부는 `prism.observed_state_model_binding_audit.v1` 형식의 `STATE_MODEL_BINDINGS_DIAGNOSTIC_ONLY`다.

이 장부는 `build_ijhe_completion_audit.py`와 native union evidence binder의
`diagnostic_observed_equipment_state_evidence` 검사에도 연결된다. 따라서 완료
감사를 실행할 때 정상 상태 모델 연결이 누락되거나 사고 방출로 잘못 표시되면
상태 증거 검사 자체가 `BLOCKED`가 된다. 검사 수는 늘리지 않고 기존 상태 증거
검사의 evidence 안에 모델 바인딩 결과를 함께 보존한다.

| 항목 | 결과 |
|---|---:|
| 관측 component | 3 |
| 정상 상태 모델에 필수 신호가 연결된 component | 3 |
| 별도 진단 adapter가 있는 component | 3 |
| 적격 사고 방출 provider packet | 0 |
| 사고 방출 export | 3개 모두 `missing` |

즉, `lh2-intake-tank`는 저장탱크 정상 상태 모델, `lh2-storage-vent`는 벤트 스택 모델, `lh2-supply-vaporizer-boundary`는 기화기 모델 후보에 연결된다. 이 연결은 상태 진단에 필요한 입력을 확인하는 단계다. 정상 상태 모델의 압력·온도·차압 출력이나 진단 adapter가 누출의 질량 유량, 개구, 지속시간, 종료 시각을 대신하지 않는다.

## 승격하지 않는 항목

이 감사는 다음을 만들지 않는다.

- 사고 방출 event 또는 `ResolvedGasRelease`/`ResolvedLiquidRelease` packet
- 문헌 빈도와 설비 상태를 자동으로 결합한 빈도
- SLABx-LH2 피해 계산의 새 입력
- 시설 IR/F-N 또는 전체 QRA

따라서 `status_consistency_current.json`에는 이 장부를 별도 1개 검사로만 연결한다. 장부가 삭제되거나 status pointer가 다른 파일을 가리키거나, 정상 모델·진단 adapter를 사고 방출로 표시하면 일관성 감사가 실패한다. 현재 25개 일관성 검사는 모두 통과하지만, IJHE 완료 감사의 `facility_release_boundary`, `actual_provider_release_packet`, `facility_case_provider_packet_coverage` 등 엄격한 증거 차단은 그대로 남아 있다.

## 다음에 필요한 자료

모델 연결을 사고 계산으로 승격하려면 설비별 exact asset identity, P&ID 끝점과 포트, 사고 시나리오의 개구·방향·시간 이력, 질량·엔탈피 폐합, 종료 근거, 그리고 독립 qualification sidecar가 있는 provider packet이 필요하다. 그 자료가 들어오기 전에는 현재 진단 모델 연결을 시설 위험 결과로 사용하지 않는다.
